## Visão do encontro

**Objetivo:** mostrar o que entra no projeto e como o código chega à `main` quando há mais de uma pessoa: `package.json`, faixas de versão, lock, `npx expo install` e `expo-doctor` no Bloco 1; branch, Pull Request, revisão e conflito no Bloco 2.

**Resultado ao fim das 4h:** cada aluno tem o `expo-doctor` sem problemas, o script `relatorio` no `package.json`, a lista dos produtos com `--categoria`, uma Issue fechada por um PR revisado pelo colega e um conflito no `catalogo.json` resolvido em dupla.

**Pré-requisitos:** laboratório do E21: `src/data/catalogo.json`, `produtos.js` reexportando o JSON e `scripts/relatorio-catalogo.mjs` com `--categoria`. A turma usa `add`, `commit` e `push` desde o E10.

**Materiais:** projetor, Wi-Fi, quadro com duas cores, uma segunda conta do GitHub (ou um aluno voluntário) colaboradora do repositório de demonstração, quiz publicado.

## Antes do encontro

:::steps
1. Na véspera, avise: "tragam a senha do GitHub e o celular da verificação em duas etapas". Sem login, o Bloco 2 para.
2. `lojinha` de demonstração no estado do E21, no GitHub, com `git status` limpo.
3. Numa branch `e22-desalinhado`, instale com `npm install` uma versão maior anterior do `expo-image` e confirme que o `npx expo start` e o `npx expo install --check` reclamam.
4. Prepare o conflito num segundo clone (`lojinha-colega`), com a segunda conta: `feature/preco-fone-a` com o Fone Bluetooth a `189.9` e PR aberto. No clone principal, `feature/preco-fone-b` com `179.9` e PR aberto. Os dois ficam verdes até a aula.
5. Rode `npx expo-doctor` na rede da escola e cronometre: na primeira vez ele baixa o pacote.
6. Duplas no quadro pela posição das mesas; com número ímpar, um trio em rodízio.
:::

## Abertura (15 min)

Retomada (5 min):

1. "Qual motor roda o JavaScript da Lojinha no celular, e qual roda os scripts no computador?" Esperado: Hermes no celular; V8, dentro do Node.
2. "Por que o relatório termina em `.mjs`?" Esperado: para usar `import` sem mexer no `"type"` do `package.json`.
3. "O que `process.argv.slice(2)` devolve com `--categoria=audio`?" Esperado: `['--categoria=audio']`, sempre texto.

Tarefa de casa (5 min): abra 2 repositórios do E21 e confira o `catalogo.json`, as duas linhas do `produtos.js` e o script recusando `--categoria=xyz`. Quem não terminou copia o JSON e o script da solução do E21 no início do laboratório.

Objetivos (5 min): projete "O que você vai aprender" da aula 25. "Hoje o código de vocês só entra na `main` depois que um colega ler, rodar e aprovar."

## Bloco 1 · npm e as dependências do Expo (50 min)

**"O que você vai aprender" e "Funciona no meu celular" (3 min).** Leia a história e faça a pergunta. Anote as hipóteses num canto do quadro e não responda: elas voltam no "Pense".

**"O package.json (1)" e "(2)" (7 min).** Abra o `package.json` da demonstração e peça que cada aluno abra o seu. Pergunte onde está o Expo Router, o que o `main` faz e por que `react` não tem símbolo. Esperado: em `dependencies`; aponta a entrada para as rotas; o modelo fixa a versão exata. Rode `npm ls expo-image`: a versão instalada cabe na faixa do arquivo.

**"Versão semântica" e "Faixas: ^ e ~" (7 min).** No quadro, uma reta com `2.4.1`, `2.4.9`, `2.5.0`, `2.9.3` e `3.0.0`. Numa cor, a chave do `~`; na outra, a do `^`. Pergunte onde cai um recurso novo. Esperado: dentro do `^` e fora do `~`. Só então avance para o diagrama do slide, que repete a reta: as linhas tracejadas marcam onde cada faixa para.

**"package-lock.json" (4 min).** No lock, procure `node_modules/expo-image`: o campo `version` traz o número exato. `git log --oneline -- package-lock.json` mostra o lock mudando nos commits do E12 e do E16. "Ninguém editou isso à mão."

**"Pense" (6 min).** Três minutos em duplas, respostas em voz alta. Esperado: `2.6.0`; `2.4.1` para todos; `2.4.3`. Volte às hipóteses: a sexta-feira se resolve com o lock no commit e o `npx expo install`.

**"npm install ou npx expo install?" e "Conferindo a saúde do projeto" (10 min).** Demonstração:

:::steps
1. `git switch e22-desalinhado` e `npx expo start`: leia em voz alta o aviso de versão.
2. <kbd>Ctrl</kbd> + <kbd>C</kbd> e `npx expo install --check`: o pacote aparece com a versão esperada; aceite a correção.
3. `git diff package.json`: a faixa voltou ao `~` do SDK.
4. `npx expo-doctor` até a mensagem de que nenhum problema foi encontrado.
5. "Rodem agora o `npx expo-doctor` no `lojinha` de vocês": o download corre enquanto você segue.
6. `git switch main` e apague a branch de demonstração.
:::

**"npx" (2 min).** Pergunte por que o curso nunca instalou o CLI do Expo global. Esperado: ele vem no pacote `expo`, na versão do SDK.

**"Scripts" (4 min).** Na demonstração, acrescente o `relatorio` e rode `npm run relatorio -- --categoria=audio`. Sem o `--`, o npm avisa algo como `Unknown cli config` e o relatório sai sem filtro. A turma **não** faz isso agora: o script entra no laboratório, numa branch.

**"npm audit" e "Como escolher um pacote" (5 min).** Rode `npm audit` e leia com a turma de quais pacotes vêm os alertas, se houver. Leia o bloco do `--force` em tom sério. Em reactnative.directory, procure "camera" e mostre plataformas e Expo Go.

**"Erros comuns" a "Próximos passos" (2 min).** Leia rápido e pergunte quem já tem o `expo-doctor` limpo.

:::tip Ritmo
Se atrasar, fale a tabela do `npx` sem perguntas e pule o React Native Directory. A demonstração do `--check` e o "Pense" não se cortam: eles explicam a história da sexta-feira.
:::

## Bloco 2 · Git e GitHub em equipe (50 min)

**"O que você vai aprender" e "Duas pessoas, um catálogo" (2 min).** Pergunte quem já perdeu trabalho com Git. Esperado para o slide: "cada um numa branch", "alguém revisa antes".

**"O fluxo completo do Git" (3 min).** Antes de projetar o slide, quatro caixas no quadro: pasta de trabalho, área de preparação, repositório local e GitHub. Um aluno diz o comando de cada seta, inclusive a do `git pull`. Depois, o diagrama do slide confere as respostas.

**"Branches" e "Merge" (7 min).** Ao vivo:

:::steps
1. `git switch main`, `git pull` e `git switch -c chore/readme-comandos`; `git branch` mostra o `*`.
2. No `README.md`, uma seção "Comandos" com `npm start` e `npm run relatorio -- --categoria=audio`; commit "Documenta os comandos no README".
3. `git switch main`: o README volta à versão antiga diante da turma. Volte para a branch e ele reaparece.
4. `git log --oneline --graph --all`: a branch um commit à frente.
:::

**"Pull Request" e "Revisão de código" (9 min).** `git push -u origin chore/readme-comandos`, **Compare & pull request**, descrição com "O que muda" e "Como testar" e a segunda conta em **Reviewers**. Mostre **Settings**, **Collaborators**, **Add people**: a turma faz isso na pausa. Com a segunda conta, comente uma linha em **Files changed** pedindo uma mudança; responda com um commit e mostre o PR se atualizando. Aprove, faça o merge, **Delete branch** e atualize a `main` local com `git pull`.

**"Da branch à main" (1 min, dentro dos 9).** Projete a animação e deixe rodar uma vez em silêncio. Na segunda volta, um aluno narra cada etapa com o comando ou botão que você acabou de usar: `git switch -c`, os commits, **Create pull request**, **Approve** e **Merge pull request**.

**"Pense" (4 min).** Individual. Esperado: o caminho `script/`, a pasta `.expo/` e o "aaa", com **Request changes**. Peça a alguém que leia o comentário do caminho como o mandaria ao colega.

**"Conflito" e "Resolvendo o conflito" (4 min).** Só com os slides: leia as marcas e pergunte o que é `HEAD`. Esperado: a branch em que você está. Insista no passo 3: conflito se resolve conversando.

**"Pratique" (3 min).** Individual, no caderno. Não mostre a resposta: ela vira a demonstração.

**Conflito ao vivo (6 min).** Execute a resposta da turma:

:::steps
1. Com a segunda conta, faça o merge do PR da `feature/preco-fone-a`.
2. Atualize o PR da `feature/preco-fone-b`: *This branch has conflicts that must be resolved*.
3. No clone principal, a sequência da turma até o `git merge main`; o VS Code mostra as marcas e os botões.
4. Combine o preço em voz alta com quem "é a Ana" e use **Accept Current Change**.
5. `npm run relatorio` prova que o JSON está válido. `git add`, `git commit`, `git push`, PR verde e merge.
:::

**".gitignore", "Mensagens de commit" e "Issues" (5 min).** `git check-ignore -v .expo` mostra a linha do `.gitignore` responsável. Peça a versão boa de cada mensagem antes de mostrar. Abra ao vivo a Issue "Relatório recusa categoria com maiúscula": ela vira o desafio opcional da tarefa.

**"Erros comuns" a "No laboratório" (2 min).** Leia rápido; os erros já apareceram.

**Desafio que prepara o laboratório (5 min).** Em duplas, no caderno: a descrição do PR de hoje, com O que muda, Como testar (comandos exatos) e `Closes`. Esperado: "Script `relatorio` e, com `--categoria`, a lista dos produtos dela"; `npm run relatorio` e `npm run relatorio -- --categoria=audio`; `Closes #` com o número da Issue.

:::tip Ritmo
Se atrasar, corte o `git check-ignore` e a Issue ao vivo, e revise o PR sem o commit de correção. O PR ao vivo e o conflito ao vivo não se cortam: o laboratório repete esses dois caminhos.
:::

## Laboratório (70 min)

**Enunciado:** os 7 passos do slide "No laboratório" da aula 26. Issue "Listar os produtos da categoria"; commit de entrega "E22: script relatorio e produtos da categoria".

**Organização:** duplas do quadro; cada um no próprio repositório, revisando o PR do outro. Os convites de colaborador saem na pausa. O revisor clona o repositório do colega à parte (`git clone <url> lojinha-do-colega`); o relatório só usa módulos do Node e dispensa `npm install`. O conflito acontece no repositório de um da dupla, com esse clone; sobrando tempo, invertem os papéis. No trio, A revisa B, B revisa C e C revisa A.

**Marcos:** 2:30, `expo-doctor` limpo, Issue e branch criadas; 2:45, script pronto e PR aberto com revisor; 3:00, revisões e merge dos dois PRs; 3:20, conflito resolvido e com merge; 3:30, entrega.

**O que observar:** commits direto na `main`, PR sem "Como testar", `node_modules/` ou `.expo/` em **Files changed**, aprovação em menos de um minuto (pergunte "você rodou?") e qualquer `--force`. Antes do commit do conflito, peça `git diff --check`: ele acusa marcas esquecidas.

:::example Solução de referência
`package.json`, só a seção que muda:

```json
"scripts": {
  "start": "expo start",
  "android": "expo start --android",
  "ios": "expo start --ios",
  "web": "expo start --web",
  "relatorio": "node scripts/relatorio-catalogo.mjs"
}
```

`scripts/relatorio-catalogo.mjs`. Até o comentário `// E22`, é uma versão do E21; a do aluno pode ser diferente e continua valendo:

```javascript
import fs from 'node:fs';
import path from 'node:path';

const arquivo = path.join(process.cwd(), 'src', 'data', 'catalogo.json');
const { categorias, produtos } = JSON.parse(fs.readFileSync(arquivo, 'utf-8'));

const opcao = process.argv.slice(2).find((a) => a.startsWith('--categoria='));
const filtro = opcao ? opcao.split('=')[1] : null;

if (filtro && !categorias.some((c) => c.slug === filtro)) {
  console.log(`Categoria "${filtro}" não existe.`);
  console.log(`Use uma destas: ${categorias.map((c) => c.slug).join(', ')}`);
  process.exit(1);
}
const lista = filtro ? produtos.filter((p) => p.categoria === filtro) : produtos;

console.log(filtro ? `Relatório: ${filtro}` : 'Relatório: catálogo inteiro');
categorias.forEach((categoria) => {
  const quantidade = lista.filter((p) => p.categoria === categoria.slug).length;
  if (quantidade > 0) console.log(`${categoria.nome}: ${quantidade} produto(s)`);
});

const media = lista.reduce((soma, p) => soma + p.preco, 0) / lista.length;
console.log(`Preço médio: R$ ${media.toFixed(2)}`);

const semImagem = lista.filter((p) => !p.imagem).map((p) => p.nome);
console.log(`Sem imagem: ${semImagem.length ? semImagem.join(', ') : 'nenhum'}`);

// E22: com --categoria, lista os produtos dela
if (filtro) {
  console.log('');
  console.log('Produtos da categoria:');
  lista.forEach((p) => {
    console.log(`- ${p.nome}: R$ ${p.preco.toFixed(2)} (nota ${p.avaliacao})`);
  });
}
```

Saída de `npm run relatorio -- --categoria=audio`, depois das duas linhas que o npm imprime:

```plaintext
Relatório: audio
Áudio: 3 produto(s)
Preço médio: R$ 259.90
Sem imagem: nenhum

Produtos da categoria:
- Fone Bluetooth: R$ 199.90 (nota 4.6)
- Caixa de Som Portátil: R$ 249.90 (nota 4.4)
- Microfone USB: R$ 329.90 (nota 4.3)
```

Descrição do PR:

```markdown
**O que muda:** script `relatorio` no package.json e, com `--categoria`, a lista dos produtos dela.

**Como testar:**
- `npm run relatorio`: relatório do catálogo inteiro, sem lista
- `npm run relatorio -- --categoria=audio`: os 3 produtos de áudio com preço e nota
- `npm run relatorio -- --categoria=xyz`: mensagem com as categorias válidas

Closes #1
```

O caminho completo:

```bash
git switch main
git pull
npx expo-doctor                  # se reclamar: npx expo install --check e commit
git switch -c feature/relatorio-categoria
# edite package.json e scripts/relatorio-catalogo.mjs
npm run relatorio -- --categoria=audio
git add package.json scripts/relatorio-catalogo.mjs
git commit -m "E22: script relatorio e produtos da categoria"
git push -u origin feature/relatorio-categoria
# no GitHub: PR, revisão, ajustes e merge
git switch main
git pull
git branch -d feature/relatorio-categoria
```

Conflito em dupla, no repositório da Ana, com o Bruno no clone dele:

```bash
# Ana (repositório dela)
git switch -c feature/preco-fone-a     # preço do fone: 189.9
git commit -am "Corrige o preço do Fone Bluetooth"
git push -u origin feature/preco-fone-a

# Bruno (lojinha-do-colega, ao mesmo tempo)
git switch -c feature/preco-fone-b     # preço do fone: 179.9
git commit -am "Aplica a promoção do Fone Bluetooth"
git push -u origin feature/preco-fone-b

# os dois abrem PR; Ana faz o merge do dela; o do Bruno mostra o conflito
git switch main
git pull
git switch feature/preco-fone-b
git merge main                         # marcas no catalogo.json
npm run relatorio                      # depois de resolver: o JSON está válido
git add src/data/catalogo.json
git commit -m "Resolve conflito no preço do fone"
git push                               # o PR fica verde; merge
```

`src/data/catalogo.json`, trecho combinado pela dupla:

```json
{
  "id": 1,
  "nome": "Fone Bluetooth",
  "preco": 179.9,
  "categoria": "audio",
```
:::

**Critérios:** os do slide, mais: nenhum `<<<<<<<` em arquivos da `main`.

**Entrega:** o aluno cola o link do repositório na entrega do laboratório E22 no sistema. Em **Pull requests**, filtro **Closed**, você vê em segundos a revisão, o merge e a Issue ligada.

## Fechamento (25 min)

**Correção coletiva (10 min).** Projete 3 PRs da turma:

- Um exemplar: "Como testar", comentário atendido e Issue fechada. Pergunte: "se o revisor aprovasse sem rodar, o que poderia passar?" Esperado: um caminho errado no script, como no "Pense".

## Encerramento (5 min)

**Tarefa de casa:** terminar o laboratório, revisar as aulas 25 e 26 e refazer o quiz quem ficou abaixo de 70%. Desafio opcional: resolver a Issue "Relatório recusa categoria com maiúscula" numa branch `fix/categoria-maiuscula` (um `toLowerCase()` no filtro resolve), com PR revisado e `Closes #N`.

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| `git push` recusado com `rejected` | O GitHub tem commits que a máquina não tem | `git pull`, resolver o conflito se houver e `git push`; nunca `--force` |
| O colega não aparece em **Reviewers** ou não aprova | Convite não aceito, ou ele é o autor do PR | **Settings**, **Collaborators**; aceitar em github.com/notifications |
| `npm run relatorio --categoria=audio` ignora o filtro | Faltou o `--` | `npm run relatorio -- --categoria=audio` |
| `Missing script: "relatorio"` | Script fora de `"scripts"` ou terminal fora da raiz | `npm run` sem nome lista os scripts; conferir a pasta |
| PR com milhares de arquivos | `node_modules/` ou `.expo/` já commitados | `git rm -r --cached node_modules .expo`, `.gitignore` e commit |
| `SyntaxError` ao ler o JSON | Marcas de conflito commitadas | Buscar `<<<<<<<`; `git diff --check` antes do commit |
| Editor estranho no terminal depois do `git merge` | Commit de merge sem `-m` abriu o Vim | <kbd>Esc</kbd>, `:wq` e <kbd>Enter</kbd> |
| `expo-doctor` acusa versões fora do SDK | Pacote instalado com `npm install` | `npx expo install --check` e o doutor de novo |

## Plano B

- **Sem internet ou GitHub fora do ar:** o Git funciona sem rede. Branch, merge e conflito no próprio repositório, simulando as duas pessoas com duas branches locais. PR, revisão e `expo-doctor` ficam para casa, no mesmo link; o quiz vai para a abertura do E23.
- **Aluno sem acesso ao GitHub:** recuperação da senha ou da verificação em duas etapas na pausa; enquanto isso, ele revisa como colaborador do colega e abre o próprio PR em casa.
- **Colega faltou:** trio em rodízio ou você como revisor. Para o conflito, dois clones do próprio repositório (`git clone <url> lojinha-2`), um para cada papel.
- **Sem projetor:** grafo de branches no quadro a cada comando e demonstrações em grupos de 5 em volta do seu computador.
- **`expo-doctor` lento demais:** no encontro, só o `npx expo install --check`; o doutor fica para casa.
