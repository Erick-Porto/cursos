## Visão do encontro

**Objetivo:** a Lojinha passa a se conferir sozinha: Jest (`jest-expo`) nas funções puras de `src/utils/`, um ciclo de TDD num bug real, o script `verificar`, o `.env` com `EXPO_PUBLIC_` e o GitHub Actions rodando lint e testes a cada push e PR.

**Resultado ao fim das 4h:** 12 testes ou mais nos quatro utilitários, `npm run verificar` sem erros, `.env` fora do Git e `.env.example` dentro, visto e selo verdes. Último encontro da unidade Ambiente JavaScript.

**Pré-requisitos:** Lojinha do E23 com `eslint.config.js`, lint zerado e `formatar.ts`; `validar.js`, `mascaras.js` (E15) e `filtrar.js` (E17); repositório público com `git push` funcionando e o fluxo de PR do E22.

**Materiais:** projetor com terminal e navegador lado a lado, quadro, Wi-Fi, seu repositório de demonstração, o repositório vitrine (abaixo) e o quiz publicado.

## Antes do encontro

:::steps
1. Lojinha de demonstração no estado do E23, `git status` limpo, num repositório **público** seu com a aba Actions habilitada.

## Bloco 1 · Testes automatizados com Jest (50 min)

**"O preço que sumiu" (5 min).** Pergunta do slide. Esperado: as funções puras de `src/utils/`, porque mexem com dinheiro e com o que o cliente digita, aparecem em várias telas e rodam sem celular.

**"Jest no projeto Expo" (9 min).** Instalação coletiva, cada aluno no próprio projeto:

:::steps
1. <kbd>Ctrl</kbd> + <kbd>C</kbd> no servidor do Expo (no Windows, ele trava arquivos) e `git status` limpo.
2. `npx expo install jest-expo jest -- --save-dev`: os dois entram em `devDependencies`, como no E22.
3. `npm pkg set scripts.test=jest jest.preset=jest-expo`: script e configuração sem risco de vírgula errada.
4. `npm test`: "No tests found, exiting with code 1" é esperado.
5. Crie `src/utils/validar.test.js` com o código de "Seu primeiro teste" e rode: `Tests: 2 passed`.
:::

Quem não vê os 2 testes passando, você atende na pausa.

**"Seu primeiro teste" e "Lendo uma falha" (8 min).** Leia o teste como frase. Crie `formatar.test.js` com `toBe('R$ 199,90')`, digitado com espaço comum, e rode. Pergunte: "Expected e Received são iguais. Por que falhou?" Deixe a turma chutar e revele com `console.log(formatarPreco(199.9).charCodeAt(2))`: aparece `160`; o espaço comum é `32`. Corrija com `\u00a0`.

**"Matchers" e "toBe ou toEqual?" (5 min).** Comente só `toBe`, `toEqual` e `toBeNull`; o `toThrow` volta no E32. Mostre `toBe([2, 1])` falhando com `serializes to the same string`.

**"Arrange, act, assert" e "test.each" (6 min).** Escreva o teste do `aplicarFiltros` e **quebre o código de propósito** (`b.preco - a.preco`): vermelho. Desfaça: é o hábito que separa teste de enfeite. Rode o `test.each` com `npm test -- --verbose` para mostrar os nomes do `%p`.

**"Pense" (4 min).** Duplas. Esperado: a tabela da resposta, com pelo menos uma borda. Se surgir `'ana@loja'`, pergunte o que a função devolve: a mensagem de formato.

**"TDD" (7 min).** Abra com o slide "TDD: o teste vem antes": deixe a animação do ciclo rodar uma volta e aponte a seta do próximo teste, que fecha o ciclo. Os slides "TDD: vermelho" e "TDD: verde e refatorar" acompanham a demonstração ao vivo, no `mascaras.test.js`:

:::steps
1. Conte o bug do `+55` e anote no quadro os palpites do que o campo mostra hoje.
2. Escreva o teste e rode: vermelho, `Received: "(55) 11987-6543"`. Compare com os palpites.
3. Verde mínimo: separe o `slice(0, 11)` e, antes dele, corte o `55` quando vierem 13 dígitos. Verde.
4. Refatore para `tirarCodigoDoPais` com `CODIGO_DO_BRASIL`: os 7 testes verdes.
:::

**"Cobertura" (3 min).** `npm test -- --coverage` e, no navegador, `coverage/lcov-report/index.html`: as linhas sem teste do `validar.js` aparecem em vermelho. "100% quer dizer sem bug?" Esperado: não, só que toda linha rodou.

**"Testes de componente" a "Próximos passos" (3 min).** Só mostre o código; ninguém instala hoje. Os erros comuns já apareceram ao vivo.

:::tip Ritmo
Se atrasar, pule o relatório HTML e fale o slide de componente sem o código. A instalação, a falha do espaço e o TDD não se cortam: o laboratório usa os três.
:::

## Bloco 2 · Automação e integração contínua (50 min)

**"Funciona na minha máquina" (4 min).** Pergunta do slide. Esperado: um servidor que rode os testes a cada push e uma regra que exija verde para o merge.

**"O script verificar" e "O lint precisa conhecer o Jest" (8 min).** Ao vivo: `npm pkg set scripts.verificar="npx expo lint && npm test"` e `npm run verificar`. O lint para em `'describe' is not defined` e os testes nem aparecem: é o `&&` trabalhando. Mostre o código de saída `1` com `echo $?` (Git Bash) ou `$LASTEXITCODE` (PowerShell). Acrescente o bloco de `globals` e rode de novo: tudo verde, saída `0`.

**"Variáveis de ambiente" a ".env.example e .gitignore" (8 min).** Crie o `.env`, ponha `console.log('API:', process.env.EXPO_PUBLIC_API_URL);` no `Inicio.js`, reinicie o Expo e mostre o valor no terminal. Troque pela desestruturação: `undefined`. Apague o log. O `.env` aparece no `git status` até entrar no `.gitignore`, com `coverage/`. Crie o `.env.example`. "O endereço da DummyJSON é segredo?" Esperado: não; a regra vale para chaves e senhas.

**"Integração contínua com GitHub Actions" e "Do push ao visto verde" (3 min).** Desenhe no quadro: push, runner Linux novo, `npm ci`, lint, testes, visto ou X. O desenho fica até o laboratório. Projete a animação do slide seguinte e pergunte: "se o lint falhar, o `npm test` roda?" Esperado: não; o passo vermelho para os seguintes e o resultado é o X.

**"verificar.yml (1)" e "(2)" (8 min).** Na Lojinha de demonstração:

:::steps
1. `git switch -c feature/testes-e-ci`.
2. Crie `.github/workflows/verificar.yml` com as duas partes dos slides; mostre a pasta com ponto no VS Code.
3. Selo no topo do `README.md`, com o seu usuário.
4. Commit "E24: testes e CI" e `git push -u origin feature/testes-e-ci`.
5. Abra o PR: o check "Verificar / verificar" aparece amarelo.
6. Na aba Actions, abra o job e os passos enquanto rodam. A primeira execução leva de 1 a 3 minutos.
:::

**"Pense" (3 min).** Esperado: o runner só tem o que está no Git, e o lock antigo não tem o pacote novo; a correção é o commit do `package-lock.json`.

**"Lendo o resultado" e "Selo" (5 min).** Volte ao PR: visto verde. Faça o merge e mostre a execução na `main` disparada por ele; ao terminar, o selo do README fica verde.

**"CI vermelho bloqueia o merge" (4 min).** No repositório vitrine, abra o PR `demo/quebrado`: X vermelho e "Merging is blocked". No passo **Testes**, leia com a turma o teste "ordena pelo menor preço" e o diff: `-` é o esperado, `+` o recebido. Mostre a regra em Settings > Branches: opcional na Lojinha, obrigatória em equipe.

**"Erros comuns" a "No laboratório" (2 min).** Leitura rápida.

**Desafio que prepara o laboratório (5 min).** Em duplas: "Listem os arquivos que vocês vão criar ou mudar e se cada um vai para o Git." Esperado: vão os quatro `*.test.js`, `mascaras.js`, `package.json`, o lock, `eslint.config.js`, `.gitignore`, `.env.example`, `verificar.yml` e `README.md`; ficam fora `.env` e `coverage/`. A lista no quadro vira o checklist.

:::tip Ritmo
Se atrasar, só cite o `undefined` da desestruturação. O workflow ao vivo e o PR bloqueado não se cortam; se o Actions demorar, siga para o "Pense" e volte ao PR depois.
:::

`src/utils/mascaras.js`, depois do TDD:

```javascript
const CODIGO_DO_BRASIL = '55';

function tirarCodigoDoPais(digitos) {
  const temCodigo = digitos.length === 13 && digitos.startsWith(CODIGO_DO_BRASIL);
  return temCodigo ? digitos.slice(2) : digitos;
}

export function mascararTelefone(texto) {
  const d = tirarCodigoDoPais(texto.replace(/\D/g, '')).slice(0, 11);
  if (d.length === 0) return '';
  if (d.length <= 2) return `(${d}`;
  if (d.length <= 7) return `(${d.slice(0, 2)}) ${d.slice(2)}`;
  return `(${d.slice(0, 2)}) ${d.slice(2, 7)}-${d.slice(7)}`;
}
```

import { aplicarFiltros } from './filtrar';

const lista = [
  { id: 1, nome: 'Fone Bluetooth', preco: 199.9, categoria: 'audio', avaliacao: 4.5 },
  { id: 2, nome: 'Caixa de Som', preco: 89.9, categoria: 'audio', avaliacao: 4.8 },
  { id: 3, nome: 'Bola de Futebol', preco: 59.9, categoria: 'esporte', avaliacao: 4.1 },
];

const ids = (produtos) => produtos.map((p) => p.id);

describe('aplicarFiltros', () => {
  test('sem categoria, devolve todos em ordem de nome', () => {
    expect(ids(aplicarFiltros(lista, { categoria: null, ordem: 'nome' }))).toEqual([3, 2, 1]);
  });

  test('filtra pela categoria', () => {
    expect(ids(aplicarFiltros(lista, { categoria: 'esporte', ordem: 'nome' }))).toEqual([3]);
  });

  test('ordena pelo menor preço', () => {
    expect(ids(aplicarFiltros(lista, { categoria: 'audio', ordem: 'preco' }))).toEqual([2, 1]);
  });

  test('ordena pela melhor avaliação', () => {
    expect(ids(aplicarFiltros(lista, { categoria: null, ordem: 'avaliacao' }))).toEqual([2, 1, 3]);
  });

  test('categoria sem produtos devolve lista vazia', () => {
    expect(aplicarFiltros(lista, { categoria: 'livros', ordem: 'nome' })).toEqual([]);
  });

  test('não altera a lista recebida', () => {
    aplicarFiltros(lista, { categoria: null, ordem: 'preco' });

  });

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| "No tests found, exiting with code 1" | Nenhum arquivo termina em `.test.js` (por exemplo, `.teste.js`) | Conferir o nome; `npx jest --listTests` lista o que o Jest achou |
| Lint com `'describe' is not defined` | `eslint.config.js` sem o bloco dos testes ou com `files` errado | Colar o bloco do slide, com `'**/*.test.js'` |
| Expected e Received idênticos na tela | Espaço comum no preço esperado | `\u00a0` entre `R$` e o número; `charCodeAt` mostra `160` |
| `process.env.EXPO_PUBLIC_API_URL` é `undefined` | Sem o prefixo, `.env` fora da raiz, desestruturação ou servidor sem reiniciar | Conferir nome e local; `npx expo start -c` |
| Push recusado: "refusing to allow a Personal Access Token to create or update workflow" | Token sem o escopo `workflow` | Novo token com `workflow`, ou novo login pelo Git Credential Manager |
| Nada aparece na aba Actions | Pasta `github` sem ponto, `workflow` no singular ou arquivo em outra branch | Caminho `.github/workflows/verificar.yml`, na branch do push |
| "Invalid workflow file" | Tab ou indentação errada no YAML | Reindentar com espaços; "Render Whitespace" no VS Code mostra os tabs |
| `npm ci` vermelho: "package.json and package-lock.json are in sync" | Lock fora do commit ou desatualizado | `npm install` local e commit do `package-lock.json` |

## Plano B
