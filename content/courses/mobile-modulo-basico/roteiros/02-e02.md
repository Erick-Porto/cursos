## Visão do encontro

**Objetivo**: cada aluno sai com o ambiente funcionando e o `minhas-tarefas` criado com Vite, versionado com Git e publicado no GitHub.

**Resultado ao fim das 4h**: repositório público `minhas-tarefas` com dois commits ou mais e `App` montado com `Cabecalho` e `Rodape` em arquivos próprios.

**Pré-requisitos (E01)**: Node LTS, Git e VS Code instalados; conta no GitHub; papéis de HTML, CSS e JavaScript; ideia de componente.

**Materiais**: projetor, Wi-Fi para `npm install` em massa, um computador por aluno, sua conta do GitHub, pendrive com instaladores e projeto pronto, quiz `quiz-e02` publicado.

## Antes do encontro

:::steps
1. Confira `node -v`, `npm -v`, `git --version` e `code .` na máquina da demonstração; apague `meu-primeiro-repo` e `minhas-tarefas` (pastas e repositórios no GitHub)
2. Remova a credencial `git:https://github.com` do Gerenciador de Credenciais do Windows para a autorização aparecer ao vivo
3. Rode `npm create vite@latest teste -- --template react` para ver as perguntas da versão atual; apague `teste`
4. Teste a solução de referência; leve-a com `node_modules` no pendrive, junto dos instaladores de Node, Git e VS Code
5. Abas: github.com logado, slides das duas aulas, quiz `quiz-e02` publicado, lista de quem não entregou o E01. Fonte grande no terminal e no VS Code
:::

## Abertura (15 min)

Enquanto a turma senta, todos rodam `node -v`, `npm -v` e `git --version`; quem receber "não reconhecido" levanta a mão (Plano B).

Três perguntas, 5 min:

1. "Cor, texto e clique de um botão: qual linguagem cuida de cada um?" Esperado: CSS, HTML, JavaScript.
2. "Por que React em vez de JavaScript puro?" Esperado: você declara o que a tela mostra e o React atualiza o DOM.
3. "O que vocês instalaram e para que serve?" Esperado: Node roda JavaScript fora do navegador, Git guarda histórico, VS Code edita, GitHub publica.

Tarefa, 5 min: abra o `perfil.html` de um voluntário no DevTools; quem não entregou entrega hoje por commit, no Bloco 1.

Leia "O que você vai aprender" da aula A: "hoje é o dia de configurar; do E03 em diante vocês só repetem".

## Bloco 1 · Ambiente de desenvolvimento: Node.js, npm, VS Code e Git (50 min)

**Slides "Por que tantas ferramentas?" a "npm: a loja de pacotes" (8 min).** A turma chuta as quatro respostas. No Node, insista: o aluno precisa dele, o usuário do site não. No npm, abra `package.json` e `node_modules` de um projeto pronto.

**Slides "Terminal: 5 comandos que bastam" e "VS Code: editor, extensões e atalhos" (8 min).** A turma repete: `cd Documentos`, `mkdir projetos-react`, `cd projetos-react`, `ls`, `code .`. No VS Code, ``Ctrl + ` `` abre o terminal integrado, usado daqui em diante; `Ctrl + Shift + X` confere as extensões.

**Slides "Git: fotografias do seu projeto" a "Pratique: seu primeiro commit" (17 min).** Analogia do "salvar jogo"; depois demonstre, lendo cada resposta:

:::steps
1. `git config --global user.name` e `user.email`: sem isso o commit falha com "Author identity unknown"
2. `mkdir meu-primeiro-repo`, `cd meu-primeiro-repo`, `git init`
3. `echo "Olá, Git" > notas.txt`, `git status` (vermelho), `git add .`, `git status` (verde)
4. `git commit -m "Cria notas.txt"` e `git log --oneline`
:::

Projete "Do arquivo editado ao commit" e deixe a animação dar uma volta em silêncio; pergunte em qual caixa o `notas.txt` estava quando o `git status` ficou verde (em "marcados"). Frise que o commit leva só o que foi marcado: é o "nothing to commit" de quem esquece o `git add`.

No "Pratique" a turma repete e faz o segundo commit; quem não entregou o E01 copia `perfil.html` e `estilo.css` para `meu-primeiro-repo` antes dele.

**Slides "GitHub: seu portfólio público" e "node_modules nunca vai para o Git" (10 min).** No navegador: New repository, `meu-primeiro-repo`, Public, sem README. No terminal:

:::steps
1. `git branch -M main`: Git antigo cria `master`, o GitHub espera `main`; sem isso o push falha com "src refspec main does not match any"
2. `git remote add origin` com a URL HTTPS da página
3. `git push -u origin main`: o Git Credential Manager abre; autorize pelo navegador
4. Senha do GitHub não vale ("Support for password authentication was removed"): a saída é o navegador ou um token (Settings, Developer settings)
5. Atualize a página: commits no ar. A turma faz o push agora
:::

Em `.gitignore`, mostre que `git status` não lista `node_modules`.

**Slides "Pense" a "Próximos passos" (7 min).** "Por que versionar sozinho?" Esperado: voltar a um commit quando algo quebra, backup, portfólio. Se ninguém responder, pergunte quem já perdeu trabalho em pendrive. Em "Erros comuns" aponte o `:q!`; em "Próximos passos", terminal aberto em `projetos-react`.

:::tip Ritmo
Faltando 10 min, corte o "Pratique" (o laboratório repete o ciclo). Nunca corte o push: os erros de autenticação devem aparecer com você na sala.
:::

## Bloco 2 · Primeiro projeto React com Vite e JSX (50 min)

**Slides "Por que um gerador de projeto?" e "Criando o projeto em 4 comandos" (9 min).** Resposta do slide: "três arquivos, `App.jsx`, `Cabecalho.jsx` e `Rodape.jsx`; o resto o Vite gera". Crie o projeto ao vivo em `projetos-react`:

:::steps
1. `npm create vite@latest minhas-tarefas -- --template react`. Se o gerador perguntar algo ("Install with npm and start now?"), `No` mantém a sequência do slide; se pedir o framework, React e JavaScript
2. `cd minhas-tarefas`, `npm install`: na espera, mostre o `package.json`
3. `npm run dev` e leia o endereço no terminal: se a 5173 estiver ocupada, o Vite sobe na 5174 e avisa; para liberá-la, `Ctrl + C` no terminal esquecido
4. Abra o endereço no navegador
:::

**Slides "O que cada arquivo faz" a "npm run dev e a recarga automática" (8 min).** Abra cada arquivo da tabela enquanto o lê. Troque o `<h1>` para "Minhas Tarefas", salve e deixe a turma olhar o navegador antes de falar.

**Slides "JSX: HTML dentro do JavaScript" a "Regra 3: toda tag fecha" (10 min).** Quebre cada regra ao vivo no `App.jsx` (dois irmãos sem raiz, `class`, `<img>` sem `/>`) e mostre a tela de erro do Vite e o conserto. Frise: `class` só avisa no console, os outros dois param a compilação (questão 5 do quiz).

**Slides "Expressões com chaves" e "Pense" (7 min).** Digite as quatro linhas com um nome da turma. "JSX é HTML?" Esperado: não; é JavaScript traduzido pelo Vite em chamadas de função, por isso `class` conflita com a palavra reservada e as chaves executam JavaScript. Se ninguém responder, mostre o código traduzido no DevTools (Sources, `src/App.jsx`).

**Slides "Seu primeiro componente: Saudacao" a "Resumo" (8 min).** Crie `src/components/Saudacao.jsx`, importe no `App` e esqueça o `export default` de propósito: a turma lê "Element type is invalid" na ordem do slide seguinte.

**Slide "No laboratório" e desafio (8 min).** Leia os seis passos. Desafio: cada aluno roda agora `npm create vite`, `cd` e `npm install`, para baixar durante a pausa; enquanto baixa, projete o trecho e peça os três erros (sem raiz, `class`, `<img>` aberta).

```jsx
function Cabecalho() {
  return (
    <img src="/logo.png" alt="Logo">
    <h1 class="titulo">Minhas Tarefas</h1>
  )
}
```

:::tip Ritmo
Apertou? Condense as três regras em 5 min de erros ao vivo. O `npm install` antes da pausa não se corta: economiza 10 min de laboratório.
:::

## Laboratório (70 min)

**Enunciado** (slide "No laboratório"): criar `minhas-tarefas` com Vite; `git init` e primeiro commit; limpar o modelo (`App` com fragmento vazio, `App.css` vazio); `Cabecalho.jsx` com `<header>` e título; `Rodape.jsx` com `<footer>`, nome e `{new Date().getFullYear()}`; os dois no `App`; segundo commit e push público.

**Sala**: individual (cada um precisa do próprio repositório), em duplas para se ajudarem.

**Marcos**: 15 min, `npm run dev` rodando; 25 min, primeiro commit; 45 min, `Cabecalho` e `Rodape` na tela; 60 min, push feito; 70 min, link no sistema.

**Circule observando**: prompt dentro de `minhas-tarefas`; `git status` sem `node_modules`; `export default` em cada componente; ano vindo da expressão; dois commits com mensagens claras.

:::example Solução de referência
```jsx
// src/App.jsx
import Cabecalho from './components/Cabecalho.jsx'
import Rodape from './components/Rodape.jsx'
import './App.css'

function App() {
  return (
    <>
      <Cabecalho />
      <Rodape />
    </>
  )
}

export default App
```

```jsx
// src/components/Cabecalho.jsx
function Cabecalho() {
  return (
    <header>
      <h1>Minhas Tarefas</h1>
    </header>
  )
}

export default Cabecalho
```

```jsx
// src/components/Rodape.jsx
function Rodape() {
  const ano = new Date().getFullYear()
  return (
    <footer>
      <p>Feito por Ana Souza, {ano}</p>
    </footer>
  )
}

export default Rodape
```

```bash
git init
git add .
git commit -m "Cria o projeto"
# ... depois de criar os componentes
git add .
git commit -m "Adiciona cabeçalho e rodapé"
git branch -M main
git remote add origin https://github.com/SEU-USUARIO/minhas-tarefas.git
git push -u origin main
```
:::

**Critérios**: roda sem erro; dois componentes em `src/components`; repositório público com dois commits ou mais, sem `node_modules`. **Entrega**: link do repositório no campo da aula no sistema, até o E03 para quem não fizer o push hoje.

## Fechamento (25 min)

**Correção coletiva (10 min)**: projete o repositório de dois ou três voluntários. Elogie commits com mensagens claras, componentes em arquivos próprios, ano calculado. Aponte sem nomear: `class` em vez de `className`, ano digitado, um único commit "update", `node_modules` enviado. Feche perguntando "o que o E03 muda aqui?": três cartões de tarefa diferentes.

**Quiz (15 min)**: `quiz-e02`, sete questões, três tentativas, nota mínima 70, gabarito ao fim. Podem consultar os slides, não o colega.

**Resultado**: questão 3 (`add` e `commit`) mal respondida, repita o ciclo ao vivo na abertura do E03; 5 ou 6 (regras do JSX), comece quebrando um componente e pedindo o conserto.

## Encerramento (5 min)

Tarefa: reler os slides; terminar o laboratório e o push (link até o E03); instalar as extensões que faltam; um terceiro commit mudando o título, para repetir o ciclo.

Prévia: "Hoje o cabeçalho é sempre igual; no E03, um mesmo componente mostra três tarefas diferentes com props, listas e estilos. Tragam o `minhas-tarefas` rodando".

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| `npm` ou `git` "não é reconhecido" | Terminal aberto antes da instalação, ou instalação incompleta | Reabrir o terminal; se persistir, reinstalar do pendrive |
| "npm.ps1 cannot be loaded" | Política de execução do PowerShell | Usar Command Prompt ou Git Bash no VS Code, ou `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| "Author identity unknown" no commit | Faltou `git config --global` | Os dois comandos do slide; repetir o commit |
| "src refspec main does not match any" no push | Sem commit, ou branch `master` | `git log`; depois `git branch -M main` e push |
| "Authentication failed" ou pedido de senha | Senha em vez de token, ou credencial de outra conta salva | Remover `git:https://github.com` do Gerenciador de Credenciais e repetir pelo navegador |

## Plano B

**Sem internet**: Git funciona offline: faça o Bloco 1 até o commit e deixe o push de tarefa. Para o Bloco 2 e o laboratório, distribua pelo pendrive o `minhas-tarefas` com `node_modules`; `npm run dev` roda sem rede.

**Sem projetor**: a turma acompanha os slides no sistema; você dita os comandos e circula.

**Aluno sem computador**: dupla com quem tem tudo instalado, revezando quem digita; o rodapé leva os dois nomes e o link vale pelos dois. Em casa, ele cria o próprio repositório.

**Sem celular**: não se aplica (celulares entram no E06).

**Instalação do E01 falhou**: instale pelo pendrive nos primeiros 8 min do Bloco 1 (Node e Git bastam), com um monitor no grupo. Quem não conseguir faz o laboratório em dupla e repete em casa.
