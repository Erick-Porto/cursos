## Visão do encontro

**Objetivo:** o `lojinha-regras` passa a se conferir sozinho: Jest com Babel, os primeiros testes (`abreviar` e as categorias do catálogo), um ciclo de TDD (`boasVindas`), o script `verificar`, variáveis de ambiente com `process.env` e `--env-file`, e o GitHub Actions rodando lint e testes a cada push e PR.

**Resultado ao fim das 4h:** 12 testes ou mais, `npm run verificar` sem erros, `.env` fora do Git e `.env.example` dentro, visto e selo verdes. É o último encontro da unidade Ambiente JavaScript: quem concluir as 8 aulas (E01 a E04) ganha a conquista **Primeiro script**.

**Pré-requisitos:** `lojinha-regras` do E03: `package.json` com `"type": "module"`, os scripts `catalogo`, `relatorio` e `lint` e o `picocolors` (E02); `eslint.config.js` com `@eslint/js` e `globals.node`, lint zerado (E03); repositório público no GitHub com `git push` funcionando e o fluxo de branch e PR do E03.

**A turma ainda não estudou a linguagem** (ela começa no E05). Hoje os alunos leem e copiam funções curtas, explicadas em uma frase; o foco é o que entra, o que sai e como conferir. Não detalhe o `if`, o `slice` nem o `+` de textos: "você vai entender cada parte a partir do E05".

**Materiais:** projetor com terminal e navegador lado a lado, quadro, Wi-Fi, seu repositório de demonstração, o repositório vitrine (abaixo) e o quiz publicado.

## Abertura (15 min)

Retomada (5 min):

1. "O que o lint encontra que o Prettier não encontra?" Esperado: erros no código, como uma variável que não existe ou um import errado; o Prettier só arruma a forma.
2. "Como você para um script numa linha para ver o valor de uma variável?" Esperado: um breakpoint no VS Code, clicando à esquerda do número da linha, e o script rodando pelo depurador. Gancho: "O depurador ajuda a achar um bug que você já sabe que existe. Hoje vocês ganham algo que acha o bug antes de alguém ver."
3. "Por que a mudança entra por uma branch e um PR, e não direto na `main`?" Esperado: alguém revisa antes do merge e a `main` fica sempre funcionando. Gancho para o Bloco 2: "Hoje a revisão ganha um revisor automático."

Tarefa de casa (5 min): abra 2 repositórios do E03 e confira o `eslint.config.js`, `npm run lint` sem erros e o PR mesclado. Quem está sem lint instala agora (`npm i -D eslint @eslint/js globals`) e copia o `eslint.config.js` da solução de referência abaixo: o `verificar` de hoje depende dele.

Objetivos (5 min): projete "O que você vai aprender" da aula 7. "Hoje o `lojinha-regras` ganha um revisor que não cansa: ele roda os testes a cada push e avisa quando algo quebra." Avise: "Vocês vão ler funções prontas. O que importa hoje é o que entra e o que sai; cada parte do código vocês aprendem a partir do E05."

## Bloco 1 · Testes automatizados com Jest (50 min)

**"O preço que sumiu" (5 min).** Pergunta do slide. Esperado: as funções que mexem com dinheiro e as que recebem o que alguém digitou, porque aparecem em vários lugares e um erro nelas custa caro.

**"Jest no lojinha-regras" (9 min).** Instalação coletiva, cada aluno no próprio projeto:

:::steps
1. `git status` limpo e o terminal do VS Code na raiz do `lojinha-regras`.
2. `npm i -D jest babel-jest @babel/preset-env`: os três entram em `devDependencies`, como o ESLint no E03.
3. `npm pkg set scripts.test=jest`: troca o `test` do `npm init` sem risco de vírgula errada. Abra o `package.json` e mostre a linha nova.
4. Crie o `babel.config.json` na raiz, com a linha do slide.
5. `npm test`: "No tests found, exiting with code 1" é esperado. Ainda não há teste.
:::

Quem não vê essa mensagem, você atende na pausa.

**"A função que você vai testar" e "Seu primeiro teste" (8 min).** Crie `src/utils/texto.js` copiando o slide e leia a frase do slide, sem detalhar o `if` nem o `slice`. Crie `texto.test.js`, leia cada teste como uma frase e rode: `Tests: 2 passed`. Pergunte: "Se amanhã alguém reescrever o `abreviar` de outro jeito, o teste muda?" Esperado: não; ele confere a promessa, não o jeito.

**"Lendo uma falha" (5 min).** Escreva o teste com `toBe('Caixa de Som…')`, colando o `…` de um documento (no Windows, <kbd>Alt</kbd> + <kbd>0133</kbd> no teclado numérico também produz o caractere). Rode e pergunte: "Quem está errado, a função ou o teste?" Esperado: o teste, porque o comentário da função promete três pontos. Mostre a linha marcada com `>`, corrija para `'Caixa de Som...'` e veja o verde.

**"Matchers" e "toBe ou toEqual?" (5 min).** Comente `toBe`, `toEqual`, `toContain` e `toHaveLength`; o `toThrow` volta no E17. Crie `src/data/produtos.test.js` com o teste do slide e mostre o `toBe` falhando com `serializes to the same string`. Troque por `toEqual` e acrescente o teste "são quatro", com `toHaveLength(4)`.

**"Arrange, act, assert" e "test.each" (6 min).** Escreva o teste "não passa do limite" e a tabela do `test.each`. **Quebre o código de propósito**: troque `<=` por `<` no `abreviar` e rode. Vermelho na linha do limite exato, com `Received: "Fone Blueto..."`. Desfaça: é o hábito que separa teste de enfeite. Rode `npm test -- --verbose` para mostrar os nomes montados pelo `%p`.

**"Pense" (4 min).** Duplas. Esperado: a tabela da resposta, com a borda dos espaços. Se surgir o nome vazio, anote no quadro como pergunta para a dona da loja: "Teste também serve para descobrir regra que ninguém decidiu."

**"TDD" (7 min).** Abra com o slide "TDD: o teste vem antes": deixe a animação do ciclo rodar uma volta e aponte a seta do próximo teste. Os slides seguintes acompanham a demonstração ao vivo, no `texto.test.js`:

:::steps
1. Escreva no quadro os três casos do Pense.
2. Importe o `boasVindas`, escreva o teste do `'Ana'` e rode: vermelho, `boasVindas is not a function`.
3. Verde mínimo: a função com `'Olá, ' + nome + '!'`. Verde.
4. Escreva o teste do `'  Ana '` e peça palpites do Received antes de rodar: vermelho, `"Olá,   Ana !"`. Compare com os palpites.
5. Acrescente o `.trim()`: os dois testes verdes.
6. Refatore os dois testes numa tabela do `test.each` e acrescente a linha do `'Ana Souza'`: três verdes.
:::

**"Cobertura" (3 min).** Comente o `describe` do `boasVindas` e rode `npm test -- --coverage`: `% Funcs` cai para 50 e a linha 8 aparece na coluna Uncovered. Abra `coverage/lcov-report/index.html` no navegador: a linha sem teste fica em vermelho. Volte o `describe`. "100% quer dizer sem bug?" Esperado: não, só que toda linha rodou.

**"Erros comuns" a "Próximos passos" (3 min).** Leitura rápida: a maioria já apareceu ao vivo.

:::tip Ritmo
Se atrasar, pule o relatório HTML da cobertura. A instalação, a leitura da falha e o TDD não se cortam: o laboratório usa os três.
:::

## Bloco 2 · Automação e integração contínua (50 min)

**"Funciona na minha máquina" (4 min).** Pergunta do slide. Esperado: um servidor que rode os testes a cada push e uma regra que exija verde para o merge.

**"O script verificar" e "O lint precisa conhecer o Jest" (8 min).** Ao vivo: acrescente `"verificar": "eslint . && jest"` no `package.json` e rode `npm run verificar`. O lint para em `'describe' is not defined` e os testes nem aparecem: é o `&&` trabalhando. Mostre o código de saída `1` com `echo $?` (Git Bash) ou `$LASTEXITCODE` (PowerShell). Acrescente o bloco do `globals.jest` no `eslint.config.js` e rode de novo: tudo verde, saída `0`.

**"Variáveis de ambiente" a ".env.example e .gitignore" (10 min).** Crie `src/scripts/ambiente.js` e rode com `node`: `API: undefined`. Crie o `.env` e rode com `--env-file=.env`: aparece o endereço. Rode com `--env-file=.env.local` para mostrar o `not found`. Crie o script `ambiente` no `package.json`. Mostre o `git status`: o `.env` aparece até entrar no `.gitignore`, junto com `coverage/`. Crie o `.env.example`. "O endereço da DummyJSON é segredo?" Esperado: não; a regra vale para senhas, tokens e chaves. O `EXPO_PUBLIC_` é só prévia do E30: uma frase basta.

**"Integração contínua com GitHub Actions" e "Do push ao visto verde" (3 min).** Desenhe no quadro: push, runner Linux novo, `npm ci`, `eslint .`, `jest`, visto ou X. O desenho fica até o laboratório. Projete a animação e pergunte: "se o lint falhar, o `jest` roda?" Esperado: não; o `&&` para no primeiro erro, o passo fica vermelho e o resultado é o X.

**"verificar.yml (1)" e "(2)" (8 min).** Explique o `npm ci`, que a turma só conhece de nome desde o E02: "é a instalação das máquinas limpas; apaga o `node_modules`, instala exatamente o lock e não conserta nada". No `lojinha-regras` de demonstração:

:::steps
1. `git switch -c feature/testes-e-ci`.
2. Crie `.github/workflows/verificar.yml` com as duas partes dos slides; mostre a pasta com ponto no VS Code.
3. Selo no topo do `README.md`, com o seu usuário.
4. Commit "E04: testes e CI" e `git push -u origin feature/testes-e-ci`.
5. Abra o PR: o check "Verificar / verificar" aparece amarelo.
6. Na aba Actions, abra o job e os passos enquanto rodam. A primeira execução leva de 1 a 3 minutos.
:::

**"Pense" (3 min).** Esperado: o runner só tem o que está no Git, e o lock antigo não tem o pacote novo; o `npm ci` não conserta o lock, e a correção é o commit do `package-lock.json`.

**"Lendo o resultado" e "Selo" (5 min).** Volte ao PR: visto verde. Faça o merge e mostre a execução na `main` disparada por ele; ao terminar, o selo do README fica verde.

**"CI vermelho bloqueia o merge" (4 min).** No repositório vitrine, abra o PR `demo/quebrado`: X vermelho e "Merging is blocked". No passo **Lint e testes**, leia com a turma a falha do limite exato: Expected `"Fone Bluetooth"`, Received `"Fone Blueto..."`. Mostre a regra em Settings > Branches: opcional no `lojinha-regras`, obrigatória em equipe.

**"Erros comuns" a "No laboratório" (2 min).** Leitura rápida.

**Desafio que prepara o laboratório (3 min).** Em duplas: "Listem os arquivos que vocês vão criar ou mudar e se cada um vai para o Git." Esperado: vão `texto.js`, `texto.test.js`, `produtos.test.js`, `ambiente.js`, `package.json`, o lock, `babel.config.json`, `eslint.config.js`, `.gitignore`, `.env.example`, `verificar.yml` e `README.md`; ficam fora `.env`, `coverage/` e `node_modules/`. A lista no quadro vira o checklist.

:::tip Ritmo
Se atrasar, só cite o `not found` do `--env-file`. O workflow ao vivo e o PR bloqueado não se cortam; se o Actions demorar, siga para o "Pense" e volte ao PR depois.
:::

**Enunciado:** os 6 passos do slide "No laboratório" da aula 8, com o checklist do quadro.

**Organização:** individual, na branch `feature/testes-e-ci`. A dupla do desafio revisa o PR do colega, como no E03, e só aprova com o check verde.

Para todo teste novo: "Você já viu esse teste vermelho?"

```javascript
// encurta o texto para caber em `limite` caracteres, terminando em '...'
export function abreviar(texto, limite) {
  if (texto.length <= limite) return texto;
  return texto.slice(0, limite - 3) + '...';
}

export function boasVindas(nome) {
  return 'Olá, ' + nome.trim() + '!';
}
```

`src/utils/texto.test.js`:

```javascript
import { abreviar, boasVindas } from './texto.js';

describe('abreviar', () => {
  test.each([
    ['Fone Bluetooth', 20, 'Fone Bluetooth'], // caminho feliz: cabe
    ['Caixa de Som Portátil', 15, 'Caixa de Som...'], // caminho feliz: corta
    ['Fone Bluetooth', 14, 'Fone Bluetooth'], // borda: exatamente no limite
    ['Jogo de Panelas', 10, 'Jogo de...'], // borda: limite pequeno
    ['', 10, ''], // borda: vazio
  ])('%p com limite %p vira %p', (texto, limite, esperado) => {
    expect(abreviar(texto, limite)).toBe(esperado);
  });

  test('não passa do limite', () => {
    // arrange: um nome longo e o limite
    const nome = 'Caixa de Som Portátil';
    const limite = 15;
    // act: chama a função, uma vez só
    const curto = abreviar(nome, limite);
    // assert: confere o resultado
    expect(curto).toHaveLength(limite);
  });

  test('texto que cabe não ganha reticências', () => {
    expect(abreviar('Fone Bluetooth', 20)).not.toContain('...');
  });
});

describe('boasVindas', () => {
  test.each([
    ['Ana', 'Olá, Ana!'], // caminho feliz
    ['Ana Souza', 'Olá, Ana Souza!'], // nome composto
    ['  Ana ', 'Olá, Ana!'], // borda: espaços nas pontas
  ])('%p vira %p', (nome, esperado) => {
    expect(boasVindas(nome)).toBe(esperado);
  });
});
```

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| "No tests found, exiting with code 1" | Nenhum arquivo termina em `.test.js` (por exemplo, `.teste.js`) | Conferir o nome; `npx jest --listTests` lista o que o Jest achou |
| `Must use import to load ES Module` ou `Cannot use import statement outside a module` | `babel.config.json` ausente, com outro nome ou fora da raiz | Conferir nome e local; o arquivo fica ao lado do `package.json` |
| `TypeError: ... is not a function` | Nome importado diferente do exportado, ou função sem `export` | Conferir a grafia no `import` e o `export` no `texto.js` |
| Expected e Received quase iguais | Reticências (`…`) ou aspas curvas copiadas de um documento | Redigitar o esperado no VS Code |
| Lint com `'describe' is not defined` | `eslint.config.js` sem o bloco dos testes ou com `files` errado | Colar o bloco do slide, com `'**/*.test.js'` |
| Lint com `'globals' is not defined` | Config sem o `import globals from 'globals'` do E03 | Import no topo e `npm i -D globals` |
| `API: undefined` | Script rodado sem `--env-file`, `.env` fora da raiz ou nome da variável diferente | `npm run ambiente`; conferir `API_URL` nos dois lados |
| `node: .env: not found` | Clone novo, sem o `.env` | `cp .env.example .env` (no Prompt de Comando, `copy`) |
| Push recusado: "refusing to allow a Personal Access Token to create or update workflow" | Token sem o escopo `workflow` | Novo token com `workflow`, ou novo login pelo Git Credential Manager |
| Nada aparece na aba Actions | Pasta `github` sem ponto, `workflow` no singular ou arquivo em outra branch | Caminho `.github/workflows/verificar.yml`, na branch do push |
| "Invalid workflow file" | Tab ou indentação errada no YAML | Reindentar com espaços; "Render Whitespace" no VS Code mostra os tabs |
| `npm ci` vermelho: "package.json and package-lock.json are in sync" | Lock fora do commit ou desatualizado | `npm install` local e commit do `package-lock.json` |
| `npm audit` aponta vulnerabilidade no Jest e sugere `--force` | Dependência antiga de uma ferramenta que só roda no computador | Não use `--force`: ele rebaixa o Jest para a versão 25 e quebra os testes |

## Plano B

- **Sem internet:** hotspot do seu celular e instalação do Jest em ondas de 4 alunos. Sem rede nenhuma, a turma escreve os testes em duplas nas máquinas que já têm o Jest; workflow e selo viram tarefa de casa e o quiz vai para o E05.
- **GitHub fora do ar ou Actions lento:** o laboratório até o `npm run verificar` não depende do GitHub. Mostre o CI no repositório vitrine e deixe o push para casa.
- **Aluno sem push funcionando:** segue localmente até o `verificar` verde e resolve a credencial em casa, com o passo a passo do E03.
- **Aluno sem o lint do E03:** `npm i -D eslint @eslint/js globals` e o `eslint.config.js` da solução de referência; sem ele, o `verificar` não passa do primeiro comando.
- **Jest que não instala:** feche o VS Code e qualquer terminal rodando script (no Windows, eles travam arquivos do `node_modules`) e repita. Passou de 10 minutos, dupla no laboratório e instalação em casa.
