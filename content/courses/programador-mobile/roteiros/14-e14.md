## Visão do encontro

**Objetivo:** ensinar a trabalhar com a lista inteira, além da peneira do `filter`: transformar cada item com `map`, achar um com `find` e `findIndex`, perguntar à lista com `some`, `every` e `includes`, escrever o teste da peneira em várias linhas (a seta com chaves e `return`) e pôr em ordem com `sort`, sempre numa cópia. Os passos do projeto são a prática do dia: `nomesDosContatos`, `buscarPorId` e `buscarContatos` juntos; a Sua vez é a `ordenarPorNome`.

**Como a aula funciona:** cada conceito vem em três slides, como na aula 3. A seção (título e gancho) é a hora da conversa: leia o gancho, ouça duas ou três respostas e explique com a analogia indicada abaixo. O slide seguinte é a âncora, o que o aluno lê para revisar. Todo método que percorre a lista tem a sua tabela item por item: monte no quadro com a turma **antes** de mostrar a do slide. Depois do conceito vem um slide **Projeto 2 · Passo K**: a turma faz junto com você, no próprio computador, e só segue quando o "Pronto quando" aparece em todas as telas. Depois de cada tema há um slide **Exercícios** com 3 a 5 exercícios e as respostas. Em aula, faça o primeiro em voz alta com a turma; os outros ficam para a revisão em casa.

**Resultado ao fim das 4h:** cada aluno tem o `agenda-de-contatos` no fim da etapa 2. O `src/regras/lista.js` tem, abaixo do comentário do kit, `nomesDosContatos`, `buscarPorId`, `buscarContatos` e `ordenarPorNome`, todas com `export` e sem `console.log`. O `src/regras/lista.test.js` tem 11 testes, e `npm test` mostra `Tests: 22 passed, 22 total` (3 suites). O `src/scripts/agenda.js` lê o termo do comando, mostra `Encontrados: N` e as linhas em ordem alfabética: `npm run agenda mar` mostra Helena, Marcos e Mariana. O commit `Projeto 2: etapa 2, buscar, ordenar e nomes` está no GitHub. Na página (`npx serve .`), o painel mostra 7 de 14.

**Pré-requisitos:** a etapa 1 pronta (E13): o kit rodando, `contato.js` com `criarContato`, `descreverContato` e `formatarAniversario`, 11 testes, o repositório público `agenda-de-contatos` com dois commits. Do curso: a peneira do `filter` e o teste com seta (aula 3), template string e `Math.round` (E06), `function`, `return`, a seta e o caso "com chaves, precisa de `return`" (E07), Jest com `toBe`, `toEqual` e `test.each` (E08), `trim`, `toLowerCase`, `includes` e `startsWith` de texto e o `%s` (E09), `if`, `&&`, `||`, `!`, `undefined` e `null`, `return` antecipado (E10), `for...of` e `push` (E11), `npx serve` (E12), fichas, colchetes e o kit (E13). A turma **não** viu `map`, `find`, `findIndex`, `some`, `every`, `includes` de lista, `sort`, `slice`, os três pontos `[...]` nem o `!==`. O spread a fundo, a referência (o endereço da casa) e a imutabilidade como regra são do E15: hoje, a cópia aparece só para o `sort`, e `const copia = contatos` é "outro nome para a mesma lista", sem mais.

**Materiais:** projetor com o VS Code em fonte grande, quadro (as tabelas item por item), Wi-Fi para o `git push`, a página do Projeto 2 aberta, quiz publicado. Fora do git, na sua máquina: `privado/projetos/projeto-2/etapa-1/` (o início de hoje), `etapa-2-juntos/` (depois dos três passos), `etapa-2/` (depois da Sua vez) e `conferir-agenda.mjs` (confere as funções de um aluno).

## Projeto: sua vez (30 min)

**Enunciado:** o slide "Projeto 2 · Sua vez: ordenarPorNome". A função `ordenarPorNome(contatos)` no `lista.js`, com `export`, devolvendo uma cópia em ordem alfabética (Álvaro primeiro, Rafael por último) sem mudar a lista recebida; dois testes (a ordem e "a lista recebida não mudou"); no `agenda.js`, os encontrados em ordem.

**Organização:** individual, sem olhar a tela do vizinho nos primeiros 15 minutos. Depois disso, quem travou pode pedir ajuda a um colega, que explica sem digitar por ele.

**Marcos:** 3:15, a função e o teste da ordem verdes (21); 3:25, o teste "não muda" verde (22); 3:35, `npm run agenda mar` em ordem, commit e push.

**O que observar:** o `sort` direto em `contatos`, ou `const copia = contatos;` (o teste "não muda" fica vermelho com `Received: "Álvaro Mendes"`, e a página avisa "ordenarPorNome mudou a lista que recebeu"); o `sort()` sem comparador (`Received: "Mariana Souza"` no teste da ordem: com fichas, cada uma vira o mesmo texto, `[object Object]`, e a ordem não muda); `a.localeCompare(b)` sem o `.nome` (`TypeError: a.localeCompare is not a function`); o `ordenarPorNome` esquecido no `import` do teste ou do `agenda.js` (`ReferenceError: ordenarPorNome is not defined`); o `nomes[14]` escrito como `nomes[15]` (dá `undefined`). Pergunta para quem travou: "o que o `sort` faz com a lista que recebe? E o que você quer que aconteça com a `contatos`?".

:::example Solução de referência
A função, no fim do `src/regras/lista.js`:

```javascript
// Uma lista nova, em ordem alfabética. A lista recebida fica como estava.
export function ordenarPorNome(contatos) {
  const copia = [...contatos];
  copia.sort((a, b) => a.nome.localeCompare(b.nome));
  return copia;
}
```

No `lista.test.js`, o `import` vira `import { nomesDosContatos, buscarPorId, buscarContatos, ordenarPorNome } from './lista.js';` e, no fim:

```javascript
test('ordenarPorNome: Álvaro primeiro, Rafael por último', () => {
  const nomes = nomesDosContatos(ordenarPorNome(contatos));
  expect(nomes[0]).toBe('Álvaro Mendes');
  expect(nomes[14]).toBe('Rafael Gomes');
});

test('ordenarPorNome não muda a lista recebida', () => {
  ordenarPorNome(contatos);
  expect(contatos[0].nome).toBe('Mariana Souza');
});
```

O `src/scripts/agenda.js` inteiro:

```javascript
// npm run agenda: mostra a agenda no terminal.
// Com uma palavra no fim, busca: npm run agenda mar
import { contatos } from '../data/contatos.js';
import { descreverContato, formatarAniversario } from '../regras/contato.js';
import { buscarContatos, ordenarPorNome } from '../regras/lista.js';

let termo = '';
if (process.argv[2]) {
  termo = process.argv[2];
}
const encontrados = ordenarPorNome(buscarContatos(contatos, termo));

console.log(`Agenda: ${contatos.length} contatos`);
console.log(`Encontrados: ${encontrados.length}`);

for (const contato of encontrados) {
  console.log(`${descreverContato(contato)}, aniversário ${formatarAniversario(contato)}`);
}
```

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| Os testes da busca vermelhos com `Received` `[]` e o do termo vazio com `Received: 0` | a seta com chaves sem o `return` | Ler o Caso 3 de "Seta com chaves na prática"; `return noNome \|\| noTelefone;` |
| Só o teste `"MAR"` vermelho | o termo sem `toLowerCase()` | `termo.trim().toLowerCase()`; o nome já está em minúsculas |
| `buscarPorId acha o Álvaro` com `Received: "Mariana Souza"` e outros testes com `99` no lugar do `1` | `contato.id = id`, com um `=` só: troca o id da Mariana | `===`, a pergunta de sim ou não |
| `buscarPorId` com `Received: undefined` e `Received: []` | `filter` no lugar do `find`: veio uma lista, e a lista não tem `.nome` | `find`, que entrega o item |
| `TypeError: (0 , _lista.buscarPorId) is not a function` | faltou o `export` antes da `function` | `export function buscarPorId` |
| `ReferenceError: ... is not defined` no teste ou no `agenda.js` | a função não entrou no `import` com chaves | acrescentar o nome no fim das chaves, na ordem em que as funções nasceram |
| `does not provide an export named 'formatarAniversario'` no `npm run agenda` | a Sua vez do E13 não foi feita | terminar o `formatarAniversario` pelos slides do E13 |
| `npm run agenda (11) 3456` mostra 9 contatos | sem aspas, o PowerShell some com os parênteses e manda só `11` | `npm run agenda "(11) 3456"` |
