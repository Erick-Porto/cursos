## Visão do encontro

**Objetivo:** fechar o Projeto 2, a Agenda de contatos, e aprender os módulos a fundo construindo a última etapa. A turma revê o `export` com nome, conhece o `export default` (e o `import` dos dois juntos), escreve o `validarContato`, que devolve a lista dos problemas do formulário, muda a ficha `NOMES_DOS_GRUPOS` para um arquivo só dela, vê a página do kit funcionando com as 14 funções, completa o README com o print e entrega. Não há laboratório à parte: os passos do projeto são a prática do dia.

**Como a aula funciona:** cada conceito vem em três slides, como na aula 3. A seção (título e gancho) é a hora da conversa: leia o gancho, ouça duas ou três respostas e explique com a analogia indicada abaixo. O slide seguinte é a âncora, o que o aluno lê para revisar. **Resultado ao fim das 4h:** cada aluno tem, no `agenda-de-contatos`, o `src/regras/validacao.js` com o `validarContato` (`export default`, as quatro regras e as quatro mensagens do enunciado), o `src/regras/validacao.test.js` com 5 testes, o `src/regras/grupos.js` com `export const NOMES_DOS_GRUPOS`, importado pelo `contato.js` e pelo `validacao.js`, e o README com a frase dele e o print em `docs/agenda.png`. `npm test` mostra `Test Suites: 5 passed, 5 total` e `Tests: 39 passed, 39 total`; `npm run agenda mar` continua igual ao do E15; a página, com `npx serve .`, mostra "Funções do seu projeto: 14 de 14" sem aviso, e salvar o formulário vazio mostra as três mensagens do nome, do telefone e do grupo. Commit `Projeto 2: etapa 4, validação e a agenda na web`, `git push` e o link entregue na página do Projeto 2. Prazo da entrega: início do E17.

**Pré-requisitos:** `export` e `import` com chaves de um arquivo próprio (E07); Jest com `test`, `expect`, `toBe` e `toEqual` (E08); `trim` e `includes` de texto (E09); `if`, `&&`, `||` e `!` (E10); `for...of` e `push` (E11); `npx serve .` e o print no README (E12); fichas, colchetes com a chave numa variável e `Object.keys` (E13); `includes` de lista (E14); spread de objeto, o Desfazer da página e um arquivo de regras importando outro, o `edicao.js` com o `criarContato` (E15). **Materiais:** projetor com o VS Code e o terminal lado a lado, fonte grande; quadro com duas cores; a sua cópia do projeto no fim da etapa 3 (para a demonstração do problema) e outra para fazer a etapa ao vivo; uma pasta de demonstração `demo-cardapio`, fora de qualquer projeto (veja "Antes do encontro"); a página do Projeto 2 aberta (página do curso, seção **Projetos**), com o guia de correção ao lado; quiz publicado. 1. "O que o `[...contatos, novo]` faz com a lista `contatos`?" Esperado: nada; ele monta uma lista nova, com todos de antes e o novo no fim. É tirar uma cópia e mexer na cópia, sem rasurar o original.

## Projeto: sua vez (30 min)

**Enunciado:** os slides "Projeto 2 · Sua vez: o e-mail" e "Projeto 2 · Sua vez: o grupo". **O que observar:** `&&` no lugar do `||` no e-mail (o teste "e-mail sem @ não passa" fica vermelho, recebendo `[]`: só reclama quando faltam os dois); o `if` do e-mail sem o "veio alguma coisa?" antes (três testes ficam vermelhos, os que usam o e-mail vazio da ficha `certo`, cada um recebendo um `E-mail inválido` a mais: o e-mail vazio também não tem `@`); `grupos.includes` direto na ficha, sem o `Object.keys` (`TypeError: grupos.includes is not a function` em todos os testes do arquivo); o `!` esquecido na regra do grupo (todos os 5 testes vermelhos: o grupo certo passou a ser o problema); a ficha copiada para o `validacao.js` em vez do `import` (funciona, mas perde o critério da rubrica); um teste com a ficha incompleta, `{ email: 'x' }`, no lugar de `{ ...certo, email: 'x' }` (`Cannot read properties of undefined (reading 'trim')`). Pergunta para quem travou: "que pergunta de sim ou não você quer fazer ao e-mail? E se ele vier vazio, o que deve acontecer?".

:::example Solução de referência
`src/regras/validacao.js` inteiro, no fim da etapa 4:

```javascript
// Etapa 4 (E16): conferir os dados do formulário antes de salvar.
//
// Aqui entra, com export default:
//   validarContato(dados)   a lista dos problemas; lista vazia quando está tudo certo
//
// O que ela recebe e devolve, com exemplos, está no enunciado do Projeto 2.

import { soDigitos } from './texto.js';
import { NOMES_DOS_GRUPOS } from './grupos.js';

// Confere os dados do formulário e devolve a lista dos problemas, na ordem dos campos.
// Tudo certo: a lista vem vazia.
export default function validarContato(dados) {
  const erros = [];

  if (dados.nome.trim() === '') {
    erros.push('Informe o nome');
  }

  const digitos = soDigitos(dados.telefone).length;
  if (digitos !== 10 && digitos !== 11) {
    erros.push('O telefone precisa de 10 ou 11 dígitos, com o DDD');
  }

  const email = dados.email.trim();
  if (email !== '') {
    if (!email.includes('@') || !email.includes('.')) {
      erros.push('E-mail inválido');
    }
  }

  const grupos = Object.keys(NOMES_DOS_GRUPOS);
  if (!grupos.includes(dados.grupo)) {
    erros.push('Escolha família, amigos ou trabalho');
  }

  return erros;
}
```

`src/regras/validacao.test.js` inteiro (os dois primeiros testes são do passo 1):

```javascript
import validarContato from './validacao.js';

const certo = {
  nome: 'Rafaela Lopes',
  telefone: '(11) 91234-5678',
  email: '',
  grupo: 'amigos',
  aniversario: null,
};

test('dados certos: nenhum problema', () => {
  expect(validarContato(certo)).toEqual([]);
});

test('nome vazio e telefone sem DDD: dois problemas, na ordem dos campos', () => {
  const dados = { ...certo, nome: '   ', telefone: '98765-4321' };
  expect(validarContato(dados)).toEqual([
    'Informe o nome',
    'O telefone precisa de 10 ou 11 dígitos, com o DDD',
  ]);
});

test('e-mail com @ e ponto passa', () => {
  expect(validarContato({ ...certo, email: 'rafaela@exemplo.com' })).toEqual([]);
});

test('e-mail sem @ não passa', () => {
  expect(validarContato({ ...certo, email: 'rafaela.exemplo.com' })).toEqual(['E-mail inválido']);
});

test('grupo que não existe não passa', () => {
  expect(validarContato({ ...certo, grupo: 'vizinhos' })).toEqual([
    'Escolha família, amigos ou trabalho',
  ]);
```

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| `TypeError: (0 , _validacao.default) is not a function` em todos os testes do arquivo | `export function validarContato`, sem o `default` | `export default function validarContato`; a página também avisa: "Ela tem export com nome; o combinado é export default." |
| `TypeError: (0 , _validacao.validarContato) is not a function` | chaves no `import` do teste, com a função em `export default` | `import validarContato from './validacao.js'`, sem chaves |
| `ReferenceError: NOMES_DOS_GRUPOS is not defined` nos testes do `descreverContato` | a ficha saiu do `contato.js`, e o `import` não entrou | `import { NOMES_DOS_GRUPOS } from './grupos.js';` logo abaixo do comentário do kit |
| `Cannot read properties of undefined (reading 'amigos')` no Jest; `does not provide an export named 'NOMES_DOS_GRUPOS'` no `npm run agenda` e na página | faltou o `export` antes do `const` no `grupos.js` (o Jest, com o Babel, deixa o nome `undefined`; o Node e o navegador recusam o arquivo) | `export const NOMES_DOS_GRUPOS` |
| `e-mail sem @ não passa` vermelho, recebendo `[]` | `&&` no lugar do `\|\|` | `!email.includes('@') \|\| !email.includes('.')` |
| `TypeError: grupos.includes is not a function` | o `includes` direto na ficha, sem o `Object.keys` | `Object.keys(NOMES_DOS_GRUPOS)` dá a lista; o `includes` é dela |
| `Cannot read properties of undefined (reading 'trim')` | um teste com uma ficha sem o campo (`{ nome: 'Ana' }`) | a ficha `certo` com o campo trocado: `{ ...certo, ... }` |
| testes verdes, mas a página diz "Não deu para importar src/regras/edicao.js: Failed to fetch dynamically imported module" | um `import` sem o `.js` dentro de um arquivo de regras: o Jest acha, o navegador não | `from './contato.js'`; o Console (<kbd>F12</kbd>) mostra o arquivo |
| a página fica em "Carregando as suas funções..." | aberta com dois cliques, ou sem o `/web/` no fim | `npx serve .` na raiz e `http://localhost:3000/web/` |
| a imagem não aparece no README | o caminho ou o nome do arquivo (`Docs/Agenda.PNG`, `agenda.png.png`) | `docs/agenda.png`, igual ao nome do arquivo, tudo em minúsculas |
