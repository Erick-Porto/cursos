## Visão do encontro

**Objetivo:** levar o Racha-conta para o GitHub e aprender o Git fazendo isso. A turma confere a identidade do Git, cria o repositório, deixa o `node_modules` de fora com o `.gitignore`, tira a foto da etapa 1, cria o repositório público no GitHub, faz o primeiro push com o login, escreve o README em Markdown e lê o histórico no terminal e no site. É a etapa 2 do Projeto 1: o código do `racha.js` não muda.

**Como a aula funciona:** igual ao E04. Cada conceito abre com o slide de seção (título e gancho): leia o gancho, ouça duas ou três respostas e explique com a analogia indicada abaixo. O slide seguinte é a âncora, o que o aluno lê para revisar. Depois do conceito vem um **Projeto 1 · Passo K**: a turma faz junto com você e só segue quando o "Pronto quando" aparece na tela de todos. No fim, a **Sua vez** é feita sozinho, sem a solução no slide.

**As analogias do dia, sempre as mesmas:** o repositório é o álbum de fotos do projeto; o commit é a foto com legenda (o `git add` chama quem vai sair na foto, o `git commit` clica); o `.gitignore` é o que fica fora da foto; o GitHub é o álbum na nuvem, como o backup de fotos do celular da aula 2; o push é mandar a sua cópia para a nuvem; o README é o manual que vem na caixa; o histórico é o álbum inteiro, da foto mais nova para a mais velha.

**Fora do encontro:** branch como rascunho paralelo, pull request, Issues e `git pull` ficam para o E42 (Git em equipe); o `git clone` aparece só como comando de recuperação, no Plano B. O `git branch -M main` aparece só como "a linha principal se chama `main`". Se alguém perguntar por branch: "é para trabalhar em equipe, no E42".

**Resultado ao fim das 4h:** cada aluno tem `github.com/<usuario>/racha-conta`, **público**, com `src/`, `.gitignore` (uma linha: `node_modules/`), `package.json`, `package-lock.json` e `README.md` com as seções "Como rodar" e "O que ele mostra". **Sem** `node_modules`. O histórico tem 3 commits: `Projeto 1: etapa 1, a conta no terminal`, `Projeto 1: etapa 2, GitHub e README` e o da Sua vez (mensagem livre). Na máquina, a pasta tem o `.git` e o `origin` gravado com `-u`, e `npm run racha` mostra a mesma saída do E04.

**Pré-requisitos:** do E01 (aula 2), o Git instalado e configurado (`user.name`, `user.email`, `init.defaultBranch main`), a conta no GitHub e as seções "Git" e "GitHub" (o álbum de fotos e o backup na nuvem). Do E04, a etapa 1 pronta: `npm run racha` com `Subtotal: R$ 187.50`, `Unidades pedidas: 5` e `Itens acima de R$ 50: 2`. A turma **nunca** fez um commit e não conhece Markdown.

**Materiais:** projetor com o terminal do VS Code em fonte grande e o navegador logado na sua conta do GitHub, quadro, Wi-Fi com o github.com liberado (navegador **e** `git push`), a página do Projeto 1 aberta, quiz publicado, e num pendrive a pasta `etapa-1` da solução de referência (`privado/projetos/projeto-1/etapa-1/`, só na sua máquina) para quem chegar sem o projeto.

## Antes do encontro

:::steps
1. Na véspera, avise a turma: tragam o usuário e a senha do GitHub, o celular com o app da verificação em duas etapas, se a conta tiver, e o acesso ao e-mail da conta (o GitHub manda um código para o e-mail quando alguém entra num computador novo). Quem esqueceu a senha recupera antes da aula.
2. Ensaie a etapa 2 inteira na sua pasta do E04, com push de verdade. Depois, apague o ensaio: no GitHub, **Settings** do repositório, no fim da página, **Delete this repository**; na pasta, a pasta oculta `.git` (no PowerShell, dentro da `racha-conta`: `Remove-Item -Recurse -Force .git`). A demonstração ao vivo começa no `git init` e cria o `racha-conta` de novo na sua conta.
3. Num computador do laboratório: `git --version` e `git credential-manager --version` (o Git Credential Manager é quem abre a janela **Connect to GitHub** no primeiro push). Rode `git config --global user.name`: se aparecer o nome de outra pessoa, a turma vai ver o mesmo, e o Passo 1 resolve.
4. Na rede da escola, faça um push de teste num repositório seu: confirma que o proxy deixa passar o `git push` e o login pelo navegador. No fim, `git credential-manager github logout <seu-usuario>` e saia do GitHub no navegador.
5. Abra a página do Projeto 1: no critério **Repositório** (15 pontos), a rubrica pede o repositório público, sem `node_modules`, com um commit por etapa e o README. Você mostra isso na abertura.
6. Faça uma tentativa de teste no quiz.
:::

## Abertura (10 min)

**Retomada do E04 (4 min):**

1. "Para levar o Racha-conta para outro computador, o que vai junto?" Esperado: `src/`, `package.json` e `package-lock.json`; o `node_modules` não. Gancho: "Hoje um arquivo de uma linha deixa o `node_modules` de fora sozinho."
2. "Se o `node_modules` sumir, como ele volta?" Esperado: com `npm install`, que lê a ficha e a nota fiscal.
3. "No E01, vocês gravaram o nome e o e-mail no Git. Para quê?" Esperado: para assinar as fotos. Se ninguém lembrar, não insista: o Passo 1 retoma.

**Projeto no lugar (4 min).** Todos abrem o VS Code na pasta `racha-conta` (da pasta de projetos: `cd racha-conta` e `code .`) e rodam `npm run racha`. Confira, mesa por mesa, as três últimas linhas da etapa 1. Quem não tem as duas linhas da Sua vez do E04 (unidades e itens caros) faz os passos 1 e 2 com a turma, escreve as duas linhas na folga do fim do Bloco 1 e só então tira a foto do Passo 3: a foto da etapa 1 precisa sair completa. Quem perdeu a pasta copia a `etapa-1` do pendrive para a pasta de projetos, ao lado do `lojinha-regras`, e roda `npm install`: hoje a aula é o Git, não o código do E04.

**Objetivos (2 min).** Projete "O que você vai aprender". "Hoje o Racha-conta sai deste computador. Cada etapa vira uma foto com legenda, e eu corrijo o projeto pelo link do GitHub de vocês."

## Bloco 1 · O álbum no computador (80 min)

**"Palavras novas de hoje" (3 min).** Leia as seis palavras com um exemplo rápido de cada uma. Não explique ainda: cada uma ganha a sua seção.

**"O Racha-conta só existe aqui" (5 min).** Leia o slide e faça a pergunta. Esperado: pendrive, e-mail, Google Drive. "Tudo isso é cópia solta, sem saber o que mudou de uma para outra. O Git guarda uma foto de cada etapa, e o GitHub guarda as fotos na nuvem." Mostre na página do Projeto 1 o critério **Repositório**, 15 pontos.

**Projeto · Passo 1 (7 min).** Todos rodam os dois `git config --global` sem valor. Três situações:

- Aparece o nome e o e-mail do aluno: siga.
- Vem vazio: os três comandos do slide, com aspas no nome (sem aspas, o Git grava só a primeira palavra, como na aula 2).
- Aparece o nome de **outra pessoa** (comum no laboratório): o aluno grava o dele. "A foto sai com a assinatura de quem estiver configurado no computador."

Peça que confiram o e-mail no github.com, **Settings**, **Emails**: precisa ser o mesmo, senão os commits aparecem no GitHub sem a foto do perfil.

**Seção "O repositório" (8 min).** Leia o gancho. Esperado: num álbum, numa pasta do celular separada por data. "O repositório é o álbum do projeto: cada commit é uma foto de todos os arquivos naquele momento." Em "Repositório: o álbum do projeto", rode na sua pasta `git init` e `git status`. Leia a tradução do slide e aponte o `node_modules/`: "isso vai para o GitHub?". Esperado: não, o `npm install` refaz. Diga que a pasta `.git` não aparece no painel do VS Code: ele a esconde de propósito, para ninguém mexer.

**"O repositório na prática" (5 min).** Ao vivo, o caso 1: `cd ..`, `git status` (o `fatal`), `cd racha-conta`. O caso 2: `git init` de novo (o `Reinitialized`). O caso 3 só pelo slide, sem demonstrar: "se alguém vir as pastas dos projetos no `git status`, me chame antes de seguir".

**Seção "O .gitignore" (7 min).** Leia o gancho. Esperado: a bagunça, a roupa na cadeira. "O `.gitignore` é a lista do que fica fora da foto." Pergunte por que o `node_modules` fica fora. Esperado: é grande e o `npm install` refaz (E04). Na tabela "Entra nas fotos?", pergunte linha por linha antes de mostrar. Leia o aviso do nome em voz alta.

**Projeto · Passo 2 (12 min).** Todos ao mesmo tempo, você no projetor. Antes do `git init`, confira mesa por mesa que o terminal termina em `racha-conta`. Para criar o `.gitignore` na raiz: clique num espaço vazio do painel (para o arquivo não nascer dentro de `src`) e use o ícone de arquivo novo. Circule procurando: `.gitignore` dentro de `src/`; nome `gitignore`, sem o ponto; arquivo não salvo (bolinha branca na aba). O "Pronto quando" é a pasta `node_modules` cinza no painel: dá para conferir de longe.

**Seção "Commits" (8 min).** Leia o gancho. Esperado: alguém chama todo mundo, arruma quem fica na frente, "olha o passarinho". "O `git add` chama para a foto; o `git commit` clica e escreve a legenda." Em "Commit: a foto com legenda", aponte os três itens e pergunte: "depois do commit, o GitHub já tem a foto?". Esperado: não; a foto fica no computador. Escreva no quadro: `add` = chamar, `commit` = clicar.

**"O commit em português" (5 min).** Leia a tabela. "O código da foto de cada um vai ser outro: é como o número de série." O `git log --oneline` volta no Passo 3 e na seção do histórico.

**"Commits na prática" (7 min).** Na sua pasta, `git add .` e `git status`: os arquivos passam para `Changes to be committed`, com `new file:` na frente de cada um. Mostre a linha correspondente da tabela. Pergunte: "se eu mudar um arquivo agora, sem outro `git add`, ele entra na foto?". Esperado: não; vai para `Changes not staged for commit`. A linha do `modified` a turma vê de verdade na Sua vez, com o README.

**Projeto · Passo 3 (10 min).** A turma roda os três comandos. Os dois `warning: ... LF will be replaced by CRLF` assustam: "é aviso do Windows sobre o fim das linhas, não é erro". Quem receber `Author identity unknown` volta ao Passo 1. Quem rodou `git commit` sem o `-m` cai num editor no terminal (o Vim): <kbd>Esc</kbd>, `:q!` e <kbd>Enter</kbd>, e repete com o `-m`. Peça que alguns leiam em voz alta o código da foto: são todos diferentes. Termine com `git status` em todas as máquinas: `nothing to commit, working tree clean`.

**Folga (3 min).** Para quem ficou para trás nos passos 2 e 3, e para as duas linhas da Sua vez do E04 de quem ainda não tinha (depois delas, `git add .` e o commit da etapa 1).

:::tip Ritmo
Se atrasar, mostre "O repositório na prática" e "O commit em português" só pelo slide. O Passo 2 com o `node_modules` cinza e o Passo 3 com o `working tree clean` em **todas** as máquinas não se cortam: sem a primeira foto, o push do Bloco 2 falha com `src refspec main does not match any`.
:::

## Bloco 2 · O álbum na nuvem (75 min)

**Seção "GitHub e push" (5 min).** Leia o gancho. Esperado: quem tem backup na nuvem não perde nada. "O GitHub é o álbum na nuvem, o backup de fotos do celular da aula 2." Em "GitHub: o álbum na nuvem", abra o seu perfil no GitHub e mostre um endereço `github.com/usuario/repositorio`. "Público quer dizer que eu, e qualquer recrutador, abrimos pelo link."

**"Push: mandar a sua cópia para a nuvem" (4 min).** Percorra o diagrama com o dedo: as duas setas de cima a turma já fez; a de baixo é agora. Pergunte: "vocês mudam o README, não fazem commit e dão push. O GitHub recebe o README novo?". Esperado: não; só vai o que virou foto.

**"Os três comandos em português" (5 min).** Leia a tabela. "O GitHub mostra os três prontos, com o usuário de vocês: ninguém digita o endereço." Do `git branch -M main`, diga só o que está no slide; a palavra branch tem outro uso, que fica para o E42.

**"O login no primeiro push" (3 min).** Leia os cinco passos. "O código pode vir do app da verificação em duas etapas ou do e-mail. Quem está sem o celular entra pelo e-mail."

**Projeto · Passo 4 (25 min).** Primeiro você, no projetor, do começo ao fim, com a sua conta. Depois a turma, e você circula.

:::steps
1. No github.com, o **+** fica no alto, à direita. O nome do repositório é exatamente `racha-conta`. Visibilidade **Public**. README, `.gitignore` e licença desligados: é o erro mais comum do dia (o push é recusado com `fetch first`).
2. Depois do **Create repository**, a página mostra "Quick setup". O terceiro bloco, *…or push an existing repository from the command line*, tem um botão de copiar à direita.
3. Ao colar no terminal, o VS Code pode perguntar se quer colar várias linhas: **Paste**. Se a última linha ficar parada, <kbd>Enter</kbd>.
4. A janela **Connect to GitHub**: **Sign in with your browser**. O navegador abre no GitHub; o aluno entra, digita o código da verificação (app ou e-mail) e autoriza o **Git Credential Manager** no botão verde. A aba diz que a autenticação deu certo; o push termina no terminal.
5. Se, no lugar da janela, o VS Code mostrar *The extension 'GitHub' wants to sign in using GitHub*, clique em **Allow**: o caminho no navegador é o mesmo, autorizando o Visual Studio Code.
:::

Marcos: 2:05, todos com o repositório criado; 2:15, todos com o push. Quem travar no login segue com o Passo 5, que é local até o push, e você ajuda em paralelo; o primeiro `git push -u origin main` dele leva as duas fotos de uma vez. O "Pronto quando" é a página recarregada sem `node_modules`: peça que virem a tela para você.

**Seção "O README" (6 min).** Leia o gancho. Esperado: no manual, na caixa, num vídeo. "O README é o manual que vem na caixa: o que o projeto faz e como ligar." Pergunte: "como vocês deixam uma palavra em negrito no WhatsApp?". Esperado: asteriscos. "O Markdown é isso: marcas simples que viram formatação." Leia a tabela linha por linha.

**"Markdown na prática" (5 min).** Ao vivo, num arquivo de teste: a crase no teclado ABNT2 (<kbd>Shift</kbd> + a tecla do acento agudo, depois espaço, três vezes) e o mesmo bloco com `´´´` na prévia, que não vira bloco. Depois, `#racha-conta` sem espaço na prévia. Se o VS Code completar crases sozinho, apague as que sobrarem. Apague o arquivo de teste.

**Projeto · Passo 5 (12 min).** A turma cria o `README.md` na raiz (o mesmo cuidado do `.gitignore`: fora de `src`) e digita, sem copiar: é curto, e é digitando que se aprende o Markdown. Prévia com <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>V</kbd>. Depois, os três comandos. Saída esperada:

```plaintext
[main 8505def] Projeto 1: etapa 2, GitHub e README
 1 file changed, 10 insertions(+)
 create mode 100644 README.md
To https://github.com/ana-souza/racha-conta.git
   801afb4..8505def  main -> main
```

Quem não completou o push do Passo 4 recebe `fatal: The current branch main has no upstream branch`: para ele, o comando é `git push -u origin main`. Recarregue a sua página no projetor: o README aparece embaixo dos arquivos.

**Seção "O histórico" (5 min).** Leia o gancho. Esperado: pela data, rolando, pela busca. "O histórico é o álbum inteiro, e é a legenda que diz o que tem em cada foto." Na sua pasta, `git log --oneline`: aponte `HEAD -> main` e `origin/main` na mesma linha. No GitHub, clique no link **Commits** (com o relógio), abra a foto da etapa 2 e mostre o README em verde, com `+`.

**"O histórico na prática" (3 min).** No caso 1, pergunte "o que falta?" antes de ler. Esperado: o push. No caso 2, peça a versão boa de cada legenda ruim antes de mostrar a coluna da direita.

**"Quando aparece um erro" (2 min).** Lembre a luz do painel do carro da aula 3 e pergunte quais a turma já viu hoje.

:::tip Ritmo
Se o Passo 4 passar dos 25 minutos por causa dos logins, mostre "Markdown na prática" e "O histórico na prática" só pelo slide: a Sua vez retoma os dois. O Passo 4 com o push e o Passo 5 com o README no GitHub não se cortam: sem eles, a etapa 2 não existe.
:::

## Projeto: sua vez (30 min)

**Apresentação (3 min).** Projete "Projeto 1 · Sua vez: o que ele mostra" e "Etapa 2 pronta". Leia as dicas em voz alta. Mostre no projetor como se seleciona a saída no terminal e se copia com <kbd>Ctrl</kbd> + <kbd>C</kbd> (sem seleção, o atalho interrompe o comando, o que aqui não faz mal).

**Enunciado:** no README, depois de "Como rodar", a seção `## O que ele mostra`, com a saída do `npm run racha` num bloco de código `plaintext`. Commit com uma legenda que diga o que mudou, `git push` e, no GitHub, o histórico com 3 commits.

**Organização:** individual, sem olhar a tela do vizinho nos primeiros 15 minutos. Depois, quem travou pode pedir ajuda a um colega, que explica sem digitar por ele.

**Marcos:** 3:15, o README com a seção nova certa na prévia; 3:25, commit e push; 3:35, o histórico com 3 commits no GitHub.

**O que observar:**

- A saída colada **sem** o bloco: no GitHub, a tabela vira uma linha só, embaralhada. Pergunte: "o que faz o texto aparecer com letra de máquina de escrever?".
- O bloco aberto com `´´´` ou sem as crases do fim: o resto do README vira código.
- A saída copiada com as duas linhas `>` do npm: não é erro, mas o enunciado pede de `Racha-conta:` até a última.
- O README salvo? `nothing to commit, working tree clean` logo depois de mexer quer dizer arquivo não salvo.
- Commit sem push: o `git log --oneline` mostra o `origin/main` uma linha abaixo. É o caso 1 do histórico.
- Legenda `aaa` ou `readme`: peça uma que diga o que mudou.

Pergunta para quem travou: "o que o `git status` diz agora? Em qual grupo está o README?".

Os comandos e as saídas, conferidos no Git 2.49 do Windows (os códigos das fotos mudam a cada máquina):

```bash
git status
git add .
git commit -m "README: o que o racha-conta mostra"
git push
git log --oneline
```

## Fechamento (20 min)

**Correção da sua vez (6 min).** Com licença, projete o repositório de um aluno que acertou: o README com a tabela dentro do bloco, o link **Commits** com as 3 fotos e, dentro da foto da Sua vez, as 19 linhas novas em verde. Depois, mostre no quadro o erro mais comum que você viu (em geral, o bloco sem crases ou com `´´´`). Feche: "do E06 em diante, toda etapa termina com `git add .`, `git commit` e `git push`".

**Quiz (14 min).** `Quiz: E05 · Git e GitHub`: 10 questões, 70% para aprovar, 3 tentativas, gabarito ao fim. Individual, slides fechados. Avise que a de completar pede uma palavra exata. Se a questão do `git status` com os dois grupos ou a do `origin/main` uma linha abaixo passar de 30% de erro no painel, refaça as duas na abertura do E06.

## Encerramento (5 min)

**Computador do laboratório (2 min).** Antes de sair, cada um roda `git credential-manager github logout <seu-usuario>` e sai da conta do GitHub no navegador. Sem isso, o próximo aluno daquela máquina envia commits com a conta de outra pessoa ou recebe `403`. Se a resposta for `warning: no such account`, o nome está errado: `git credential-manager github list` mostra as contas guardadas.

**Tarefa de casa:** terminar a etapa 2, se faltou (README com as duas seções, os 3 commits e o push), e refazer o quiz quem ficou abaixo de 70%. Quem quiser: abrir o próprio perfil no GitHub e conferir que o `racha-conta` aparece lá.

**Prévia do E06:** "Números, textos e dinheiro. O Racha-conta calcula a gorjeta e o total em centavos, sem o erro do `0.1 + 0.2`, e a etapa 3 termina com commit e push, como hoje."

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| `git status` lista `lojinha-regras/` e `racha-conta/` | `git init` rodado na pasta de projetos | Na pasta de projetos (confira o caminho), `Remove-Item -Recurse -Force .git`; depois `cd racha-conta` e `git init` |
| `node_modules/` continua no `git status` | `.gitignore` com outro nome (`gitignore`, `.gitignore.txt`), dentro de `src/` ou não salvo | Renomear, mover para a raiz, salvar |
| `warning: ... LF will be replaced by CRLF` | o Git do Windows ajustando o fim das linhas | É só aviso: siga |
| `Author identity unknown` no commit | computador sem `user.name` e `user.email` | Os três `git config --global` do Passo 1 |
| O commit saiu com o nome de outra pessoa (`git log`, sem `--oneline`, mostra o `Author`) | o `git config` do aluno anterior | Grave os dados certos e, **antes do push**, digite para ele `git commit --amend --reset-author --no-edit` |
| Um editor estranho abre depois do `git commit` | faltou o `-m "..."` | <kbd>Esc</kbd>, `:q!`, <kbd>Enter</kbd>; repetir com `-m` |
| `[rejected] main -> main (fetch first)` | repositório criado com README | No GitHub, **Settings**, no fim, **Delete this repository**; criar de novo, vazio, com o mesmo nome, e rodar `git push -u origin main` de novo |
| `Repository not found` no push | usuário ou nome do repositório com erro no endereço, ou repositório não criado | Copiar o endereço da página do GitHub: `git remote set-url origin https://github.com/<usuario>/racha-conta.git` |
| `Permission to ... denied to outra-pessoa` e `403` | o computador guardou o login de outra pessoa | `git credential-manager github logout outra-pessoa` e push de novo: a janela de login volta |
| O terminal pede `Username for 'https://github.com':` | Git sem o Credential Manager | Plano B (token) |
| `fatal: The current branch main has no upstream branch` | o primeiro push, com `-u`, não terminou | `git push -u origin main` |
| `GH007: Your push would publish a private email address` | a conta esconde o e-mail e bloqueia push com ele | No GitHub, **Settings**, **Emails**: desmarcar o bloqueio de push que expõe o e-mail, e push de novo |
| O README não aparece na página do repositório | `README.md` dentro de `src/`, ou sem commit e push | Mover para a raiz, commit e push |
| No GitHub, o README mostra `´´´` ou vira todo código | acento agudo no lugar da crase, ou faltou fechar o bloco | Trocar por crases; três no fim do bloco |

## Plano B

- **Sem internet, ou o GitHub bloqueado pela rede:** os passos 1, 2, 3 e o README do Passo 5 são locais (`init`, `.gitignore`, commits). O repositório no GitHub e o push vão para casa ou para o começo do E06: um único `git push -u origin main` leva todas as fotos. O quiz não depende do push.
- **O login não funciona (sem o Credential Manager, ou o navegador não volta):** um token. No github.com, **Settings**, **Developer settings**, **Personal access tokens**, **Tokens (classic)**, **Generate new token (classic)**, marque `repo`, gere e copie. Quando o terminal pedir `Username`, o usuário; em `Password`, cole o token (o terminal não mostra nada enquanto você cola). Apague o token no fim da aula.
- **Aluno sem acesso à conta (senha ou verificação em duas etapas):** recuperação na pausa; enquanto isso, ele faz os commits locais. O push vai em casa.
- **Computadores do laboratório apagados entre os encontros:** agora o projeto está no GitHub. No começo do E06, antes de tudo, cada um recupera a pasta na pasta de projetos com `git clone https://github.com/<usuario>/racha-conta.git`, `cd racha-conta` e `npm install` (e confere o Passo 1 de novo). O `git clone` não é conteúdo do E05: mostre como comando de recuperação.
- **Sem projetor:** os slides no celular de cada aluno e as demonstrações em grupos em volta do seu computador.
- **Turma atrasada:** a Sua vez vai para casa, com prazo até o início do E06. Os passos 1 a 5 não se cortam: o E06 começa com o repositório no GitHub e termina com o commit da etapa 3 e `git push`.
