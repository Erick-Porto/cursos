## Visão do encontro

**Objetivo:** dar a cada equipe a estrutura do projeto até o Demo Day: pastas por funcionalidade, uma API própria com `json-server` acessada pelo celular, a pasta `src/api/` do `lojinha-regras` apontando para ela e o estado do domínio num contexto com `useReducer`, explicado linha a linha. No meio do caminho, a Lojinha ganha a API de verdade: o hook `useProdutos`, com páginas sob demanda e puxar para atualizar, escrito ao vivo.

**Resultado ao fim das 4h:** no celular de cada pessoa, as 5 telas do protótipo navegam por abas e pilha, no tema da equipe; a tela principal lista dados do `db.json` e atualiza ao puxar; o contexto do domínio tem guarda, reducer e testes verdes com o `jest-expo`; cada parte entrou na `main` por PR revisado. A Lojinha de demonstração rola os 194 produtos da DummyJSON; a de cada aluno fica para casa.

**Pré-requisitos:** entrega do E41 (quadro com 12 a 20 issues, `main` protegida, app com Expo Router abrindo no celular de todos); a Lojinha da `v1 Lojinha` (E40), de onde saem o tema, o kit de UI e a pasta `src/api/` que veio do `lojinha-regras` no E30; Git Bash, que vem com o Git.

**Materiais:** projetor espelhando celular e terminal, quadro com duas cores, Wi-Fi que permita conexões entre aparelhos, hotspot de reserva, a `lojinha` de demonstração na `v1 Lojinha` com a solução do `useProdutos` na branch `e42-lojinha-conectada`, o repositório de demonstração da lanchonete no estado do E41 com a solução na branch `e42-solucao`, quiz publicado.

## Bloco 1 · Arquitetura de um app (60 min)

**"O que você vai aprender" e "Três pessoas, um app, um prazo" (3 min).** Colete palpites para a pergunta sem corrigir. Esperado ao fim do bloco: pelo Wi-Fi, com o IP do computador do Bruno.

**"Por funcionalidade: a árvore da lanchonete" (5 min).** Desenhe no quadro a árvore da Lojinha e, ao lado, a da lanchonete. Peça que alguém circule, nas duas, o que muda para "observação no lanche". Esperado: na Lojinha, `telas/`, `contexts/` e `regras/`; na lanchonete, `features/carrinho/` e `features/cardapio/`. Pergunte em qual árvore o PR de duas pessoas conflita menos. Aponte `regras/` e `modelos/` fora das features: vieram prontas do `lojinha-regras`, e todas as funcionalidades usam.

**"Camadas: quem chama quem" (3 min).** Projete a animação e aponte as setas descendo: tela, hook ou contexto, `api/`, servidor; depois, a resposta subindo. Pergunte se a `api/pedidos.js` pode importar o `useCarrinho`. Esperado: não; a `api/` não conhece React.

**"Pratique" (4 min).** Equipes, 2 minutos, uma resposta por equipe. O item 4 costuma ir para `features/carrinho/`: lembre que `subtotal` é a regra do E07, que veio do `lojinha-regras` e serve a qualquer tela.

**"json-server: a API da equipe" (6 min).** Ao vivo, no repositório da lanchonete:

:::steps
1. Na raiz, crie o `db.json` do slide, com um segundo produto `"disponivel": false`.
2. Num segundo terminal, `npx json-server db.json --port 3000`; na primeira vez, responda `y`. Mostre os Endpoints. Os endereços impressos dizem `localhost`, mas o servidor escuta em todas as interfaces e atende pelo IP.
3. No navegador do computador, `http://localhost:3000/produtos` e depois `?categoriaId=lanches`.
4. Com o servidor ligado, mude o preço do X-Burger no `db.json` e recarregue: o servidor releu o arquivo.
5. Pergunte por que os ids estão entre aspas. Esperado: o json-server trata todo id como texto e converte números na primeira escrita.
:::

**"CRUD: quatro métodos, seis rotas" (5 min).** No Git Bash (no PowerShell, `curl` é outro comando), com o `db.json` aberto ao lado:

```bash
curl -X POST http://localhost:3000/pedidos -H "Content-Type: application/json" \
  -d '{"clienteNome":"Ana","status":"recebido","total":22.9,"itens":[]}'
curl -X PATCH http://localhost:3000/pedidos/ID -H "Content-Type: application/json" -d '{"status":"preparando"}'
curl -X PUT http://localhost:3000/pedidos/ID -H "Content-Type: application/json" -d '{"status":"pronto"}'
curl -X DELETE http://localhost:3000/pedidos/ID
```

Troque `ID` pelo id que o POST devolveu, como `xR31mCj8zuk`, e mostre o `db.json` mudando. Depois do PUT, pare: o pedido perdeu `clienteNome`, `total` e `itens`. Pergunte: "O cliente desistiu do pedido: DELETE ou PATCH?" Esperado: PATCH com `cancelado`; o pedido continua em "Meus pedidos" e a cozinha sabe que não precisa preparar. DELETE serve, por exemplo, para a categoria sem lançamentos do Controle de gastos. Editar o status à mão no `db.json` é como a equipe faz o papel da cozinha nos testes.

**"Do celular ao computador" e "EXPO_PUBLIC_API_URL" (6 min).** No navegador do celular espelhado, `http://localhost:3000/produtos` falha; com o IP da linha `exp://192.168...:8081` do terminal do Expo, o JSON aparece. Responda a pergunta do início do bloco. Depois, a ponte com o E04: "Lá, o Node lia o `.env` com `--env-file` e via qualquer variável. No app, quem lê é o Expo, e só as `EXPO_PUBLIC_` chegam ao celular, copiadas para dentro dele." Abra o `.gitignore` do modelo do Expo: ele ignora `.env*.local`, não o `.env`. Acrescente a linha ao vivo. Cada equipe sobe o json-server e todos abrem o JSON no próprio celular; quem não vê é atendido na pausa.

**"src/api/: o pedir do E19 com outro endereço" (2 min).** Na `lojinha` de demonstração, abra `src/api/cliente.js` e troque só a linha do `URL_BASE`. Ponha um `console.log(URL_BASE)` provisório: sem `.env`, aparece a DummyJSON. "Com `.env`, a mesma linha leva o app da equipe ao json-server; o resto do `pedir` é o do E19." Aponte no `src/api/pedidos.js` do slide que o `id` não passa por `Number()`.

**"A Lojinha em páginas" e "listarProdutos devolve a página e o total" (4 min).** No terminal, `curl "https://dummyjson.com/products?limit=20&skip=40"` e aponte `total`, `skip` e `limit` no fim. Depois `skip=180`: vêm 14, e o `limit` cai para 14. Por fim `skip=200`: `products` vazio. Pergunte: "Quantos pedidos de 20 até o fim?" Esperado: 10, o último com `skip=180`. Mude ao vivo o retorno do `listarProdutos` para `{ produtos, total }`. Lembre o `onEndReached` do E34, que paginava o catálogo local com o `paginar` do E14: "a mesma ideia, agora com o servidor".

**"useProdutos (1)" a "useProdutos (3)" (11 min).** Ao vivo, na `lojinha` de demonstração, em `src/hooks/useProdutos.js`:

:::steps
1. Escreva os estados, a ref e o retorno. Pergunte: "Por que três estados de espera?" Esperado: cada um liga uma rodinha num lugar diferente, e o puxar não pode mostrar o esqueleto.
2. Escreva `buscarPagina` com um `console.log('pedindo', pular)` provisório na primeira linha. Aponte o `pular === 0`: recomeçar substitui; continuar junta no fim. Pergunte: "Por que `setProdutos` recebe uma função?" Esperado: entre o pedido e a resposta há um `await`, e a função recebe a lista mais recente.
3. Mostre o `setEsperando`: o `set` passado como valor, como um callback do E10, desligado no `finally` do E17. "É a promessa do E34: a rodinha para mesmo quando a rede falha."
4. Escreva `recarregar`, o efeito, `atualizar` e `carregarMais`; leia em voz alta os três motivos para não carregar mais.
:::

**"Pense" (4 min).** Duplas, 2 minutos. Esperado: produtos 21 a 40 duas vezes; o `useRef` muda na hora, o estado só na próxima renderização. Demonstre: tire `buscando.current ||` do `if`, ponha `&delay=2000` no caminho do `listarProdutos`, role até o fim, suba um pouco e desça. O terminal mostra `pedindo 20` duas vezes e o aviso de chave repetida. Desfaça.

**"O Início só desenha" (5 min).** No `src/telas/Inicio.js`, apague o `carregar`, a `simularRede` e o import de `src/data/produtos.js`; chame o `useProdutos()`, mantenha o `GradeEsqueleto`, o `extraData={favoritos}` e o coração, e acrescente `onEndReached`, `desenharRodape` e o `RefreshControl`. A `EntradaAnimada` passa a criar o próprio valor, com um atraso pela posição (veja a referência da tarefa de casa): o `entradas` de 12 valores do E39 quebraria na página 2. No celular:

:::steps
1. Role até o fim: rodinha no rodapé, `pedindo 20` uma vez no terminal, grade maior.
2. Ligue o modo avião e role de novo: "Tentar de novo" no rodapé, com os 40 produtos na tela. Desligue, toque no botão: a grade continua.
3. Puxe a grade: a rodinha gira no topo, a grade não some e volta a ter 20. Apague o `console.log`.
:::

**"Erros comuns" e "Resumo" (2 min).** Leia rápido; quase todos já apareceram.

:::tip Ritmo
Se atrasar, faça só o POST e o PUT no CRUD e dê a resposta do "Pense" sem a demonstração com `delay`. O JSON no navegador do celular e o modo avião no meio da rolagem não se cortam: sem o primeiro, o laboratório trava; o segundo é o que a turma mais erra em casa.
:::

## Bloco 2 · Estado global e hooks (45 min)

**"O que você vai aprender" e "O carrinho em cinco lugares" (3 min).** Colete palpites para a pergunta do `null`. O mais comum, "porque o carrinho começa vazio", vai para o quadro: ele volta no "Pense".

**"Quatro tipos de estado" (4 min).** Cada equipe classifica 4 dados do próprio briefing. Esperado na Agenda: dia aberto em Horários (local), serviço e horário escolhidos (compartilhado), horários livres (servidor), nome do cliente (aparelho, no E43).

**"A receita (1)" a "A receita (3)" (9 min).** Ao vivo, no repositório da lanchonete:

:::steps
1. `CarrinhoContext.js` com `createContext(null)`, Provider com `useState` e `useCarrinho` **sem** guarda; Provider no `app/_layout.js` e a `quantidade` num `Text` da tela inicial.
2. Comente o Provider e recarregue: tela vermelha com um `TypeError` que fala de `null`. Pergunte se o erro diz o que falta. Esperado: não.
3. Acrescente a guarda: "useCarrinho precisa estar dentro do CarrinhoProvider". O erro agora diz o que falta e onde.
4. Descomente o Provider e desenhe o rádio do slide, com duas antenas: o Provider mais próximo vence.
:::

**"Pense" (3 min).** Individual. Esperado: com o padrão falso, o toque não faz nada e não há erro; com `null` e a guarda, o erro aparece na hora. Volte ao palpite do quadro: `[]` é o estado inicial, não o padrão.

**"useReducer" a "O Provider com dispatch" (7 min).** Copie do `lojinha-regras` para a lanchonete `src/regras/carrinho.js`, `src/regras/precos.js` e `src/modelos/erros.js` (de que o carrinho depende). Crie o `carrinhoReducer.js` e troque `useState` por `useReducer`, com o `value` no formato do E36 (`adicionar`, `remover`, `alterar`, `esvaziar`, `quantidade`, `total`); `git diff --stat` mostra que nenhuma tela mudou. "O reducer só escolhe a regra; a conta é a do E07 e do E09, já testada." Plante o bug: troque o `case 'adicionar'` por `itens.push({ ...acao.produto, qtd: 1 }); return itens;`. O `console.log` mostra o item, a tela não muda. Pergunte por quê. Esperado: mesma referência, e o React conclui que nada mudou. Desfaça.

**"Estoque: o erro fica fora do reducer" (3 min).** Na `lojinha` de demonstração, lembre o Tênis de Corrida do E32, com 1 em estoque. Pergunte: "Se o reducer chamasse `Alert.alert`, ele ainda seria puro? E dá para testar no Jest?" Esperado: não e não. Mostre que o `adicionar` do Provider chama a regra só para conferir: se ela lança, o `dispatch` nem sai. Na lanchonete, sem `estoque`, a conferência não é necessária.

**"Jest no app: o preset jest-expo" e "O reducer se testa sem React" (7 min).** Rode `npm test` antes de instalar: o npm responde `Missing script: "test"`. Instale com `npx expo install jest-expo jest -- --save-dev`, acrescente o script e o preset do slide e rode de novo: verde. "O `expect` é o do E04; o que muda é quem traduz o código do app." Depois, no teste, troque `{ ...xBurger, qtd: 2 }` por `{ ...xBurger, qtd: 3 }`: o vermelho mostra o esperado e o recebido, como no `lojinha-regras`. Desfaça.

**"Quando o Context não basta" e "Zustand, como visão" (3 min).** Só conversa. Pergunte se o cardápio deveria morar num contexto. Esperado: não; é dado do servidor, e um hook busca na tela que mostra, como o `useProdutos` do Bloco 1.

**"Dado do servidor: um hook por tela" (2 min).** É o `useProdutos` sem páginas. Insista: duas telas com `usePedidos()` têm duas listas, como o `useTarefas` do E24.

**"Erros comuns" a "No laboratório" (1 min).** Projete os passos e siga para o desafio.

**Desafio que prepara o laboratório (3 min).** Em equipe, no papel: o contexto do domínio do briefing, com nome, estado inicial, ações (`type` e dados) e o que o hook devolve. Compare com a tabela do Laboratório e copie no quadro a versão de cada equipe: é o contrato de quem vai escrever o contexto.

:::tip Ritmo
Se atrasar, mostre o teste já escrito e reduza o Zustand a um minuto. O Provider esquecido, o bug do `push` e o `npm test` verde com o `jest-expo` não se cortam: o laboratório depende dos três.
:::

## Laboratório (70 min)

**Enunciado:** os 7 passos do slide "No laboratório" da aula 83, adaptados ao briefing:

| Briefing | Pastas de `features/` | Coleções do `db.json` | Contexto do domínio | Ações do reducer |
|---|---|---|---|---|
| Cardápio e pedidos | `cardapio`, `carrinho`, `pedidos` | categorias, produtos, pedidos | `CarrinhoContext`, com as regras do `lojinha-regras` | adicionar, alterar, remover, esvaziar |
| Agenda de serviços | `catalogo`, `agenda`, `agendamentos`, `perfil` | servicos, profissionais, clientes, agendamentos | `AgendamentoContext`: o agendamento em montagem | escolherServico, escolherHorario, limpar |
| Controle de gastos | `mes`, `lancamentos`, `categorias`, `resumo` | categorias, lancamentos | `MesContext`: o mês aberto | anterior, proximo, hoje |

Na Agenda, a pasta `catalogo` evita confusão com `src/servicos/`; a rota pode seguir `/servicos`. Abas sugeridas: Cardápio, Carrinho e Meus pedidos; Serviços, Meus agendamentos e Perfil; Mês, Lançamentos, Resumo e Categorias; o resto vai na pilha. No `mesReducer`, teste a virada de ano: `proximo` de dezembro vai para janeiro. Nos Gastos, o `formatarPreco` do `lojinha-regras` serve para mostrar os centavos: `formatarPreco(valorCentavos / 100)`, ou o `paraReais` do E05.

**Organização:** equipes de 2 ou 3, cada parte numa issue e numa branch `feature/<issue>-<nome>`:

- **Pessoa A**, navegação e tema: `src/theme/` e `src/components/ui/` da Lojinha com as cores da equipe, guarda no `useTema`, fontes, abas, pilha, rotas finas e as 5 telas como esqueleto. Abre o primeiro PR.
- **Pessoa B**, API: `db.json` com 8 a 12 registros realistas, script `api`, `.env.example`, `.env` no `.gitignore`, `src/api/` com o `cliente.js` do `lojinha-regras` (e o `src/modelos/erros.js`) e o hook da tela principal, com puxar para atualizar.
- **Pessoa C**, contexto: regras copiadas, reducer, testes com o `jest-expo`, Provider e hook com guarda. Em dupla, B e C dividem esta parte.

O PR de A entra primeiro; B e C trazem a `main` para a sua branch antes de abrir o deles. O conflito esperado é no `app/_layout.js` e no `package.json`: resolva o primeiro com a turma.

**Marcos:** 2:30, JSON no navegador do celular de todos; 2:50, navegação na `main`; 3:05, tela principal com dados do `db.json`; 3:20, contexto com testes na `main`; 3:30, `feat: E42 arquitetura e estado global` e entrega.

`src/api/cliente.js`, o do `lojinha-regras` (E19) com o endereço do `.env` e as mensagens da lanchonete. Ele importa `src/modelos/erros.js`, copiado junto:

```javascript
import { ErroDeNegocio } from '../modelos/erros.js';

export const URL_BASE = process.env.EXPO_PUBLIC_API_URL ?? 'https://dummyjson.com';

export class ApiError extends ErroDeNegocio {
  constructor(status) {
    super(status === 404 ? 'Não encontramos esse item.' : 'O servidor da lanchonete não respondeu. Tente de novo.', 'API_' + status);
    this.name = 'ApiError';
    this.status = status;
  }
}

export async function pedir(caminho, opcoes = {}) {
  let resposta;
  try {
    resposta = await fetch(URL_BASE + caminho, {
      ...opcoes,
      headers: { 'Content-Type': 'application/json', ...opcoes.headers },
    });
  } catch (erro) {
```

```javascript
import { adicionarItem, alterarQuantidade, removerItem } from '../../regras/carrinho';

const QTD_MAXIMA = 10; // briefing: de 1 a 10 por produto

export function carrinhoReducer(itens, acao) {
  switch (acao.type) {
    case 'adicionar': {
      if (!acao.produto.disponivel) return itens; // indisponível não entra
      const atual = itens.find((i) => i.id === acao.produto.id);
      if (atual && atual.qtd >= QTD_MAXIMA) return itens;
      return adicionarItem(itens, acao.produto);
    }
    case 'alterar':
      return alterarQuantidade(itens, acao.id, Math.min(acao.qtd, QTD_MAXIMA));
    case 'remover':
      return removerItem(itens, acao.id);
    case 'esvaziar':
      return [];
    default:
      throw new Error('Ação desconhecida: ' + acao.type);
  }
}
```

`src/hooks/useProdutos.js` completo:

```javascript
import { useEffect, useRef, useState } from 'react';
import { listarProdutos } from '../api/produtos';
import { ErroDeNegocio } from '../modelos/erros';

const LIMITE = 20;

export function useProdutos() {
  const [produtos, setProdutos] = useState([]);
  const [total, setTotal] = useState(0);
  const [carregando, setCarregando] = useState(true); // esqueleto
  const [atualizando, setAtualizando] = useState(false); // rodinha do topo
  const [carregandoMais, setCarregandoMais] = useState(false); // rodinha do rodapé
  const [erro, setErro] = useState(null);
  const buscando = useRef(false); // trava: um pedido por vez

  async function buscarPagina(pular, setEsperando) {
    buscando.current = true;
    setEsperando(true); // liga a rodinha certa
    try {
      const pagina = await listarProdutos({ limite: LIMITE, pular });
      setProdutos((atuais) => (pular === 0 ? pagina.produtos : [...atuais, ...pagina.produtos]));
      setTotal(pagina.total);
      setErro(null);
    } catch (e) {
      if (!(e instanceof ErroDeNegocio)) throw e; // bug: não esconda (E39)
      setErro(e.message);
    } finally {
      buscando.current = false;
      setEsperando(false); // a rodinha para, mesmo quando a rede falha
    }
  }

  function recarregar() {
    buscarPagina(0, setCarregando);
  }
  useEffect(() => { recarregar(); }, []);

  function atualizar() {
    if (buscando.current) return;
    buscarPagina(0, setAtualizando);
  }

  function carregarMais() {
    if (buscando.current || carregando || produtos.length >= total) return;
    buscarPagina(produtos.length, setCarregandoMais);
  }

  const temMais = produtos.length < total;
  return { produtos, carregando, atualizando, carregandoMais, erro, temMais,
    recarregar, atualizar, carregarMais };
}
```

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| O JSON abre no computador, não no navegador do celular | Redes diferentes, Wi-Fi que isola aparelhos ou firewall barrando o Node | Mesmo Wi-Fi; no Windows, liberar o Node em redes privadas; em último caso, hotspot |

## Plano B

- **Rede que isola os aparelhos:** hotspot do seu celular, uma equipe por vez. Sem hotspot, o app roda no navegador do computador (tecla `w`, com `npx expo install react-dom react-native-web @expo/metro-runtime`), onde `http://localhost:3000` funciona, ou no emulador Android, que enxerga o computador em `http://10.0.2.2:3000`.
- **Firewall que você não pode liberar:** navegador do computador ou emulador; o teste no celular fica para casa.
- **Sem internet para o `npx`:** a máquina que já baixou o json-server serve a equipe pelo IP dela. A demonstração do `useProdutos` usa a branch `e42-lojinha-conectada` gravada antes, ou um `listarProdutos` provisório que fatia uma lista local de 194 itens com `slice(pular, pular + limite)` e devolve `{ produtos, total }` depois de um `setTimeout`.
- **Equipe incompleta:** quem veio faz navegação e API; o contexto vira tarefa de casa, com o desafio do quadro como contrato.
- **Sem projetor:** árvore e camadas no quadro; demonstrações do json-server em rodízio, em volta do seu computador.
