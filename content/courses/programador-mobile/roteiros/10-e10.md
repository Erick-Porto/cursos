## Visão do encontro

**Objetivo:** ensinar o código a escolher um caminho e construir, com isso, a etapa 7 do Racha-conta. A turma aprende `if` e `else`, o `null` como "não deu", os operadores `&&`, `||` e `!`, o `Number.isInteger`, o `else if`, o retorno antecipado e o ternário. Nos passos juntos, ela escreve `lerPessoas` com os testes e faz o `racha.js` aceitar as pessoas no comando, com um aviso quando elas não valem. Na Sua vez, o `lerValor` passa a devolver `null` e o script ganha o aviso do valor, com `else if`.

**Como a aula funciona:** cada conceito vem em três slides, como na aula 3 e no E04. A seção (título e gancho) é a hora da conversa: leia o gancho, ouça duas ou três respostas e explique com a analogia indicada abaixo. O slide seguinte é a âncora, o que o aluno lê para revisar. Depois vêm os casos "na prática" e, para cada decisão, uma tabela caso por caso (entrada, caminho, resultado): monte a tabela no quadro com a turma antes de mostrar a do slide. Os slides **Projeto 1 · Passo K** são feitos junto com você, e só se segue quando o "Pronto quando" aparece na tela de todos. As duas **Sua vez** são feitas sozinho, sem a solução no slide.

**Resultado ao fim das 4h:** no `racha-conta` de cada aluno, `src/regras/conta.js` com `lerPessoas` (um inteiro de 1 a 50, ou `null`) e o `lerValor` devolvendo `null` para `''`, `'abc'`, `'0'`, `'0,00'`, `'-10'` e `'187,505'`; `conta.test.js` com 33 testes verdes; `racha.js` lendo o valor (`process.argv[2]`) e as pessoas (`process.argv[3]`), com `if` / `else if` / `else`: `npm run racha "R$ 100,00" 3` mostra `Pessoas na mesa: 3` e `Por pessoa: R$ 36,66`, `npm run racha abc` mostra só o aviso do valor e `npm run racha 100 0` só o aviso das pessoas. Commit `Projeto 1: etapa 7, entrada inválida` e `git push`. É a etapa 7 do Projeto 1.

**Pré-requisitos:** E04 a E09. A turma já sabe: `package.json` e `npm run racha`, Git e `git push`, tipos, `let` e `const`, centavos com `Math.round`, `Math.floor` e `%`, template string, funções com parâmetro, `return`, `export` e `import`, Jest com `test`, `test.each`, `toBe`, vermelho e verde, os métodos de texto do E09 (`trim`, `replace`, `split`), `Number`, `NaN` e `Number.isNaN`, e o `if` sem `else` (aula 3 e `if (process.argv[2])` do E09). Ela **não** viu: `else`, `else if`, `&&`, `||`, `!`, `null`, ternário, `Number.isInteger` nem o `.length` de um texto (ele é explicado hoje, no `else if`). Laços ficam para o E11, e o `switch`, para o E17.

**Materiais:** projetor com o VS Code em fonte grande e o terminal integrado (PowerShell), quadro com canetas de duas cores, o seu `racha-conta` de demonstração no fim da etapa 6, a página do Projeto 1 (página do curso, em **Projetos**) e o quiz publicado.

## Projeto: sua vez (30 min)

**Enunciado:** os slides "Projeto 1 · Sua vez: o null do lerValor" e "Projeto 1 · Sua vez: o aviso do valor". Primeiro, os testes dos seis textos recusados, num `test.each` como o dos recusados do `lerPessoas`, e o vermelho. Depois, o `lerValor` com retorno antecipado até ficar verde, com 33 testes. Por fim, o aviso do valor no `racha.js`, antes do das pessoas, que vira `else if`.

**Organização:** individual, cada um no próprio `racha-conta`, sem olhar a tela do vizinho nos primeiros 15 minutos. Depois disso, quem travou pode pedir ajuda a um colega, que explica sem digitar por ele.

**Marcos:** 3:12, os seis testes novos vermelhos (`Tests: 6 failed, 27 passed, 33 total`); 3:25, `lerValor` verde, com 33; 3:35, o aviso do valor no script e o commit.

**O que observar:**

- `if (partes[1].length > 2)` sem conferir o tamanho da lista: `TypeError: Cannot read properties of undefined (reading 'length')` em cinco testes, inclusive no aceito `lerValor("187")`. Pergunta: "e se o texto não tem ponto, quantas partes o `split` devolve?"
- As casas conferidas multiplicando por 100: `72.9 * 100` dá `7290.000000000001`, o problema do E06. Elas se conferem pelo texto, com o `split`
- `reais < 0` no lugar de `reais <= 0`: ficam vermelhos o `''`, o `'0'` e o `'0,00'`, com `Received: 0`
- `Number.isNaN(limpo)`, no texto: dá sempre `false`, porque o `Number.isNaN` não converte. Fica vermelho o `'abc'`, com `Received: NaN`. Pergunte "o que está dentro do `limpo`, um texto ou um número?"
- `reais === NaN`: nunca é `true`. Lembre a retomada da abertura
- No script, dois `if` separados no lugar do `else if`: com `abc`, aparece o aviso **e** um recibo com `R$ 0,00`. "Quantos caminhos devem rodar?"
- As pessoas conferidas antes do valor: `npm run racha abc 0` mostra o aviso das pessoas. O slide pede o do valor
- Valor negativo no comando (`npm run racha -10`): o npm avisa `npm warn Unknown cli config "--10"` e não passa o `-10` ao script. O negativo se testa no Jest

Pergunta para quem travou: "qual é o primeiro problema que o texto pode ter? Escreva um `if` só para ele, com `return null`, e rode os testes. Quantos ficaram verdes?"

:::example Solução de referência
Os testes, no `conta.test.js`, logo depois do `test.each` dos aceitos do `lerValor`:

```javascript
test.each(['', 'abc', '0', '0,00', '-10', '187,505'])('lerValor("%s") dá null', (texto) => {
  expect(lerValor(texto)).toBe(null);
});
```

O vermelho, antes de mudar a função (trecho; um bloco `●` para cada um, com `Received: 0`, `NaN`, `0`, `0`, `-1000` e `18751`):

```plaintext
  ● lerValor("187,505") dá null

    expect(received).toBe(expected) // Object.is equality

    Expected: null
    Received: 18751

Test Suites: 1 failed, 1 total
Tests:       6 failed, 27 passed, 33 total
```

A função, no `conta.js`:

```javascript
export function lerValor(texto) {
  let limpo = texto.trim();
  limpo = limpo.replace('R$', '');
  limpo = limpo.trim();
  limpo = limpo.replace(',', '.');

  const partes = limpo.split('.');
  if (partes.length > 1 && partes[1].length > 2) {
    return null;
  }
  const reais = Number(limpo);
  if (Number.isNaN(reais) || reais <= 0) {
    return null;
  }
  return paraCentavos(reais);
}
```

| Texto | Onde para | Devolve |
|---|---|---|
| `'187,505'` | no primeiro `if`: `'505'` tem 3 caracteres | `null` |
| `'abc'` | no segundo `if`: `Number.isNaN(NaN)` é `true` | `null` |
| `''`, `'0'`, `'0,00'` | no segundo `if`: `0 <= 0` | `null` |
| `'-10'` | no segundo `if`: `-10 <= 0` | `null` |
| `'R$ 187,50'` | passa pelos dois | `18750` |

Outras soluções valem, se os 33 testes passam: três `if` separados (um para as casas, um para o `NaN`, um para o zero e o negativo) estão certos.

`src/scripts/racha.js` no fim da etapa 7:

```javascript
import fs from 'node:fs';
import pc from 'picocolors';
import {
  paraCentavos,
  calcularGorjeta,
  formatarReais,
  lerValor,
  lerPessoas,
} from '../regras/conta.js';

const texto = fs.readFileSync('src/data/conta.json', 'utf-8');
const conta = JSON.parse(texto);
const subtotal = conta.itens.reduce((total, item) => total + item.preco * item.quantidade, 0);
const unidades = conta.itens.reduce((total, item) => total + item.quantidade, 0);
const caros = conta.itens.filter((item) => item.preco > 50);

let subtotalCentavos = paraCentavos(subtotal);
if (process.argv[2]) {
  subtotalCentavos = lerValor(process.argv[2]);
}
let pessoas = conta.pessoas;
if (process.argv[3]) {
  pessoas = lerPessoas(process.argv[3]);
}

if (subtotalCentavos === null) {
  console.log(`Valor inválido: "${process.argv[2]}". Digite como 187,50 ou "R$ 187,50".`);
} else if (pessoas === null) {
  console.log(`Número de pessoas inválido: "${process.argv[3]}". Digite um número inteiro de 1 a 50.`);
} else {
  const gorjetaCentavos = calcularGorjeta(subtotalCentavos, conta.gorjeta);
  const totalCentavos = subtotalCentavos + gorjetaCentavos;
  const porPessoa = Math.floor(totalCentavos / pessoas);
  const sobra = totalCentavos % pessoas;

  console.log(pc.bold('Racha-conta:'), conta.restaurante);
  console.log('Pessoas na mesa:', pessoas);
  console.log('Itens na conta:', conta.itens.length);
  console.table(conta.itens);
  console.log('Unidades pedidas:', unidades);
  console.log('Itens acima de R$ 50:', caros.length);
  console.log(`Subtotal: ${formatarReais(subtotalCentavos)}`);
  console.log(`Gorjeta (${conta.gorjeta}%): ${formatarReais(gorjetaCentavos)}`);
  console.log(`Total: ${formatarReais(totalCentavos)}`);
  console.log(`Por pessoa: ${formatarReais(porPessoa)}`);
  console.log(`Centavos que sobram: ${sobra}`);
}
```

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| `SyntaxError: The requested module '../regras/conta.js' does not provide an export named 'lerPessoas'` | faltou o `export` antes da `function lerPessoas` | `export function lerPessoas(texto)` |
| `ReferenceError: lerPessoas is not defined`, só com as pessoas no comando | o nome não entrou no `import` do `racha.js` | `lerPessoas,` dentro das chaves do `import` |
| `Expected: null` e `Received: undefined` nos recusados | faltou o `return null` no fim da função | `return null;` depois do `if` |
| `TypeError: Cannot read properties of undefined (reading 'length')` no `lerValor("187")` | `partes[1].length` sem conferir se existe a segunda parte | `if (partes.length > 1 && partes[1].length > 2)` |
| `TypeError: Cannot read properties of undefined (reading 'trim')` com `npm run racha` sem nada | `lerPessoas(process.argv[3])` fora do `if` | a linha vai dentro do `if (process.argv[3]) { ... }` |
| `SyntaxError: Unexpected end of input` | faltou fechar uma chave, quase sempre a do `else` | Formatar Documento: o recuo mostra onde a chave falta |
| `SyntaxError: Unexpected token '}'` ou `Unexpected token 'else'` | uma `}` a mais, ou um comando entre a `}` do `if` e o `else` | conferir as chaves de cada `if`; nada entre a `}` e o `else` |
| `Pessoas na mesa: null`, `Por pessoa: R$ Infinity` e nenhum aviso | `pessoas = null`, com um `=` só, no `if` ou no `else if` | `===` |
| `Pessoas na mesa: 3` com `Por pessoa: R$ 27,50` | `conta.pessoas` esquecido no `porPessoa` e na `sobra` | trocar pelos `pessoas` dentro do `else` |
| Com `abc`, o aviso e um recibo de `R$ 0,00` | dois `if` separados no lugar de `if` / `else if` / `else` | o das pessoas vira `else if` |
| `Valor inválido: "187 50"` | no PowerShell, vírgula sem aspas parte o valor | `npm run racha "187,50"` |
| `npm warn Unknown cli config "--10"` | o npm tomou o `-10` como uma opção dele | o negativo se testa no Jest, não no comando |
