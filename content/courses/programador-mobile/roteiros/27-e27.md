## Visão do encontro

**Objetivo:** fechar o Projeto 4. A turma aprende o `useEffect` com `[]` ("depois de desenhar a tela, faça isto"), põe o `fetch` do E22 dentro do efeito, guarda as receitas da DummyJSON no estado e mostra o aviso de carregando. Na Sua vez 1, cada um faz o app avisar quando a internet ou a API falha, com o `try`/`catch`/`finally` do E20 e o `resposta.ok` do E22. Na Sua vez 2, o README com print e a entrega na plataforma. Não há laboratório à parte: os passos do projeto são a prática do dia.

**Como a aula funciona:** cada conceito vem em três slides, como desde a aula 3. A seção (título e gancho) é a hora da conversa: leia o gancho, ouça duas ou três respostas e explique com a analogia indicada abaixo. O slide seguinte é a âncora, o que o aluno lê para revisar. Depois do conceito vem um slide **Projeto 4 · Passo K**: a turma faz junto com você e só segue quando o "Pronto quando" aparece na tela de todos. No fim, as duas **Sua vez** são feitas sozinho, sem a solução no slide. Depois de cada tema há um slide **Exercícios** com 3 a 5 exercícios e as respostas. Em aula, faça o primeiro em voz alta com a turma; os outros ficam para a revisão em casa.

**Resultado ao fim das 4h:** cada aluno tem o `livro-de-receitas` com o `src/App.jsx` da solução de referência (fim deste roteiro): os estados `receitas`, `carregando`, `erro`, `busca` e `favoritas`; o `useEffect` com `[]` e a `carregarReceitas` com `try`/`catch`/`finally` e o `ok` conferido; o `if` do `conteudo` com quatro caminhos (carregando, erro, lista vazia, grade). Ao abrir, "Carregando receitas..." e depois 30 cartões em inglês; `chicken` mostra 5; sem internet, "Não foi possível carregar as receitas.". O `CartaoReceita` e o `BotaoFavorito` não mudam desde o E26. O README tem o texto do aluno, o print em `docs/tela.png` e o nome. Commit `Projeto 4: etapa 4, receitas da API e README`, `git push` e o link do repositório na página do Projeto 4. O prazo é o início do E29; o E28 é revisão e Prova 2.

**Pré-requisitos:** do E24 ao E26, componente, JSX, Vite, props, `map` com `key`, `useState`, eventos, campo controlado e função como prop; o `livro-de-receitas` no fim da etapa 3 (busca com `ListaVazia`, favoritas que marcam e desmarcam, total no `Cabecalho`). Do JavaScript: `fetch`, `resposta.json()`, `resposta.ok` e `try`/`catch` com `await` (E22), `async`/`await` e Promise (E21), `throw`, `Error` e `finally` (E20), `if`/`else if` (E10). Hoje esses são lembretes de um minuto, não aulas. **Não** fale de `StrictMode` nem de limpeza de efeito: o kit não usa `StrictMode`, e o efeito roda uma vez também no `npm run dev`.

**Materiais:** projetor com o VS Code e o Chrome lado a lado, DevTools aberto nas abas **Console** e **Rede**, fonte grande; Wi-Fi que deixe chegar a `dummyjson.com`; o seu `livro-de-receitas` no fim da etapa 3, para as demonstrações; um pendrive com o `recipes.json` do Plano B; a página do Projeto 4 e o guia de correção abertos; quiz publicado.

**Seção "useEffect" (4 min).** Leia o gancho: "o que você faz logo depois de abrir a porta de casa, à noite?". Esperado: acender a luz, largar a mochila, tirar o sapato. Depois de "O efeito, desenho por desenho", no slide **Exercícios: useEffect**, faça o 1 em voz alta, com a turma dizendo a ordem antes de você ler a resposta: o erro que costuma aparecer é pôr o `aquecimento` antes do `desenhou`, ou repeti-lo a cada clique.

**"useEffect: depois de desenhar a tela" e "O useEffect em português" (6 min).** Aponte as duas partes do `useEffect(...)`: a função (o que fazer) e o `[]` (quando fazer). ## Projeto: sua vez (45 min)

### Sua vez 1: quando a API falha (30 min)

**Enunciado:** o slide "Projeto 4 · Sua vez 1". Um estado `erro` começando `false`; o `try`/`catch`/`finally` no `carregarReceitas`, com o `catch` ligando o `erro` e o `finally` desligando o `carregando`; o `ok` conferido; o caminho da `MensagemErro` logo depois do carregando.

**Organização:** individual, sem olhar a tela do vizinho nos primeiros 15 minutos. Depois, quem travou pede ajuda a um colega, que explica sem digitar por ele.

**Marcos:** 3:00, o estado `erro` e o `try`/`catch`/`finally` escritos; 3:10, sem internet aparece a `MensagemErro`; 3:20, o `/recipes/9999` também mostra a mensagem, e o endereço voltou ao normal.

**O que observar:** o `setCarregando(false)` deixado dentro do `try` (sem internet, preso em "Carregando receitas..."); o caminho do `erro` depois da lista vazia (sem internet, "Nenhuma receita por aqui." no lugar do erro); `useState(null)` ou `useState('')` no `erro` (funciona, mas peça o `false` do enunciado); `catch (erro)`, com o mesmo nome do estado (funciona, mas confunde quem lê: peça `falha`, como na dica); o endereço `/recipes/9999` esquecido no código (com internet, a mensagem de erro não sai). Pergunta para quem travou: "o que roda sempre, com erro ou sem erro?" e "qual caminho do `if` o React testa primeiro?".

:::example Solução de referência
`src/App.jsx` no fim da etapa 4 (o comentário das etapas do kit continua no topo; os componentes não mudam desde o E26):

```jsx
import { useEffect, useState } from 'react'
import Cabecalho from './components/Cabecalho.jsx'
import CampoBusca from './components/CampoBusca.jsx'
import Carregando from './components/Carregando.jsx'
import ListaVazia from './components/ListaVazia.jsx'
import MensagemErro from './components/MensagemErro.jsx'
import Rodape from './components/Rodape.jsx'
import CartaoReceita from './components/CartaoReceita.jsx'

function App() {
  const [receitas, setReceitas] = useState([])
  const [carregando, setCarregando] = useState(true)
  const [erro, setErro] = useState(false)
  const [busca, setBusca] = useState('')
  const [favoritas, setFavoritas] = useState([])

  useEffect(() => {
    async function carregarReceitas() {
      try {
        const resposta = await fetch('https://dummyjson.com/recipes')
        if (!resposta.ok) {
          throw new Error('A API respondeu ' + resposta.status)
        }
        const dados = await resposta.json()
        setReceitas(dados.recipes)
      } catch (falha) {
        console.log(falha)
        setErro(true)
      } finally {
        setCarregando(false)
      }
    }
    carregarReceitas()
  }, [])

  function alternarFavorita(id) {
    if (favoritas.includes(id)) {
      setFavoritas(favoritas.filter((item) => item !== id))
    } else {
      setFavoritas([...favoritas, id])
    }
  }

  const visiveis = receitas.filter((receita) =>
    receita.name.toLowerCase().includes(busca.toLowerCase()),
  )

  let conteudo
  if (carregando) {
    conteudo = <Carregando />
  } else if (erro) {
    conteudo = <MensagemErro texto="Não foi possível carregar as receitas." />
  } else if (visiveis.length === 0) {
    conteudo = <ListaVazia busca={busca} />
  } else {
    conteudo = (
      <div className="grade">
        {visiveis.map((receita) => (
          <CartaoReceita
            key={receita.id}
            nome={receita.name}
            foto={receita.image}
            cozinha={receita.cuisine}
            minutos={receita.prepTimeMinutes + receita.cookTimeMinutes}
            dificuldade={receita.difficulty}
            porcoes={receita.servings}
            nota={receita.rating}
            favorita={favoritas.includes(receita.id)}
            aoFavoritar={() => alternarFavorita(receita.id)}
          />
        ))}
      </div>
    )
  }

  return (
    <>
      <Cabecalho totalFavoritas={favoritas.length} />
      <main className="conteudo">
        <CampoBusca valor={busca} aoMudar={setBusca} />
        {conteudo}
      </main>
      <Rodape autor="Ana Souza" />
    </>
  )
}

export default App
```

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| Nada no Console e nenhum pedido na aba Rede (passo 1) | a linha `carregarReceitas()` esquecida, ou o Console filtrado | Ler o efeito em voz alta: "criei a função; quem chama?" |
| Tela do Vite: ``[PARSE_ERROR] `await` is only allowed within async functions`` | `function carregarReceitas()` sem o `async` | O `async` antes do `function` |
| Tela branca e `receitas.filter is not a function` | `setReceitas(dados)` | `setReceitas(dados.recipes)`; abrir o JSON no navegador e achar o `recipes` |
| Tela branca e `useEffect is not defined` | o import ficou só com o `useState` | `import { useEffect, useState } from 'react'` |
| A aba Rede enche de pedidos (17 em poucos segundos, no teste) | o efeito sem o `[]` | `}, [])` no fim do efeito |
| Console: `useEffect must not return anything besides a function, which is used for clean-up.` | `useEffect(async () => ...)` | A função `async` dentro do efeito, chamada logo abaixo |
| "Nenhuma receita por aqui." para sempre, com internet | o `console.log(dados)` continua no lugar do `setReceitas` | Passo 2, item 3 |
| "Carregando receitas..." para sempre, com internet | faltou o `setCarregando(false)` | Passo 3, item 3 |
| "Carregando receitas..." para sempre, sem internet | o `setCarregando(false)` dentro do `try` | No `finally` |
| Sem internet, "Nenhuma receita por aqui." no lugar do erro | o caminho do `erro` depois do da lista vazia | O `else if (erro)` logo depois do carregando |
| Tela branca e `Cannot read properties of undefined (reading 'filter')` com o `/recipes/9999` | faltou conferir o `ok`: o 404 virou `dados` sem `recipes` | `if (!resposta.ok)` com o `throw`, antes do `json()` |
| A mensagem de erro aparece com internet; Console: `Error: A API respondeu 404` | o endereço `/recipes/9999` do teste ficou no código | Voltar para `https://dummyjson.com/recipes` |
| `frango` não acha nada | a API é em inglês | `chicken`, `pasta`, `salad` |
| As fotos não aparecem | sem internet: as fotos também vêm da DummyJSON | O texto do `alt` aparece no lugar; é o esperado |
| Duas linhas no Console e dois pedidos na aba Rede | o `main.jsx` foi trocado por outro (o modelo do Vite usa `StrictMode`, que roda o efeito duas vezes no `npm run dev`) | Devolver o `main.jsx` do kit; não entre no assunto com a turma |
| O Chrome não aceita código colado no Console | proteção do Chrome contra golpes | Digitar a frase que ele pede, uma vez |
