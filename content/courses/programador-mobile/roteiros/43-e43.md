## Visão do encontro

**Objetivo:** fazer, em aula, a etapa 3 do Projeto 7: o app de cada equipe passa a guardar os dados. Quem cuida dos dados escreve o **quadro de avisos** da equipe (`createContext`, o Provider com a lista num `useState` e as funções que mudam a lista), pendura o Provider em volta da `Pilha` no `app/_layout.js`, liga a própria tela com `useContext` e, depois, põe a **gaveta do celular**: dois `useEffect` com o AsyncStorage, um que lê ao abrir e outro que guarda quando a lista muda, com a trava `carregado`. Tudo entra na `main` pela branch `dados-no-celular`. Na vez da equipe, cada pessoa liga a sua tela ao quadro, numa branch `dados-` com o nome da tela, por pull request revisado.

**Como a aula funciona:** cada conceito vem em três slides. A seção (título e gancho) é a hora da conversa: leia o gancho, ouça duas ou três respostas e explique com a analogia indicada abaixo. A âncora é o que o aluno lê para revisar. Depois do conceito vem um slide **Projeto 7 · Passo K**. Hoje os passos são de **quem cuida dos dados**: essa pessoa digita, e a equipe acompanha na tela dela, como revisora (lê o slide "em português" em voz alta e confere cada linha digitada). Você faz o mesmo no projetor, no repositório de demonstração do Gasto Certo. A **Sua vez** é de cada pessoa, na própria tela, sem a solução no slide.

**Resultado ao fim das 4h:** na `main` de cada equipe:

- `src/data/GastosContext.js` (ou `AgendaContext.js`, ou `CarrinhoContext.js`): `createContext(null)`, o Provider com a lista num `useState` que começa nos dados de exemplo do kit, `carregado` em `false`, a `CHAVE` (`'gastos.lancamentos'`, `'agenda.agendamentos'` ou `'cardapio.carrinho'`), o efeito com `[]` que lê com `getItem` e `JSON.parse`, o efeito com `[lista, carregado]` que guarda com `setItem` e `JSON.stringify` só com a trava aberta, e as funções `adicionar` e `remover` (mais `esvaziar`, no Cardápio)
- `app/_layout.js` com o Provider em volta da `<Pilha />`, dentro do `TemaProvider`
- cada tela que usa a lista lendo o quadro com `useContext`, no lugar dos dados de exemplo, e chamando `adicionar`, `remover` ou `esvaziar` onde muda a lista
- um pull request `dados-no-celular` e um por tela, cada um revisado por outra pessoa da equipe

No Gasto Certo: salvar Saída, R$ 12,50, Mercado, "Pão" leva a Início de R$ 1727,10 para R$ 1714,60 e põe "Pão" no topo da Lançamentos; a lixeira apaga; fechou o app de verdade e abriu, está tudo como ficou; apagando os 7, a Lançamentos mostra "Nenhum lançamento" e a Início, R$ 0,00 três vezes.

**Pré-requisitos:** o placar do `useState` (E26); o `useEffect` com `[]` e a função `async` dentro do efeito (E27); a `prop` `children` (E29); o `Date.now()` como crachá e o `filter` com `!==` para remover (E31); o quadro de avisos pronto, `useTema()` (E34) e `useCasas()` (E36 a E38); spread e "sem rasurar o original" (E15); desestruturação (E13); `localStorage`, Promise e `async`/`await` (E21); JSON (aula 3); branch, pull request, revisão e `git pull` depois do merge (E42). **Novo hoje:** escrever um contexto (`createContext`, `.Provider` com `value`, `useContext` direto na tela, sem hook próprio); o AsyncStorage; a lista de dependências com nomes dentro (o E27 avisou que ela ficava sempre vazia); a trava.

**Materiais:** o repositório de demonstração do Gasto Certo no fim do E42 (o estado de `privado/projetos/projeto-7/etapas/e42/`), aberto no VS Code com fonte grande e o `npx expo start` rodando; o seu celular espelhado no projetor; uma segunda conta do GitHub (ou um aluno voluntário) para aprovar o pull request da demonstração; a página do Projeto 7 (página do curso, **Projetos**); quiz publicado. A solução completa está em `privado/projetos/projeto-7/` (`etapas/e43a` é o fim do passo 2; `etapas/e43`, o fim da etapa; `contextos/` tem os quadros da Agenda e do Cardápio).

```jsx
// O quadro de avisos dos agendamentos: todas as telas leem a mesma lista.
// O AgendaProvider fica em app/_layout.js, em volta de tudo, e guarda a lista na gaveta do celular
// (AsyncStorage): ela continua lá depois de fechar o app.
// Em qualquer tela:
//   const { agendamentos, adicionar, remover } = useContext(AgendaContext);
import { createContext, useEffect, useState } from 'react';
import AsyncStorage from '@react-native-async-storage/async-storage';
import { agendamentosDeExemplo } from './agenda';

export const AgendaContext = createContext(null);

const CHAVE = 'agenda.agendamentos';

export function AgendaProvider({ children }) {
  const [agendamentos, setAgendamentos] = useState(agendamentosDeExemplo);
  const [carregado, setCarregado] = useState(false);

  // ao abrir o app: tira da gaveta o que estava guardado
  useEffect(() => {
    async function carregar() {
      const texto = await AsyncStorage.getItem(CHAVE);
      if (texto !== null) {
        setAgendamentos(JSON.parse(texto));
      }
      setCarregado(true);
    }
    carregar();
  }, []);

  // a lista mudou: guarda de novo na gaveta
  useEffect(() => {
    if (carregado) {
      AsyncStorage.setItem(CHAVE, JSON.stringify(agendamentos));
    }
  }, [agendamentos, carregado]);

  function adicionar(novo) {
    setAgendamentos([{ ...novo, id: Date.now() }, ...agendamentos]);
  }

  function remover(id) {
    setAgendamentos(agendamentos.filter((item) => item.id !== id));
  }

  const valor = { agendamentos, adicionar, remover };
  return <AgendaContext.Provider value={valor}>{children}</AgendaContext.Provider>;
}
```

```jsx
// O quadro de avisos do carrinho: todas as telas leem os mesmos itens.
// O CarrinhoProvider fica em app/_layout.js, em volta de tudo, e guarda os itens na gaveta do celular
// (AsyncStorage): eles continuam lá depois de fechar o app.
// Em qualquer tela:
//   const { itens, adicionar, remover, esvaziar } = useContext(CarrinhoContext);
import { createContext, useEffect, useState } from 'react';
import AsyncStorage from '@react-native-async-storage/async-storage';
import { carrinhoDeExemplo } from './cardapio';

export const CarrinhoContext = createContext(null);

const CHAVE = 'cardapio.carrinho';

export function CarrinhoProvider({ children }) {
  const [itens, setItens] = useState(carrinhoDeExemplo);
  const [carregado, setCarregado] = useState(false);

  // ao abrir o app: tira da gaveta o que estava guardado
  useEffect(() => {
    async function carregar() {
      const texto = await AsyncStorage.getItem(CHAVE);
      if (texto !== null) {
        setItens(JSON.parse(texto));
      }
      setCarregado(true);
    }
    carregar();
  }, []);

  // os itens mudaram: guarda de novo na gaveta
  useEffect(() => {
    if (carregado) {
      AsyncStorage.setItem(CHAVE, JSON.stringify(itens));
    }
  }, [itens, carregado]);

  function adicionar(novo) {
    setItens([{ ...novo, id: Date.now() }, ...itens]);
  }

  function remover(id) {
    setItens(itens.filter((item) => item.id !== id));
  }

  function esvaziar() {
    setItens([]);
  }

  const valor = { itens, adicionar, remover, esvaziar };
  return <CarrinhoContext.Provider value={valor}>{children}</CarrinhoContext.Provider>;
}
```

Circule procurando: `createContext` fora do import (`Property 'createContext' doesn't exist`, só quando o arquivo for importado, no passo 2); o import `'./gastos'` com `@/data/gastos` (funciona também, deixe); `[...lancamentos, novo]` no lugar do molde (o novo vai para o fim: "Pão" apareceria embaixo); `===` no `filter` do `remover` (sobraria só o apagado).

O `app/_layout.js` completo do fim do passo 2 (os comentários do topo trocados pela linha do `GastosProvider`):

```jsx
// Layout raiz: o que envolve todas as telas do app.
//   TemaProvider   o tema claro ou escuro, para todas as telas (o mesmo do Projeto 6)
//   GastosProvider o quadro de avisos dos lançamentos, guardado no celular (E43)
//   Stack          a pilha de telas: a tela nova entra por cima, voltar tira a de cima
import { Stack } from 'expo-router';
import { StatusBar } from 'expo-status-bar';
import { GastosProvider } from '@/data/GastosContext';
import { opcoesDaPilha, TemaProvider, useTema } from '@/theme';

// A pilha fica num componente separado porque precisa do useTema(),
// que só funciona dentro do TemaProvider.
function Pilha() {
  const { cores, escuro } = useTema();
  return (
    <>
      <StatusBar style={escuro ? 'light' : 'dark'} />
      <Stack screenOptions={opcoesDaPilha(cores)}>
        <Stack.Screen name="(abas)" options={{ headerShown: false }} />
      </Stack>
    </>
  );
}

export default function LayoutRaiz() {
  return (
    <TemaProvider>
      <GastosProvider>
        <Pilha />
      </GastosProvider>
    </TemaProvider>
  );
}
```

## Bloco 2 · A gaveta do celular (70 min)

**Seção "AsyncStorage" (10 min).** Leia o gancho. Esperado: "estão guardadas no celular", "na memória do celular". "O app guardou numa gaveta do celular, que não esvazia quando o app fecha." Analogia do dia: **a gaveta do celular, que guarda mesmo depois de fechar o app**. Ligue ao E21: "lembram da gaveta do navegador, o `localStorage`? A do celular tem os mesmos dois botões. A diferença: ela demora, então tem `await`." Em "AsyncStorage: a gaveta do celular", leia a tabela dos botões. Depois, a demonstração de "AsyncStorage na prática", na segunda pasta, num efeito provisório no `GastosProvider`, logo abaixo dos dois efeitos (apague depois):

```jsx
useEffect(() => {
  async function testarGaveta() {
    await AsyncStorage.setItem('gastos.recado', 'Pagar a luz');
    const recado = await AsyncStorage.getItem('gastos.recado');
    console.log(recado);
    const nada = await AsyncStorage.getItem('gastos.nada');
    console.log(nada);
    const lista = [{ id: 1, descricao: 'Pão' }, { id: 2, descricao: 'Conta de luz' }];
    await AsyncStorage.setItem('gastos.teste', JSON.stringify(lista));
    const texto = await AsyncStorage.getItem('gastos.teste');
    console.log(texto);
    console.log(JSON.parse(texto).length);
  }
  testarGaveta();
}, []);
```

O terminal do Expo mostra (conferido com o AsyncStorage de mentira do pacote, que guarda e devolve do mesmo jeito):

```plaintext

 LOG  null
 LOG  [{"id":1,"descricao":"Pão"},{"id":2,"descricao":"Conta de luz"}]
 LOG  2
```

Pergunte antes da última linha: "o `texto` tem quantas letras? E a lista tem quantos itens?" Depois, tire o `JSON.stringify` da linha da lista e salve: o terminal mostra o aviso amarelo (o texto é o do pacote 2.2.0):

```plaintext

Não instale nada: o pacote está no `package.json` do kit; mostre a linha `"@react-native-async-storage/async-storage": "2.2.0"`. "Foi o `npx expo install` que escolheu essa versão, a que o Expo Go do SDK 58 abre. Se cada branch instalasse um pacote, o `package-lock.json` daria conflito, o pior de todos."

**"O quadro e a gaveta" (3 min).** Aponte as três camadas do desenho, de cima para baixo: as telas, o quadro na memória, a gaveta. "As telas não sabem que a gaveta existe. Quem fala com ela é o quadro, em dois momentos: o 1 e o 2. Cada um é um `useEffect`."

**Seção "Ler ao abrir" (9 min).** Leia o gancho. Esperado: "o próprio app", "o celular guarda". "É o primeiro efeito: ao abrir, o quadro abre a gaveta." Lembre a analogia do E27: **"depois de desenhar a tela, faça isto"**. Em "O primeiro efeito: ler ao abrir", aponte a função `async` dentro do efeito e a chamada logo embaixo: "é o molde do efeito que buscava as receitas no E27; troquem o `fetch` pelo `getItem`." Em "O primeiro efeito, caminho por caminho", pergunte: "no primeiro uso do app, o que vem da gaveta?" Esperado: `null`. "E a lista fica com quê?" Esperado: os exemplos. // O quadro de avisos dos lançamentos: todas as telas leem a mesma lista.
// O GastosProvider fica em app/_layout.js, em volta de tudo, e guarda a lista na gaveta do celular
// (AsyncStorage): ela continua lá depois de fechar o app.
// Em qualquer tela:
//   const { lancamentos, adicionar, remover } = useContext(GastosContext);
import { createContext, useEffect, useState } from 'react';
import AsyncStorage from '@react-native-async-storage/async-storage';
import { lancamentosDeExemplo } from './gastos';

export const GastosContext = createContext(null);

const CHAVE = 'gastos.lancamentos';

export function GastosProvider({ children }) {
  const [lancamentos, setLancamentos] = useState(lancamentosDeExemplo);
  const [carregado, setCarregado] = useState(false);

  // ao abrir o app: tira da gaveta o que estava guardado
  useEffect(() => {
    async function carregar() {
      const texto = await AsyncStorage.getItem(CHAVE);
      if (texto !== null) {
        setLancamentos(JSON.parse(texto));
      }
      setCarregado(true);
    }
    carregar();
  }, []);

  // a lista mudou: guarda de novo na gaveta
  useEffect(() => {
    if (carregado) {
      AsyncStorage.setItem(CHAVE, JSON.stringify(lancamentos));
    }
  }, [lancamentos, carregado]);

  function adicionar(novo) {
    setLancamentos([{ ...novo, id: Date.now() }, ...lancamentos]);
  }

  function remover(id) {
    setLancamentos(lancamentos.filter((item) => item.id !== id));
  }

  const valor = { lancamentos, adicionar, remover };
  return <GastosContext.Provider value={valor}>{children}</GastosContext.Provider>;
}
```

```jsx
// Tela Novo lançamento: o formulário de uma entrada ou de uma saída (a rota "/novo").
import { useContext, useState } from 'react';
import { Alert } from 'react-native';
import { router, Stack } from 'expo-router';
import ResumoLancamento from '@/components/ResumoLancamento';
import { Botao, Campo, Opcoes, Tela } from '@/components/ui';
import { GastosContext } from '@/data/GastosContext';
import { categorias, tipos } from '@/data/gastos';
import { formatarData, formatarReais, lerValor } from '@/utils';

export default function Novo() {
  const { adicionar } = useContext(GastosContext);
  const [tipo, setTipo] = useState('');
  const [valor, setValor] = useState('');
  const [categoria, setCategoria] = useState('');
  const [descricao, setDescricao] = useState('');
  const [erros, setErros] = useState({});

  // só as categorias do tipo escolhido, pelo nome
  const doTipo = categorias.filter((item) => item.tipo === tipo);
  const nomes = doTipo.map((item) => item.nome);

  function escolherTipo(novoTipo) {
    setTipo(novoTipo);
    setCategoria(''); // a categoria de antes era do outro tipo
  }

  function validar() {
    const novos = {};
    if (tipo === '') novos.tipo = 'Escolha entrada ou saída';

      descricao: descricao.trim(),

  return (
    <Tela rolar comCabecalho>
      <Stack.Title>Novo lançamento</Stack.Title>

        rotulo="Valor"
        placeholder="45,90"
        keyboardType="decimal-pad"
        value={valor}
        onChangeText={setValor}
        erro={erros.valor}
      />
      <Opcoes
        rotulo={tipo === '' ? 'Categoria (escolha o tipo antes)' : 'Categoria'}
        opcoes={nomes}
        valor={categoria}
        onMudar={setCategoria}
        erro={erros.categoria}
      />
      <Campo
        rotulo="Descrição"
        placeholder="Feira da semana"
        value={descricao}
        onChangeText={setDescricao}
        erro={erros.descricao}
      />
      <ResumoLancamento tipo={tipo} valor={lerValor(valor)} categoria={categoria} />
      <Botao titulo="Salvar lançamento" icone="checkmark" onPress={salvar} />
    </Tela>
  );
}

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| `Cannot read property 'lancamentos' of null` | o Provider não está no `app/_layout.js`, ou está em volta de outra coisa | `<GastosProvider>` em volta da `<Pilha />`, dentro do `TemaProvider` |

## Plano B

- **Celular ou Expo Go sem funcionar:** o app abre no navegador (tecla `w` no terminal do Expo). Lá, o AsyncStorage usa a gaveta do navegador, o `localStorage` do E21: no DevTools, aba **Application**, **Local storage**, aparece a chave `gastos.lancamentos` com o texto JSON da lista. Fechar a aba e abrir de novo é o "fechar o app". Para voltar aos exemplos, apague a chave ali.
- **Quem cuida dos dados faltou:** outra pessoa da equipe faz os passos 1 a 4 pelos slides, na mesma branch `dados-no-celular`. A pessoa que faltou revisa o pull request quando voltar e faz a sua tela na Sua vez.
- **GitHub fora do ar ou sem internet:** os passos 1 a 3 rodam sem rede. Quem cuida dos dados faz o commit na branch e deixa o push e o pull request para quando a rede voltar. Na Sua vez, sem o quadro na `main`, cada colega cria a sua branch `dados-` e põe nela o mesmo `GastosContext.js` e o mesmo Provider no `app/_layout.js`, copiados do computador de quem cuida dos dados (pendrive ou o próprio slide), para testar a tela. Quando o `dados-no-celular` entrar na `main`, a pessoa roda `git merge main --no-edit` na sua branch: arquivos iguais juntam sozinhos; se der conflito, é o do E42, e fica a versão da `main`. Ninguém faz commit na `main` local: o push depois seria recusado pela regra.
- **Equipe atrasada:** o quadro com a gaveta (passos 1 a 4) na `main` não se corta. A Sua vez pode terminar em casa, com o pull request antes do E44: no E44, o checklist de qualidade confere justamente o "fechou e abriu, está lá".
- **Sem projetor:** as demonstrações em grupos em volta do seu computador, com o seu celular passando de mão em mão.
