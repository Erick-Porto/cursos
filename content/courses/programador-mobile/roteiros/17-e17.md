## Visão do encontro

**Objetivo:** abrir a unidade Classes e estruturas de controle e o Projeto 3, a Lista de tarefas. A turma baixa o kit, põe no GitHub e escreve, com testes, as quatro regras do prazo em `src/regras/prazos.js`. Os conceitos do dia são as ferramentas dessas regras: o `switch` faz o peso da prioridade; a guarda (retorno antecipado) e a cadeia de `else if` fazem a situação do prazo; o `while` faz o próximo prazo. O `??` e o `?.` entram com exemplos próprios: no projeto, o `??` só aparece no E18 (no `constructor` da `Tarefa`) e no E21; o `?.` não aparece. Não há laboratório à parte: os passos do projeto são a prática do dia.

**Como a aula funciona:** cada conceito vem em três slides, como desde a aula 3. A seção (título e gancho) é a hora da conversa: leia o gancho, ouça duas ou três respostas e explique com a analogia indicada abaixo. O slide seguinte é a âncora, o que o aluno lê para revisar. Depois do conceito vem um slide **Projeto 3 · Passo K**: a turma faz junto com você, no próprio computador, e só segue quando o "Pronto quando" aparece na tela de todos. No fim, a **Sua vez** é feita sozinho, sem a solução no slide.

**Resultado ao fim das 4h:** cada aluno tem, na pasta de projetos, a `lista-de-tarefas` (o kit renomeado) com o `npm install` feito, o `.gitignore` com `node_modules/`, o `src/regras/prazos.js` com `pesoDaPrioridade`, `situacaoDoPrazo`, `proximoPrazo` e `textoDoPrazo` (cada uma com `export`) e o `src/regras/prazos.test.js`. O `npm test` mostra `Test Suites: 2 passed, 2 total` e `Tests: 31 passed, 31 total`. Em `http://localhost:3000/web/`, as 6 tarefas de demonstração aparecem ordenadas por urgência, com a borda da situação e o prazo em palavras ("Atrasada há 2 dias", "Vence hoje", "Vence amanhã", "Vence em 5 dias", "Sem prazo", "Concluída"), ainda sem botões; a lista "O que a página usa" mostra a Etapa 1 com 4 de 4, e o aviso amarelo diz "Próximo passo: Etapa 2 · E18 · Tarefa.js". No GitHub, o repositório público `lista-de-tarefas` com dois commits: `Projeto 3: kit da lista de tarefas` e `Projeto 3: etapa 1, prazo e prioridade`. É a etapa 1 do Projeto 3.

**Pré-requisitos:** Git e GitHub com `init`, `add`, `commit`, `remote` e `push -u` (E05); `export` e `import` (E07 e E16); Jest, `test.each` com `%s` (E08); `toUpperCase` (E09); `if`/`else`, `else if`, `null`, retorno antecipado, ternário (E10); laços e o laço sem fim (E11); `Date` com números e o mês que começa em 0, `npx serve` (E12); fichas (E13); `find` (E14). Novo hoje: `switch`, `case`, `break`, `default`, `??`, `?.`, `while` e o kit.

:::warning As analogias são as do E10
A estrada com várias saídas (vale a primeira que serve) para o `else if`; o segurança na porta do show para o retorno antecipado; o `null` como a caixa vazia de propósito e o `undefined` como a caixa que ninguém encheu; a placa "aberto/fechado" para o ternário. A única analogia nova é a do `switch`: o menu da central de atendimento. O `??` e o `?.` se explicam pela caixa vazia, sem analogia nova.
:::

**Materiais:** projetor com o VS Code em fonte grande e dois terminais (um para o `npm test`, outro para o `npx serve .`), o navegador ao lado; Wi-Fi (o `npm install` do kit baixa 372 pacotes, cerca de 54 MB por máquina); o [kit-tarefas.zip](materiais/projeto-3/kit-tarefas.zip) num pendrive, também numa versão com o `node_modules` já instalado, para quem ficar sem rede; a página do Projeto 3 aberta (página do curso, seção **Projetos**); o quiz publicado; a solução de referência do projeto em `privado/projetos/projeto-3/` (fora do Git): `etapa-1/` é o fim de hoje.

## Bloco 1 · O kit e as primeiras regras (80 min)

Aponte as duas colunas da tabela: o que a tela mostra agora e no fim do dia.

**"Projeto 3: a Lista de tarefas" (5 min).** Abra a página do Projeto 3 no projetor. Mostre a linha do tempo das 6 etapas, a rubrica e o prazo, início do E24. Diga: "É individual e é seu. **Projeto · Passo 1 (22 min).** Todos ao mesmo tempo, você no projetor, um item do `:::steps` por vez:

- **O zip.** Baixe pelo link do slide, "Extrair tudo" na pasta de projetos, renomeie para `lista-de-tarefas`. Confira, mesa por mesa, que a pasta aberta é a que tem o `package.json` (a extração pode criar pasta dentro de pasta).
- **`npm install` e `npm test`.** A instalação leva um minuto: aproveite para abrir o `src/utils/datas.js` e ler em voz alta o comentário do `diasAte`: "dias de hoje até o prazo; negativo quando já passou". O `npm test` mostra `Tests: 9 passed, 9 total`: são os testes do kit, que já passam.
- **`.gitignore`.** "O zip não traz o `.gitignore`: o site do curso não publica arquivos que começam com ponto." Na sua pasta, mostre por quê: `git init` e `git status` sem o `.gitignore` listam o `node_modules/`; com ele, o `git status` de novo já não lista. É o mesmo do E05. A turma segue a ordem do slide: o `.gitignore` primeiro, depois o `git init`.
- **Commit.** `git add .` e `git commit -m "Projeto 3: kit da lista de tarefas"`. No Windows, aparecem várias linhas `warning: in the working copy of '...', LF will be replaced by CRLF`: são normais. A última parte diz `18 files changed` e uma linha `create mode` por arquivo.

Leia com a turma o aviso amarelo ("Próximo passo: Etapa 1 · E17 · prazos.js") e a lista vazia ("A lista aparece quando src/regras/prazos.js tiver pesoDaPrioridade e situacaoDoPrazo"). Role até o fim: "O que a página usa", com as 6 etapas e 0 de 4 na primeira. "Essa lista confere cada função de vocês com os exemplos do enunciado. Salvou um arquivo? Recarregue a página."

O que observar: `npx serve .` dentro de `web/` (a tela avisa que o servidor precisa ser aberto na raiz); o `.gitignore` salvo como `.gitignore.txt`; repositório criado com README, e o `git push` recusado. Ninguém segue sem o push feito: o commit da etapa, no fim do dia, depende dele.

**Seção "O switch" (8 min).** Leia o gancho: "na central de atendimento, o que acontece quando você digita 2?". Esperado: vai para o setor 2. "E se digitar 9?" Esperado: "opção inválida", ou o menu repete. "O `switch` é esse menu: um valor, a tecla, comparado com cada opção, e o `default` é o 'outras opções'." Em "switch: um valor, vários casos", escreva o `setorDoMenu` no `rascunho.js` da pasta de demonstração e rode com 2 e com 9. Leia a tabela "em português" linha por linha: "o `return` devolve e sai da função: os casos de baixo nem são olhados".

**"switch na prática" (6 min).** Rode `setorDoMenu('2')` e pergunte, antes de mostrar a saída, o que aparece. Esperado de alguns: "Falar com um atendente". Resposta: `Opção inválida`. "O `case` compara com `===`: o texto `'2'` não é o número 2. Tudo o que chega pelo terminal é texto." Depois, o `switch` com `break`: "fora de uma função não há `return`; quem sai do `switch` é o `break`". Rode. Apague o `break` do `'semanal'` e pergunte, antes de rodar, o que sai. Esperado de muitos: "Toda semana". Rode: `Não repete`. "Sem o `break`, a execução desce para o caso de baixo e troca o rótulo." Devolva o `break`.

**Projeto · Passo 2 (13 min).** A turma apaga as três linhas de comentário do `prazos.js` e escreve o `pesoDaPrioridade`; depois, cria o `prazos.test.js` na mesma pasta, `src/regras`. Antes de rodar, pergunte: "quanto pesa `'urgente'`?". Esperado: 0, porque cai no `default`. `npm test` no primeiro terminal: `Test Suites: 2 passed, 2 total` e `Tests: 13 passed, 13 total`. Recarregue a tela: o item `pesoDaPrioridade(prioridade)` fica verde, e a Etapa 1 mostra 1 de 4; a lista ainda não aparece, e o aviso já pede a `situacaoDoPrazo`.

O que observar: `case 'média'`, com acento (o teste mostra `Expected: 2` e `Received: 0`: "os valores de código vêm sem acento; o acento é do rótulo, no E18"); `case alta:` sem aspas (`ReferenceError: alta is not defined`); o teste criado em `src/` em vez de `src/regras/` (`Cannot find module './prazos.js' from 'src/prazos.test.js'`); a função sem `export` (`(0 , _prazos.pesoDaPrioridade) is not a function`).

**Seção "Retorno antecipado" (9 min).** O gancho é o mesmo do E10, de propósito: "num show, o segurança barra quem não tem ingresso na porta ou lá dentro?". Esperado: na porta. "No E10 era isso: cada `if` barra um problema na porta, com `return`. Esse `if` da porta se chama guarda. Hoje ela tem um trabalho a mais: proteger o resto da função de um valor que ele não sabe usar." No `rascunho.js`, `primeiraLetra` com `'mariana'` e com `null`. Depois, a versão sem guarda: `TypeError: Cannot read properties of null (reading '0')`. Leia a mensagem com a turma: "tentei ler a posição 0 de `null`, a caixa vazia". Por fim, no mesmo arquivo, `import { diasAte } from './src/utils/datas.js'` e `diasAte(null, new Date(2026, 10, 10))`: `Error: O prazo precisa ser um texto 'AAAA-MM-DD'; chegou null.` "A tarefa sem prazo tem `prazo: null`. Por isso a situação do prazo, depois da pausa, começa pela guarda."

**Seção "Cadeia de else if" (10 min).** Leia o gancho: "no app de entrega, o restaurante de nota 4.7 ganha o selo 'Bom' ou 'Excelente'?". Esperado: "Excelente". "E a estrada do E10: vale a primeira saída que serve. Com `<`, a faixa menor vinha primeiro; com `>=`, é o contrário." Em "a ordem das saídas", peça o selo de 4.2 e de 2.8 antes de mostrar a tabela. Em "A ordem da cadeia na prática", rode o `seloTrocado(4.7)` e pergunte por que deu `Bom`. Esperado: 4.7 é `>= 3` e entra na primeira saída. "Nenhum erro avisa: é o teste que pega." Pergunte o selo de 4.5, de 4.49 e de 3 antes de rodar a linha da borda. Escreva no quadro e deixe até o fim do dia: "com `<`, da menor para a maior; com `>=`, da maior para a menor; teste a borda".

## Bloco 2 · O prazo, o que falta e o while (75 min)

**Projeto · Passo 3 (20 min).** Dois slides. No primeiro, o `import` no topo do `prazos.js`: desenhe no quadro a árvore `src/regras/prazos.js`, o `..` subindo para `src` e entrando em `utils/datas.js`. "O `.js` no fim é obrigatório: o Jest aceita sem, o navegador não." A turma escreve a `situacaoDoPrazo`. Pergunte: "em que linha a tarefa sem prazo sai?". Esperado: na guarda, a primeira. Monte com a turma a tabela "caminho por caminho": para cada prazo, peça o `dias` antes do caminho. No segundo slide, o `HOJE` logo abaixo do `import` e os dois testes. Leia o `new Date(2026, 10, 10, 23, 59)`: "com mais dois números, a hora e o minuto". `npm test`: `Tests: 20 passed, 20 total`. Recarregue a tela: as 6 tarefas aparecem. Deixe a turma olhar: "a tela chamou a função de vocês para cada tarefa". O prazo ainda aparece em data (`Prazo:` e o dia, porque o `textoDoPrazo` ainda não existe) e não há botões; a Etapa 1 mostra 2 de 4.

Demonstração rápida, na sua pasta: tire o `.js` do `import` e recarregue a tela. Ela mostra "Não deu para importar src/regras/prazos.js" e, no fim do aviso, `Failed to fetch dynamically imported module`. Rode `npm test`: continua verde. "O Jest aceita sem o `.js`; o navegador, não." Devolva o `.js`.

O que observar: `new Date(2026, 11, 10)` (dezembro: quase todos os testes da situação ficam vermelhos; "o mês começa em 0", do E12); `if (dias = 0)`, com um `=` só (o E10 avisou: guarda em vez de perguntar); a guarda depois do `diasAte` (`O prazo precisa ser um texto 'AAAA-MM-DD'; chegou null.`); o `diasAte(prazo)` sem o `hoje` (`diasAte precisa de hoje, um Date; chegou undefined. Você passou o hoje adiante?`).

**Seção "O operador ??" (8 min).** Leia o gancho: "a tarefa que não diz a prioridade é de prioridade alta, média ou baixa?". Esperado: média, a do meio. "É o valor de quando não vem. O `??` olha a caixa: se está vazia, `null` ou `undefined`, usa o outro valor." No `rascunho.js`, mostre primeiro `console.log(dados.prioridade)`: `undefined`, a caixa que ninguém encheu. Depois o `??`. Em "?? na prática", pergunte antes de rodar: "a mesa que escolheu 0 de gorjeta: o `??` troca por 10?". Esperado: não, o 0 não é caixa vazia. "No E18, as primeiras linhas da classe `Tarefa` são essas: a tarefa que só diz o título fica média e sem prazo."

:::info Se perguntarem do ||
O E10 usou o `||` só entre perguntas (`dia === 'sábado' || dia === 'domingo'`). A aula não compara o `??` com o `||` usado como valor padrão, para não abrir o assunto de quais valores o `if` lê como "não". Se alguém trouxer o `valor || 'padrão'` da internet, responda numa frase: "ele troca também o 0 e o texto vazio; para o valor de quando não vem, use `??`".
:::

**Seção "O operador ?." (8 min).** Leia o gancho: "dá para ler o dia do aniversário de quem não informou o aniversário?". Esperado: não, não há o que ler. "Na agenda do Projeto 2, o Daniel Rocha tem `aniversario: null`, a caixa vazia." No `rascunho.js`, rode `daniel.aniversario.dia`: `TypeError: Cannot read properties of null (reading 'dia')`. Leia a mensagem: "tentei ler `dia` de `null`". Troque por `?.`: `undefined`. Acrescente `?? 'sem data'`. Em "?. na prática", o `find` do E14 que não acha: pergunte o que o `find` devolve quando ninguém passa no teste. Esperado: `undefined`. Leia o `:::tip`: "o `?.` só onde o valor pode faltar de verdade".

**Seção "O while" (10 min).** Leia o gancho: "guardando R$ 30 por semana, quando você para de guardar para juntar R$ 100?". Esperado: "quando passar de 100", "na quarta semana". "O `while` é esse 'enquanto': enquanto não juntou 100, guarde mais 30. É o laço de conferir o carrinho do E11, só que sem lista: ele para quando a condição vira `false`." Monte a tabela volta por volta no quadro antes de mostrar a do slide: escreva `guardado` 0 e pergunte "0 < 100? então...", e desça o valor para a linha de baixo a cada volta. Rode: `4 120`. Pergunte: "e se o `guardado` começasse em 150?". Esperado: o laço roda zero vezes, e sai `0 150`.

**"O laço que não acaba" (5 min).** No `rascunho.js`, apague a linha `guardado = guardado + 30;` e rode: o terminal fica parado, sem mostrar nada. Encerre com <kbd>Ctrl</kbd> + <kbd>C</kbd>. "É o laço sem fim do E11. Com o `npm test`, é igual: ele fica parado, sem resultado." Leia as duas perguntas do fim do slide e deixe no quadro, ao lado da regra das faixas.

**Projeto · Passo 4 (17 min).** Dois slides. No primeiro, a história: "concluí hoje, dia 10, o 'Regar as plantas' da semana; quando é a próxima?". Esperado: dia 17. A turma acrescenta o `somarDias` ao `import` e escreve a função. Leia a tabela "em português". Pergunte: "por que `<= 0` e não `< 0`?". Esperado: se a data nova cair hoje, ela já vence hoje; precisa pular mais uma semana. "E o ternário é a placa do E10: diária mostra 1, o resto mostra 7." No segundo slide, o teste de três colunas: "cada linha traz três valores, e a função recebe os três, na ordem; um `%s` para cada no nome". Monte no quadro a volta por volta do `'2026-10-27'`. Pergunte também: "e com `'2026-11-12'`?". Esperado: a primeira data nova, `'2026-11-19'`, já passa de hoje: o `while` roda zero vezes. `npm test`: `Tests: 25 passed, 25 total`. Na tela, a Etapa 1 mostra 3 de 4, e o aviso pede o `textoDoPrazo`.

O que observar: dentro do `while`, `somarDias(prazo, dias)` no lugar de `somarDias(novo, dias)`. O `novo` não anda, e o `npm test` fica parado, sem resultado: é o laço que não acaba, ao vivo. Peça que o aluno encerre com <kbd>Ctrl</kbd> + <kbd>C</kbd> e leia a linha de dentro do `while` em voz alta: "o que muda a cada volta?".

**"Quando aparece um erro" (3 min).** Lembre a luz do painel do carro e leia a tabela. Pergunte quais a turma já viu hoje.

**Apresentação da Sua vez e da etapa pronta (4 min).** Projete "Projeto 3 · Sua vez" e "Etapa 1 pronta": é o que cada um faz depois da pausa. Leia as dicas em voz alta e reforce: "os testes primeiro; vocês vão ver seis vermelhos antes de escrever a função".

## Projeto: sua vez (30 min)

:::example Solução de referência
No fim de `src/regras/prazos.js`:

```javascript
// Etapa 1 (E17). O prazo em palavras, para a pessoa ler.
export function textoDoPrazo(prazo, hoje) {
  if (prazo === null) {
    return 'Sem prazo';
  }
  const dias = diasAte(prazo, hoje);
  if (dias < 0) {
    const atraso = -dias;
    return `Atrasada há ${atraso} ${atraso === 1 ? 'dia' : 'dias'}`;
  } else if (dias === 0) {
    return 'Vence hoje';
  } else if (dias === 1) {
    return 'Vence amanhã';
  } else {
    return `Vence em ${dias} dias`;
  }
}
```

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| `npm test` mostra `Could not read package.json` | o terminal está na pasta de projetos, ou na pasta de fora quando a extração criou pasta dentro de pasta | `cd` até a pasta que tem o `package.json`; abrir essa com `code .` |
| `'jest' não é reconhecido como um comando interno` | faltou o `npm install` | `npm install` na raiz do projeto |
| `git push` recusado (`rejected`) | o repositório foi criado com README | apagar o repositório no GitHub e criar de novo, vazio |
| a tela diz que o servidor precisa ser aberto na raiz | `npx serve .` rodado dentro de `web/` | <kbd>Ctrl</kbd> + <kbd>C</kbd>, `cd ..` e `npx serve .` de novo |
| a tela não muda depois de mexer no código | o arquivo não foi salvo, ou a página não foi recarregada | <kbd>Ctrl</kbd> + <kbd>S</kbd> e recarregar; o `serve.json` do kit já evita a versão velha |
| `Expected: 2` e `Received: 0` no peso | `case 'média'`, com acento | valores de código sem acento: `'media'` |
| `npm test` parado, sem resultado | laço que não acaba: dentro do `while`, `somarDias(prazo, dias)` no lugar de `somarDias(novo, dias)` | <kbd>Ctrl</kbd> + <kbd>C</kbd>; o `novo` precisa andar a cada volta |
| quase todos os testes da situação vermelhos | `new Date(2026, 11, 10)`: dezembro | o mês começa em 0: novembro é 10 |
