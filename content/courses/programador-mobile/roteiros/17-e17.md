## Visão do encontro

**Objetivo:** abrir por dentro as classes do E15 e do E16 (protótipo, cadeia, o que `class`, `extends` e `super` criam, `instanceof`) e tratar erros como parte das regras: `throw`, `try`, `catch`, `finally`, erros próprios com `codigo`, testes do caminho do erro e cada falha na mensagem certa do terminal.

**Resultado ao fim das 4h:** no `lojinha-regras`, `src/modelos/erros.js` com `ErroDeNegocio` e três filhos; `src/regras/checkout.js` com `freteDoCep`; `estoque` nos 12 produtos e a guarda em `alterarQuantidade`; `cadeia.test.js` provando a cadeia das classes da turma; `src/scripts/simular-entrega.js` imprimindo o resumo ou a mensagem com rótulo e relançando bugs. Pelo menos 12 testes novos, `npm run verificar` verde e commit "E17: erros próprios".

**Pré-requisitos:** `lojinha-regras` do E16 com `npm test` verde: `frete.js` e `pedido.js` (E13), `carrinho.js` com `subtotal`, `adicionarItem` e `alterarQuantidade`, `Produto` com `deJSON` e `toString` (E15), `Pagamento.js` com as quatro classes e `Pedido` com `#status` (E16), e o script `formas-de-pagamento.js` (E16). Nenhum pacote novo.

**Materiais:** projetor com editor e terminal lado a lado, quadro com duas cores, a pasta [demos-e17.zip](materiais/e17/demos-e17.zip) (`prototipos.mjs`, `erros.mjs` e a solução de referência em `solucao/`), branch `e17-solucao` e quiz publicado.

## Bloco 1 · Protótipos e as classes por dentro (50 min)

**"O que a class cria por baixo" e "Antes do class" (8 min).** Bloco 4: `typeof Produto` dá `'function'`. export class ErroDeNegocio extends Error {
  constructor(mensagem, codigo) {
    super(mensagem); // o Error guarda a message
    this.name = 'ErroDeNegocio';
    this.codigo = codigo;

}

export class CepInvalidoError extends ErroDeNegocio {
  constructor(cep) {
    super(`Confira o CEP ${cep}: ele precisa ter 8 números.`, 'CEP_INVALIDO');
    this.name = 'CepInvalidoError';
    this.cep = cep;
  }
}

export function alterarQuantidade(itens, id, qtd) {

import { produtos } from '../data/produtos.js';

function rotulo(erro) {
  switch (erro.codigo) {
    case 'CEP_INVALIDO': return 'Entrega';
    case 'CUPOM_INVALIDO': return 'Cupom';
    case 'ESTOQUE_INSUFICIENTE': return 'Carrinho';

  }

function aumentar(itens, id) {
  const item = itens.find((i) => i.id === id);

    console.log(`${rotulo(erro)}: ${erro.message}`);
    return itens; // a quantidade fica como estava
  }
}

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| O teste com `toThrow` falha com o próprio erro | `expect(freteDoCep(...))` sem arrow | `expect(() => freteDoCep(...))` |
| `ReferenceError: Must call super constructor` ao criar o erro | `this.name` antes do `super(mensagem)` | `super` primeiro: na filha, o objeto nasce na mãe |
| `erro.name` sai `Error` e a pilha começa com `Error:` | Faltou `this.name` na classe | Escrever o `name` à mão em cada erro |
| `SyntaxError: The requested module './erros.js' does not provide an export named ...` | Nome digitado diferente, ou `export default` no lugar de `export class` | Conferir a grafia; os erros são exportados por nome, com chaves no import |
| `Cannot find module '../modelos/erros'` | Import relativo sem a extensão | `'../modelos/erros.js'` |
| A guarda de estoque nunca dispara | Falta `estoque` no produto ou no `criarItem` | `console.log(item)`: `qtd > undefined` é sempre falso |
| Toda falha vira "Aviso: ..." ou some | `catch` sem `instanceof`, ou `catch` vazio | Relançar o que não é `ErroDeNegocio`; mostrar `erro.message` |
| `cadeia.test.js`: `Object.hasOwn(fone, 'precoPara')` dá `true` | Método criado no `constructor` (`this.precoPara = ...`) | Declarar o método no corpo da classe, como no E15 |
| Lint aponta `no-prototype-builtins` | `fone.hasOwnProperty('nome')` | `Object.hasOwn(fone, 'nome')` |
| Aviso `No such label 'simulacao' for console.timeEnd()` | Rótulos diferentes no `time` e no `timeEnd` | O mesmo texto, com acento, nos dois |
