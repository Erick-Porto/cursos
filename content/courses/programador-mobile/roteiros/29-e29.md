## Visão do encontro

**Objetivo**: mostrar que o aluno domina duas plataformas com uma só lógica, revisar a Introdução ao ambiente React Native (E26 a E29) e aplicar a Prova 3. Na grade da instituição, este encontro também fecha o Módulo Básico (React e React Native).

**Resultado ao fim das 4h**: `minhas-tarefas-mobile` com nome, ícone e splash próprios, aberto no celular de um colega pelo túnel, commit `v1 mobile` e README com captura no GitHub; Prova 3 entregue. Projeto 5: check-in da etapa 3 e a etapa 4 (hook `useConsumo`, regras puras, README e entrega) apresentada para casa, com prazo no início do E30.

**Pré-requisitos**: `minhas-tarefas` (commit `v1 web` do E25, com o fetch do E24) e `minhas-tarefas-mobile` (E28) funcionando e no GitHub; Expo Go instalado.

**Materiais**: projetor, Wi-Fi, um computador por aluno para a prova, celulares com Expo Go, folhas em branco.

## Abertura (15 min)

Três perguntas de retomada (5 min):

1. "Onde aparece o `console.log` de um app no Expo Go?" No terminal do `npx expo start`.
2. "Tela vermelha e aviso amarelo: qual é a diferença?" A vermelha para o app; o amarelo avisa e ele continua.
3. "Quais são as três props da `FlatList`?" `data`, `renderItem` e `keyExtractor`, que devolve string.

Tarefa de casa (5 min): dois alunos leem o README dos 3 bugs do E28; confirme: `push` sem `setTarefas`, texto solto na `View` e `renderItem={(item) => ...}` sem `{ item }`.

Objetivos (5 min): slide "O que você vai aprender" da aula 56 e o aviso: "Laboratório de 40 minutos; às 3:00, Prova 3, 20 questões em 60 minutos. Testem o login agora."

## Bloco 1 · Do React ao React Native (50 min)

**Slides "Dois projetos, uma só lógica" e "O que não muda" (10 min).** Com navegador e celular espelhado lado a lado, adicione a mesma tarefa nos dois e pergunte: "Quanto vocês reescreveram de verdade?" Anote dois chutes no quadro. No VS Code dividido, `alternarConcluida` nos dois arquivos: idênticas. "O que é React viaja; o que é navegador fica."

**Slides "O que muda: componentes" a "O que muda: listas" (14 min).** Três quebras ao vivo:

:::steps
1. No `App.js`, troque `<Text>{pendentes} pendentes</Text>` por `<p>{pendentes} pendentes</p>`: tela vermelha, `p` não existe. Ctrl+Z e salve.
2. No `FormularioTarefa.js`, troque `onChangeText={setTexto}` por `onChange={(e) => setTexto(e.target.value)}`: o campo trava. Pergunte por quê: não há `target.value`, o texto já chega como string.
3. Em `estilos.cartao`, escreva `padding: '16px'`: o espaçamento some. Volte para `padding: 16`: "número sem unidade, camelCase".
:::

**Slide "O que muda: navegação e APIs do aparelho" (3 min).** "Telas que se empilham chegam no E36, já na Lojinha. Hoje o app tem uma tela só."

**Slide "Pense" (6 min).** App de receitas, 2 minutos de caderno em duas colunas. Esperado: lógica é estado, `filter` da busca, `map` do favorito e `fetch` no `useEffect`; tela é `View`, `TextInput`, `Pressable`, `StyleSheet`, `FlatList` e `Image` com tamanho. Ninguém fala? Pergunte item a item: "A busca é lógica ou tela?"

**Slides "Lado a lado: adicionar tarefa" e "useEffect e fetch funcionam igual" (9 min).** Cole o diff no `App.js`, pergunte o que vai acontecer, salve: "Carregando..." e as 10 tarefas da API. Só `<p>` virou `<Text>`. "Onde mais vocês usaram esse mesmo `fetch`?" Esperado: no terminal, no `lojinha-regras` do E19. Retome os chutes: lógica copiada, tela traduzida.

**Slides "Compartilhar o app com o Expo Go" e "app.json antes de compartilhar" (6 min).** Rode `npx expo start --tunnel` e peça a um aluno em 4G para escanear. Enquanto o túnel sobe, percorra os cinco campos do `app.json`. "Mudou o `app.json`? `npx expo start -c`."

**Slides "Erros comuns ao migrar", "Resumo" e "Próximos passos" (2 min).** Leia os erros em voz alta: cada um cai na prova.

:::tip Ritmo
Passou de 0:40 no "Pense"? Corte a quebra do `padding` e mostre o fetch como diff pronto. O túnel não se corta: é a base do laboratório.
:::

## Projeto (8 min)

Sem tempo de trabalho hoje: a Prova 3 ocupa a última hora. O bloco fecha a etapa 3 e deixa a 4 para casa.

**Check-in (2 min).** "Quem fez o commit `Projeto 5: etapa 3, estado, lista e bug`?" Mãos. Abra um repositório `gota` e olhe uma coisa só: a seção Caça ao bug do README diz **como** o aluno isolou o bug (o `console.log` ou o breakpoint e o que apareceu)? **Etapa 4 (3 min).** Slide "Projeto 5 · Etapa 4: hook, regras e entrega". Ligue à aula 56: a lógica é copiada, a tela é traduzida. **Prazo e entrega (3 min).** **Início do E30**: o link do repositório colado na página do projeto, em Projetos. README com dois prints do celular e a seção do bug. :::example Solução de referência

```json

    "slug": "minhas-tarefas-mobile",
    "version": "1.0.0",
```

Cores no `App.js` (o resto do `StyleSheet` é o do E28):

```jsx
const estilos = StyleSheet.create({
  tela: { flex: 1, backgroundColor: '#1e293b' },

  concluida: { opacity: 0.5 },

```

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| Túnel parado em "Tunnel connecting" | `@expo/ngrok` não instalado ou rede bloqueando | Aceite a instalação; senão, hotspot e modo LAN |
| Colega vê "Something went wrong" | Modo LAN ou túnel caiu | Link deve terminar em `exp.direct`; Ctrl+C e `--tunnel` de novo |
| Nome ou ícone não mudaram | Cache do servidor ou do Expo Go | `npx expo start -c`; remova o projeto dos recentes |
| Ícone cortado ou ausente | PNG não quadrado ou caminho errado | 1024x1024 em `./assets/icon.png` |
| Captura não aparece no GitHub | Arquivo fora do commit ou caminho com maiúsculas | `git status` e `git add assets/captura.png` |
| "Tentativas esgotadas" na prova | Aba da tentativa fechada | Reabra pelo mesmo link; a tentativa continua |
| "Onde fica o `Alert` depois do hook?" (Projeto 5) | Dúvida entre lógica e tela | No `App`: o `Alert` é tela; o `useConsumo` guarda os dados e as funções que os mudam |
