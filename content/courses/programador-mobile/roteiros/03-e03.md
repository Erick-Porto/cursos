## Visão do encontro

**Objetivo:** o `lojinha-regras` ganha histórico e vai para o GitHub, e daqui em diante toda mudança chega à `main` por branch, Pull Request e revisão. No Bloco 1, o Git do zero (`init`, `.gitignore`, `add`, `commit`, `push`) e o fluxo de equipe (branch, PR, revisão, conflito). No Bloco 2, as ferramentas de qualidade: ESLint, Prettier, EditorConfig e o depurador do VS Code.

**Resultado ao fim das 4h:** cada aluno tem o `lojinha-regras` público no GitHub, com `.gitignore`; a Issue #1 ("Relatório com categoria em maiúscula mostra R$ NaN") provada com um breakpoint condicional e fechada por um PR revisado; o PR `chore/qualidade` com `eslint.config.js`, os scripts `lint` e `formatar`, `.prettierrc`, `.prettierignore`, `.editorconfig` e `.vscode/settings.json`, com `npm run lint` e `npx prettier --check .` limpos; e um conflito no preço do Fone Bluetooth resolvido em dupla.

**Pré-requisitos:** do E01, o Git instalado e configurado (`user.name`, `user.email` e `init.defaultBranch main`), a conta no GitHub e as extensões Prettier, ESLint e Error Lens. Do E02, o `lojinha-regras` com `src/data/produtos.js`, `src/data/catalogo.json`, os scripts `catalogo` e `relatorio`, o `picocolors` instalado e a anotação da tarefa: `npm run relatorio Audio` mostra `Produtos: 0` e `Preço médio: R$ NaN`. A turma nunca fez um commit.

**Materiais:** projetor, Wi-Fi, quadro com duas cores, uma segunda conta do GitHub (ou um aluno voluntário) num segundo navegador, quiz publicado.

## Bloco 1 · Git e GitHub (60 min)

**"O que você vai aprender" e "Um projeto, dois problemas" (3 min).** Leia a história e faça a pergunta. Anote as respostas num canto do quadro ("salvar na nuvem", "cada um na sua cópia") e não corrija: elas voltam no fechamento do bloco.

**"O primeiro repositório" a "GitHub": mão na massa (22 min).** A turma faz junto, cada um no próprio `lojinha-regras`. Você projeta o terminal da demonstração e só avança quando a maioria tiver o mesmo resultado:

:::steps
1. `cd lojinha-regras`, `git init` e `git status`. Leia a lista em voz alta e aponte o `node_modules/`: "isso vai para o GitHub?". Esperado: não; o `npm install` recria.
2. No VS Code, **New File** na raiz: `.gitignore`, com `node_modules/`. Salve e rode `git status`: a pasta sumiu e o `.gitignore` apareceu. Avise: no PowerShell, o `echo` grava o arquivo em UTF-16, e o Git não o lê.
3. `git add .` e `git status`: tudo em *Changes to be committed*. `git commit -m "E03: projeto lojinha-regras"` e `git log --oneline`. Quem receber `Author identity unknown` refaz os dois `git config --global` do E01.
4. Projete "add e commit" e percorra o diagrama com o dedo: as duas primeiras setas são o que a turma acabou de fazer.
5. "Mensagens de commit": peça a versão boa de cada mensagem ruim antes de mostrar a coluna da direita.
6. No GitHub, **New repository**: `lojinha-regras`, **Public**, sem README e sem `.gitignore`. Copie os três comandos de *push an existing repository*; no primeiro `git push`, o navegador abre para autorizar.
7. Atualize a página: arquivos e commit, sem `node_modules/`. Clique no commit e mostre o que entrou.
:::

Marco: às 0:35, todos com o commit no GitHub. Quem travar no login segue com o commit local e envia na pausa; o repositório público é pré-requisito do E04.

**"Pense" do `git status` (4 min).** Individual, 2 minutos. Esperado: só o `produtos.js` entra, com uma mensagem que nem fala dele. Pergunte: "como deixar os dois assuntos em commits separados?". Esperado: commit da descrição primeiro; depois `git add` do `package.json` e do script.

**"Branches" e "Merge" (6 min).** Ao vivo, no repositório que você acabou de criar:

:::steps
1. `git switch -c chore/readme` e `git branch`: o `*` marca onde você está.
2. Crie `README.md` com o título e uma seção "Comandos" (`npm install`, `npm run catalogo`, `npm run relatorio audio`). Commit "Cria o README com os comandos".
3. `git switch main`: o README some da pasta diante da turma. Volte para a branch e ele reaparece.
4. `git log --oneline --graph --all`: a branch um commit à frente da `main`.
:::

Não faça o merge local: ele vai pelo PR. Leia no slide "Merge" o grafo e o aviso do editor; se alguém já caiu no Vim, `:wq` e <kbd>Enter</kbd>.

**"Issues", "Pull Request" e "Revisão de código" (10 min).** Ao vivo:

:::steps
1. Aba **Issues**, **New issue**: a Issue do slide, com Passos, Esperado e Obtido. Mostre o `#1`. "Quem vai corrigir são vocês, no laboratório."
2. **Settings**, **Collaborators**, **Add people**: a segunda conta. No outro navegador, aceite o convite em github.com/notifications.
3. `git push -u origin chore/readme`, **Compare & pull request**, descrição com "O que muda" e "Como testar"; a segunda conta em **Reviewers**.
4. Com a segunda conta, em **Files changed**, comente a linha dos comandos: "falta dizer que o `npm install` vem antes". Envie com **Request changes**.
5. Atenda com um commit na mesma branch e `git push`: o PR se atualiza sozinho. Aprove com a segunda conta.
6. **Merge pull request**, **Delete branch**; no terminal, `git switch main`, `git pull` e `git branch -d chore/readme`.
:::

**"Da branch à main" (1 min).** Deixe a animação rodar uma vez em silêncio. Na segunda volta, um aluno narra cada etapa com o comando ou o botão que você acabou de usar.

**"Pense" do PR (4 min).** Individual. Esperado: o `toLowercase`, a pasta `node_modules/` e o "aaa", com **Request changes**. Peça a alguém que leia o comentário do `toLowercase` como o mandaria ao colega. Pergunte: "como o revisor descobre o `toLowercase`?". Esperado: rodando o "Como testar". "Na aula 6, vocês veem que nem o ESLint pega esse."

**"Conflito" e "Resolvendo o conflito" (8 min).** Leia as marcas do slide e pergunte o que é `HEAD`. Esperado: a branch em que você está. Depois, ao vivo no `lojinha-regras-conflito`:

:::steps
1. Com a segunda conta, faça o merge do PR da `feature/preco-fone-a`.
2. Atualize o PR da `feature/preco-fone-b`: *This branch has conflicts that must be resolved*.
3. No seu clone: `git switch main`, `git pull`, `git switch feature/preco-fone-b`, `git merge main`. O `git status` mostra o `produtos.js` e o `catalogo.json` como *both modified*.
4. No `produtos.js`, o VS Code mostra as marcas e os botões. Combine o preço em voz alta com quem "é a Ana" e use **Accept Current Change**.
5. O `catalogo.json` não se resolve à mão: `npm run catalogo` o grava de novo a partir do `produtos.js` resolvido, e prova que ele voltou a ser JavaScript válido.
6. `git diff --check` sem nada, `git add` nos dois, `git commit -m "Resolve conflito no preço do fone"`, `git push`; PR verde e merge.
:::

**"Erros comuns" e "Resumo" (2 min).** Volte às respostas anotadas no início: "salvar na nuvem" é o push; "cada um na sua cópia" é a branch, com PR para juntar.

:::tip Ritmo
Se atrasar, mostre "Mensagens de commit" sem perguntas e revise o PR do README sem o commit de correção. A mão na massa até o push, o PR ao vivo e o conflito ao vivo não se cortam: o laboratório repete os três.
:::

**"Linter", "O eslint.config.js" e "Rodando o lint" (12 min).** Ao vivo:

:::steps
1. `npm install -D eslint @eslint/js globals` e mostre as `devDependencies` novas.
2. Crie o `eslint.config.js` **sem** o bloco dos globais: só os imports de `@eslint/js` e `defineConfig` e a lista com `js.configs.recommended`. `npx eslint .`: 8 erros de `no-undef`, um para cada `console` e o `process`.

**"As regras recomendadas" (3 min).** No `produtos.js`, repita `preco: 34.99` no fim de um produto: `no-dupe-keys`. Pergunte qual preço vale. Esperado: o último. Desfaça.

**"Pense" (4 min).** Duplas, 2 minutos. Esperado: `path` e `livro`; a média dividida por 12 passa. Pergunte quem acharia o terceiro. Esperado: o depurador ou um teste (E04).

**"Prettier", "Formatando o projeto" e "EditorConfig e formatar ao salvar" (10 min).**

:::steps

4. `npx prettier --write .` e `git diff --stat`: o `produtos.js` com uma propriedade por linha. "Por isso a formatação vai num commit só dela."
5. `.editorconfig` e `.vscode/settings.json`. Bagunce o recuo do relatório e salve: tudo volta ao lugar.

6. Watch com `typeof produto.preco`; no Debug Console, `Number(produto.preco)`. Na Call Stack, clique na linha de baixo: o editor mostra a linha 10, a do `reduce`. Resposta aos palpites: o dado.

## Laboratório (75 min)

**Enunciado:** os 7 passos do slide "No laboratório" da aula 6.

**Organização:** duplas do quadro; cada um no próprio repositório, revisando o PR do outro. O revisor clona o repositório do colega à parte (`git clone <url> lojinha-do-colega`) e roda `npm install` nele: o relatório usa o `picocolors`. O conflito acontece no repositório de um da dupla, com o outro trabalhando nesse clone; sobrando tempo, invertem os papéis. No trio, A revisa B, B revisa C e C revisa A.

**Marcos:** 2:35, Issue e branch criadas e a pausa provada diante do colega; 2:50, PR do fix aberto com revisor; 3:00, revisões e merge do fix; 3:20, PR `chore/qualidade` com merge; 3:30, conflito resolvido e com merge; 3:35, entrega.

**O que observar:** commits direto na `main`; `.gitignore` criado com `echo`; correção antes da pausa que prova a causa; PR sem "Como testar"; `node_modules/` em **Files changed**; aprovação em menos de um minuto (pergunte "você rodou?"); qualquer `--force`; formatação misturada com a correção; `eslint-disable` para calar um erro. Antes do commit do conflito, peça `git diff --check`.

:::example Solução de referência
**Passo 1.** A Issue:

```markdown
**Título:** Relatório com categoria em maiúscula mostra R$ NaN

**Passos:** `npm run relatorio Audio`
**Esperado:** os 3 produtos de áudio
**Obtido:** `Produtos: 0` e `Preço médio: R$ NaN`
```

**Passo 2.** No `relatorio-catalogo.js` do E02, a linha da média é a 19 (`const media = soma / lista.length;`); se o aluno acrescentou linhas, ela muda de número. Breakpoint nela, **Edit Breakpoint** com `lista.length === 0` e, no JavaScript Debug Terminal, `node src/scripts/relatorio-catalogo.js Audio`. Com `audio`, o script não para. Na pausa:

| Painel | O que aparece |
|---|---|
| Variables | `categoria: 'Audio'`, `lista: Array(0)`, `soma: 0` e `media` ainda sem valor |
| Watch `catalogo.produtos[0].categoria` | `'audio'` |
| Watch `categoria === 'audio'` | `false` |

Lista vazia, soma 0 e `0 / 0` dá `NaN`: o filtro compara `'audio'` com `'Audio'`.

**Passo 3.** O filtro corrigido, a única linha que muda:

```javascript
if (categoria) {
  lista = lista.filter((produto) => produto.categoria === categoria.toLowerCase());
  titulo = categoria;
}
```

Saída de `npm run relatorio Audio`, depois das duas linhas que o npm imprime:

```plaintext

Em destaque: 1
Acima de R$ 200: 2
```

Descrição do PR:

```markdown
**O que muda:** o filtro do relatório compara a categoria em minúsculas, com `toLowerCase()`.

**Como testar:**
- `npm run relatorio Audio`: os 3 produtos de áudio, preço médio R$ 259.90
- `npm run relatorio audio`: o mesmo resultado
- `npm run relatorio`: o catálogo inteiro, 12 produtos

Closes #1
```

```javascript
    preco: 189.9,
>>>>>>> main
    categoria: 'audio',
```

Com as marcas no arquivo, `npm run lint` acusa `Parsing error: Unexpected token <<` e o `npm run catalogo` quebra com `SyntaxError`: dois avisos de que ainda falta resolver.

**Para quem prefere o <kbd>F5</kbd>.** `.vscode/launch.json`, que depura o arquivo aberto no editor:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "node",
      "request": "launch",
      "name": "Depurar o arquivo aberto",
      "program": "${file}",
      "skipFiles": ["<node_internals>/**"]
    }
  ]
}
```

Para passar a categoria ao relatório, acrescente `"args": ["Audio"]`. Não use o **create a launch.json file** do VS Code sem conferir: ele pode apontar para o `index.js` do campo `main` do `package.json`, que não existe.
:::

**Critérios:** os do slide, mais: a pausa do passo 2 vista pelo colega; um commit só de formatação; nenhum `<<<<<<<` na `main`.

**Entrega:** o aluno cola o link do repositório na entrega do laboratório E03 no sistema. Em **Pull requests**, filtro **Closed**, você vê em segundos as revisões, os merges e a Issue #1 fechada.

## Fechamento (20 min)

**Correção coletiva (8 min).** Projete 3 repositórios da turma:

- Um PR do fix exemplar: Issue ligada, "Como testar" e um comentário atendido. Pergunte: "se o revisor aprovasse sem rodar, o que poderia passar?". Esperado: um `toLowercase`, como no "Pense".
- Um com `node_modules/` em **Files changed** ou commits direto na `main`: mostre o `.gitignore` e o `git rm -r --cached node_modules`.
- Um conflito resolvido: abra o commit de merge e mostre que só a linha do preço mudou no `produtos.js`, sem marcas. Aponte o quadro: o lint pegou o `categria`, o Prettier acabou com as aspas, o depurador mostrou a lista vazia; no E04, os testes pegam o resto.

**Quiz (12 min).** "Quiz: E03 · Git, GitHub, lint, formatação e depuração": 10 questões, 70% para aprovar, 3 tentativas, gabarito ao fim. Individual, slides fechados. Avise que a de completar pede dois comandos exatos. Se a do `git status` ou a da sequência do conflito passar de 30% de erro, refaça as duas na abertura do E04.

## Encerramento (5 min)

**Tarefa de casa:** terminar o laboratório (lint zerado e os dois PRs com merge são pré-requisito do E04), revisar as aulas 5 e 6 e refazer o quiz quem ficou abaixo de 70%. Desafio opcional, em dupla: um esconde um preço entre aspas no `catalogo.json` do outro, que acha o produto só com o breakpoint condicional do `preco-medio.js`; `npm run catalogo` desfaz.

**Prévia do E04:** os primeiros testes automáticos do `lojinha-regras` com Jest, o script `verificar` com lint e testes de uma vez e o GitHub Actions rodando tudo a cada push e a cada PR. "O `R$ NaN` de hoje, um teste pega antes de chegar a qualquer pessoa."

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| `git push` recusado com `rejected` | O GitHub tem commits que a máquina não tem | `git pull`, resolver o conflito se houver e `git push`; nunca `--force` |
| `node_modules/` continua no `git status` | `.gitignore` criado com `echo` no PowerShell (UTF-16) ou fora da raiz | Apagar e criar pelo VS Code, na raiz, ao lado do `package.json` |
| `Author identity unknown` no commit | Máquina da escola sem `user.name` e `user.email` | Os dois `git config --global` do E01 |
| Aviso `LF will be replaced by CRLF` | O Git do Windows ajustando o fim de linha | É só aviso; o `"endOfLine": "auto"` impede o Prettier de reclamar |
| O colega não aparece em **Reviewers** ou não aprova | Convite não aceito, ou ele é o autor do PR | **Settings**, **Collaborators**; aceitar em github.com/notifications |
| Editor estranho no terminal depois do `git merge` | O commit de merge abriu o Vim | <kbd>Esc</kbd>, `:wq` e <kbd>Enter</kbd>; se for o VS Code, fechar a aba |
| `ESLint couldn't find an eslint.config.* file` | Arquivo com outro nome ou fora da raiz | `eslint.config.js` na raiz |
| `require is not defined in ES module scope` | Configuração copiada em CommonJS | `import` e `export default`, como no slide |
| `'console' is not defined` em todo script | Faltou o bloco do `globals.node` | Conferir o bloco e o `import globals from 'globals'` |
| O breakpoint nunca para | Script rodado num terminal comum, ou linha fora do caminho | JavaScript Debug Terminal; testar com um `debugger;` na linha |
| O script parece travado | Pausado num breakpoint esquecido | <kbd>F5</kbd> e remover todos no painel Breakpoints |
| Salvar não formata o arquivo | Extensão Prettier ausente ou outro formatador padrão | Instalar e conferir o `.vscode/settings.json` |
| `SyntaxError: Unexpected token '<<'` | Marcas de conflito no arquivo | Buscar `<<<<<<<`; `git diff --check` antes do commit |

## Plano B

- **Sem internet ou GitHub fora do ar:** o Git funciona sem rede. `init`, `.gitignore`, commits, branch, merge e conflito no próprio repositório, simulando as duas pessoas com duas branches locais. O push, o PR e a revisão ficam para casa; o quiz vai para a abertura do E04. ESLint e Prettier precisam do npm: hotspot em turnos de 4, ou o `node_modules` de uma máquina que instalou, copiado num pen drive.
- **Aluno sem acesso ao GitHub:** recuperação da senha ou da verificação em duas etapas na pausa; enquanto isso, ele faz os commits locais e revisa o PR do colega na tela dele. O push vai em casa.
- **Colega faltou:** trio em rodízio ou você como revisor. Para o conflito, dois clones do próprio repositório (`git clone <url> lojinha-2`), um para cada papel.
- **O depurador do VS Code não para:** rode `node --inspect-brk src/scripts/relatorio-catalogo.js Audio`, abra `chrome://inspect` no Chrome e clique em **inspect**: a aba Sources abre parada na primeira linha. Ponha o breakpoint na linha da média e aperte <kbd>F8</kbd> para seguir; o painel Scope mostra as mesmas variáveis.
- **Sem projetor:** grafo de branches no quadro a cada comando e demonstrações em grupos de 5 em volta do seu computador.
