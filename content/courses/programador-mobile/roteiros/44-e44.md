## Visão do encontro

**Objetivo:** o app de cada equipe vira um APK de preview e ganha um README que recruta, enquanto a sprint 2 fecha persistência, erros tratados e testes. No fim, o ensaio do pitch.

**Slides de seção:** cada conceito abre com um slide que só tem o nome dele e uma frase de gancho, no centro ("O build", "Segredos no app", "O README"). É a hora da conversa: faça a pergunta do gancho, que vem repetida abaixo, ouça duas ou três respostas e explique com a analogia. O slide seguinte, a âncora, ensina o mesmo conceito por escrito, para quem revisa em casa; depois dela vêm os exemplos de uso (os slides "na prática"). Em aula, passe pela âncora apontando o que acabou de dizer, sem ler tudo. As analogias da aula 86 são uma família só, a da padaria: o build é o bolo embalado para viagem, o EAS é o forno da padaria e o EAS Update troca a cobertura sem assar outro bolo. Use sempre essas, nas duas aulas e no laboratório.

**Resultado ao fim das 4h:** por equipe, um APK instalado num Android, com ícone e splash próprios, falando com o `json-server`; um dado do briefing que sobrevive ao fechar o app; 10 testes de regras verdes; README com telas, decisões, vídeo e o APK numa Release `v1.0.0`; ensaio de 5 minutos com devolutiva; PR "E44: sprint 2, APK e README" na `main`.

**Pré-requisitos:** o app da equipe no estado do E43 (fluxo principal contra o `json-server`, contexto com `useReducer`, pelo menos 5 testes, regra "main protegida"); uma conta em expo.dev por equipe, com e-mail confirmado; um Android por equipe.

**Materiais:** projetor espelhando o celular, um segundo celular Android, cronômetro visível, planilha de mentoria, pares do ensaio no quadro, quiz publicado.

## Antes do encontro

:::steps
1. Dois dias antes, avise: cada equipe escolhe o **dono do build**, cria a conta em expo.dev com e-mail e senha, confirma o e-mail e traz um Android carregado.
2. Na véspera, faça a aula 86 inteira no app de demonstração do projeto integrador e cronometre fila e compilação.
3. Gere dois APKs: um **sem** o `expo-build-properties`, no segundo celular, e um com ele, no seu. Sem segundo celular, grave a tela do erro.
4. Na rede da escola, rode `npx json-server db.json --port 3000` e abra `http://<seu-IP>:3000` no navegador do celular. Não abriu? Tente com `--host 0.0.0.0`; persistindo, a rede isola os aparelhos: hotspot do Plano B.
5. Confira se as máquinas do laboratório aceitam `npm install -g`; senão, a turma usa `npx eas-cli`.
6. Planilha de mentoria: uma linha por equipe, com o que ficou da sprint 1, o risco principal e a ordem do rodízio.
:::

## Abertura (15 min)

Retomada do E43 (5 min): checklist de qualidade, dados no aparelho e login.

1. Checklist de qualidade: "Quais são os 4 estados de uma tela que busca no `json-server`, e como forçar o de erro?" Esperado: carregando, erro, vazio e dados; <kbd>Ctrl</kbd> + <kbd>C</kbd> no terminal do `json-server`.
2. Dados no aparelho: "Por que o carrinho passa por `JSON.stringify` antes do AsyncStorage, e para que serve a trava `carregado`?" Esperado: o AsyncStorage só guarda texto; sem a trava, o `[]` inicial é gravado por cima do que estava salvo.
3. Login: "Depois do login na DummyJSON, onde fica o token, e onde fica a senha?" Esperado: o token no SecureStore, criptografado; a senha em lugar nenhum, porque o token vence e pode ser cancelado. Emende: "E o que pode ir numa variável `EXPO_PUBLIC_`?" Esperado: só valores públicos, porque ela vai para dentro do app. Gancho: "Hoje o app vira um arquivo que qualquer pessoa instala e lê."

Correção da tarefa (5 min): cada equipe mostra o quadro e o PR do commit `docs: E43 fechamento da sprint 1` por 30 segundos: o que foi para Done, que Must ficou, se a revisão cruzada foi respondida e se o dono do build já confirmou a conta no expo.dev. Equipe com Must atrasada recebe a primeira mentoria; a que ainda não tem conta cria agora, no celular. Se alguma questão do quiz do E43 passou de 30% de erro no painel, retome-a em 1 minuto antes dos objetivos.

Objetivos (5 min): projete "O que você vai aprender" da aula 86. "No Demo Day, a banca instala o app de vocês."

## Bloco 1 · Publicação com EAS (50 min)

**"Palavras novas de hoje" e "Me manda o app?" (3 min).** Leia as seis palavras em voz alta, com um exemplo rápido de cada. Na pergunta do slide, esperado: "o app precisa levar o JavaScript dentro dele".

**Seção "O build" (4 min).** Pergunte: "qual a diferença entre comer o bolo na padaria e levar um embalado para casa?". Esperado: o embalado vai inteiro e não depende da padaria aberta. "O build é o app embalado para viagem: tudo dentro de um arquivo. O Expo Go é comer na padaria: fechou o notebook, acabou o app." Com o app aberto no Expo Go, pare o `npx expo start` e recarregue: erro de conexão. Abra o APK da véspera com o servidor parado: abre, com ícone e splash próprios. No diagrama de "O JavaScript vai dentro do APK", mostre o que a turma acabou de ver: no Expo Go, o JavaScript e os dados saem do computador; no APK, só os dados. Em "Expo Go, APK e loja na prática", leia a última linha da tabela: desenvolver, testar e apresentar, publicar.

**Seção "A identidade do app" (4 min).** Pergunte: "que número identifica vocês, e mais ninguém, no país inteiro?". Esperado: o CPF. "O `android.package` é o CPF do app: único, e depois de publicado na loja não muda." Edite `name`, `version` e `android.package` ao vivo, com "A identidade do app no app.json" projetado: a tradução das chaves está nele. Cada equipe dita o seu `package`; a turma confere pela tabela de "O android.package na prática". Esperado: alguém propõe hífen.

**Seção "EAS Build" (4 min).** Pergunte: "quem não tem forno em casa e quer um bolo assado faz o quê?". Esperado: leva para a padaria assar, ou encomenda. "O EAS é o forno da padaria: vocês mandam o projeto, a Expo faz o build no computador dela e avisa quando está pronto." Em "EAS: o build na nuvem", `eas whoami` projetado. Anote o dono do build de cada equipe; quem não confirmou a conta faz isso agora, no celular. Em "O EAS na prática", mostre o `npx eas-cli` para as máquinas que bloqueiam o `npm install -g`.

**Seção "Perfis de build" (8 min).** Pergunte: "na câmera do celular, para que servem os modos retrato e noite?". Esperado: cada modo ajusta tudo de uma vez para uma situação. "Cada perfil do `eas.json` é um modo: o `preview` faz o build para testar por link; o `production`, para a loja." Em "O eas.json e os perfis", "Os três perfis" e "O perfil preview gera o APK":

:::steps
1. `eas build:configure`, escolhendo Android. Se perguntar se cria um projeto EAS na conta, responda que sim.
2. `git diff app.json` mostra o `projectId`. "Só o dono do build roda este comando; a equipe recebe pelo PR."
3. No `eas.json`, mostre os três perfis e complete o `preview` com `distribution`, `android.buildType` e `env`.
4. `ipconfig` e o IP do seu notebook no `env`: "o do computador que roda o `json-server` na apresentação".
:::

**"Pense" (3 min).** Duplas. Esperado: o AAB é o formato da loja, e o Android não o instala; perfil `preview` e o link, não o arquivo.

**Seção "http e https" (2 min).** Pergunte: "quem consegue ler um cartão-postal no caminho até a casa de quem recebe?". Esperado: qualquer um que pegar nele, até o carteiro. "O `http://` é o cartão-postal; o `https://`, a carta lacrada. O APK, por padrão, recusa cartão-postal." Em "http e https na prática", aponte a linha do `json-server`: só ela falha, e só no APK. Em "Liberar o http:// para o json-server", `npx expo install expo-build-properties` e o plugin com `usesCleartextTraffic`; mostre a lista `plugins` antes e depois.

**Seção "Gerar e instalar" (6 min).** Pergunte: "antes de pôr o bolo no forno, o que vocês conferem?". Esperado: a massa, se não faltou nada. "O `expo-doctor` confere a massa; o `eas build` leva ao forno da Expo." Enquanto o build da turma espera na fila (passo 3), projete "Do computador ao celular" e deixe a animação rodar uma vez: o projeto sobe sem o `.env`, por isso a URL da API vai no `env` do perfil.

:::steps
1. `npx expo-doctor`, que precisa terminar sem problemas.
2. `eas build --profile preview --platform android`. Responda sim ao keystore e explique o que ele é, com a imagem do slide: a assinatura num documento, que as próximas versões repetem. Se perguntar sobre emulador, responda não.
3. Abra o link do build: a turma o vê na fila.
4. Na página do build da véspera, mostre o botão **Install** e o QR code.
5. Com o `json-server` ligado, abra o APK sem o plugin, no segundo celular: "Network request failed". No seu, a lista carrega.
:::

**Seção "Segredos no app" (3 min).** Pergunte: "o cardápio impresso vai para a mão de todo cliente. O que nunca pode estar escrito nele?". Esperado: a senha do cofre, o que é só da casa. "O APK é esse cardápio: quem baixa lê o que está dentro." Em "Segredos na prática", pergunte: "O que do app de vocês não pode ir para o APK?" Esperado: com `json-server`, nada secreto; no Supabase, a `service_role`. O Supabase aparece só como exemplo de mercado: o app da equipe não o usa.

**Largada das equipes (10 min).** No quadro: issue e branch como `chore/21-apk-preview`, `app.json`, `eas.json`, plugin, `expo-doctor`, `eas build`. O dono do build digita, a equipe confere item a item; o build sai da branch e o PR vem depois. Só avance quando todas as mesas tiverem um build na fila.

**Seções "EAS Update", "As lojas" e "Mensagens de erro", até "Próximos passos" (3 min).** Uma pergunta e uma frase por seção, enquanto os builds esperam. Em "EAS Update", pergunte: "precisa assar outro bolo só para trocar a cobertura?". Esperado: não. "O EAS Update troca a cobertura, o JavaScript e as imagens; mudar a massa, como código nativo ou ícone, pede build novo": a tabela de "O EAS Update na prática" separa os dois casos. Em "As lojas", pergunte onde eles procuram um app novo. Esperado: na loja do celular. "A loja é o supermercado: só põe na prateleira o que tem cadastro e rótulo"; as lojas voltam na aula 89. Em "Mensagens de erro", pergunte o que se faz quando acende uma luz no painel do carro e deixe "Quando aparece um erro" projetado enquanto os builds terminam.

:::tip Ritmo
Se atrasar, mostre o `eas.json` pronto e fale "As lojas" sem a tabela de "O que as lojas exigem". A largada não se corta: o build disparado agora fica pronto no laboratório.

## Laboratório (70 min)

**Enunciado:** os 7 passos do slide "No laboratório" da aula 87. O APK está na fila desde o Bloco 1.

**Organização:** uma branch e um PR por item, como no E41. O dono do build cuida do APK e da Release; outra pessoa, da persistência e dos erros; a terceira, dos testes. README e vídeo são de todos. Em dupla, testes e persistência ficam com a mesma pessoa.

**Mentoria:** rodízio de 5 minutos por mesa até 3:05, começando pelas equipes marcadas na abertura. Quatro perguntas: "O APK abre sem o `npx expo start`?"; "O que falta da definição de pronto?"; "Quem está travado há mais de 15 minutos?"; "Se o tempo acabar, o que vocês cortam?" (esperado: um item Should, nunca testes nem APK).

**Sinais de risco:** build falhou duas vezes; nenhum teste novo às 2:45; README intocado às 2:55; uma pessoa digitando e duas olhando.

**Como destravar:** build vermelho, leia o log com a equipe a partir da primeira etapa vermelha, antes de qualquer palpite. Testes travados, escreva junto o caso mais simples da regra mais simples; o resto sai por cópia. Persistência, aponte a receita da aula 85 (`salvar` e `ler` do `armazenamento.js`, carregar ao abrir, salvar ao mudar com a trava `carregado`), com uma ação `carregar` no reducer. Equipe sem rumo, uma história Must só.

**Marcos:** 2:25, daily de 3 minutos; 2:40, APK instalado (build com falha relançado até aqui); 2:55, persistência e erros com PR aberto; 3:05, 10 testes, capturas e vídeo; 3:05 a 3:25, ensaio cruzado; 3:25, merge e entrega.

**Ensaio cruzado (20 min):** em pares de equipes, uma apresenta 5 minutos e recebe 3 de devolutiva; depois trocam. Assista a dois ensaios e anote para o E45 o que se repete: abertura pela tecnologia, demo que passeia por todas as telas, IP do dia desconhecido.

`src/features/carrinho/CarrinhoContext.js`:

```jsx
import { createContext, useContext, useEffect, useReducer, useState } from 'react';
import { carrinhoReducer } from './carrinhoReducer';
import { ler, salvar } from '../../servicos/armazenamento';

const CHAVE = 'cardapio.carrinho';
const CarrinhoContext = createContext(null);

export function CarrinhoProvider({ children }) {
  const [itens, dispatch] = useReducer(carrinhoReducer, []);
  const [carregado, setCarregado] = useState(false);

  useEffect(() => {
    async function carregar() {
      dispatch({ type: 'carregar', itens: await ler(CHAVE, []) });
      setCarregado(true);
    }
    carregar();
  }, []);

  useEffect(() => {
    if (carregado) salvar(CHAVE, itens);
  }, [itens, carregado]);

  const valor = {
    itens,
    quantidade: itens.reduce((soma, i) => soma + i.qtd, 0),
    total: itens.reduce((soma, i) => soma + i.preco * i.qtd, 0),
    adicionar: (produto) => dispatch({ type: 'adicionar', produto }),
    remover: (id) => dispatch({ type: 'remover', id }),
    limpar: () => dispatch({ type: 'limpar' }),
  };
  return <CarrinhoContext.Provider value={valor}>{children}</CarrinhoContext.Provider>;
}

export function useCarrinho() {
  const valor = useContext(CarrinhoContext);
  if (!valor) throw new Error('useCarrinho fora do CarrinhoProvider');
  return valor;
}
```

Regras do cardápio, `src/features/pedidos/regras.js`:

```javascript
export const PEDIDO_MINIMO = 15;

export function totalDoPedido(itens) {
  const centavos = itens.reduce((soma, i) => soma + Math.round(i.preco * 100) * i.qtd, 0);
  return centavos / 100;
}

export function atingiuPedidoMinimo(itens) {
  return totalDoPedido(itens) >= PEDIDO_MINIMO;
}

export function previsaoDeRetirada(itens) {
  const unidades = itens.reduce((soma, i) => soma + i.qtd, 0);
  return Math.min(10 + 2 * unidades, 45);
}

export function podeCancelar(pedido) {
  return pedido.status === 'recebido';
}
```

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| `eas` não é reconhecido, ou o PowerShell bloqueia scripts | terminal aberto antes da instalação, ou política de scripts do Windows | reabrir o terminal; usar o Prompt de Comando ou `npx eas-cli` |
| Build falha em "Install dependencies" | `package-lock.json` fora de sincronia ou pacote fora da versão do SDK | `npx expo install --check`; `npm install`, commit do lock e novo build |
| APK instala, mas "Network request failed" | falta o `usesCleartextTraffic`, ou a URL estava só no `.env` | conferir o plugin e o `env` do perfil; build novo |
| O navegador do celular não abre `http://<IP>:3000` | `json-server` preso ao `localhost`, ou rede que isola aparelhos | `npx json-server db.json --port 3000`; hotspot |
| Funcionou na escola, não em casa | o IP gravado no build é o da escola | outro build com o IP novo, ou o Expo Go |
| Ninguém consegue instalar o arquivo | build do perfil `production`, em `.aab` | `--profile preview` e mandar o link |
| Conflito no `projectId` do `app.json` | duas pessoas rodaram `eas build:configure` em contas diferentes | manter o do dono do build; apagar o projeto sobrando no expo.dev |
| Build parado em "Waiting in queue" | fila do plano gratuito | não cancelar nem reenviar; seguir com README e testes |
