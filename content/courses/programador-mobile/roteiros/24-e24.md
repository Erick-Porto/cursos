## Visão do encontro

**Objetivo:** abrir a unidade de React e o Projeto 4, o Livro de receitas. A turma sai do terminal e vai para a tela: entende o componente como peça de Lego, roda o kit com o Vite em `localhost:5173`, guarda o kit no Git e escreve o primeiro componente, o `CartaoReceita` fixo da pizza, em JSX, com as três regras, as chaves e uma peça do kit, a `Etiqueta`. Não há laboratório à parte: os passos do projeto são a prática do dia.

**Como a aula funciona:** cada conceito vem em três slides, como desde a aula 3. A seção (título e gancho) é a hora da conversa: leia o gancho, ouça duas ou três respostas e explique com a analogia indicada abaixo. O slide seguinte é a âncora, o que o aluno lê para revisar. Depois do conceito vem um slide **Projeto 4 · Passo K**: a turma faz junto com você, no próprio computador, e só segue quando o "Pronto quando" aparece na tela de todos. No fim, a **Sua vez** é feita sozinho, sem a solução no slide.

**Resultado ao fim das 4h:** cada aluno tem, na pasta de projetos, a `livro-de-receitas` (o kit renomeado) com o `npm install` feito, o `.gitignore` com `node_modules/` e `dist/`, o `src/components/CartaoReceita.jsx` e o `src/App.jsx` com o `import` do cartão e a `<div className="grade">` no lugar do aviso. Em `http://localhost:5173`, um cartão com a foto da pizza, "Pizza margherita", "Italiana, 35 minutos", "4 porções, nota 4.6" e a etiqueta verde "Fácil"; o Console sem mensagem vermelha. Dois commits, `Kit do livro de receitas` e `Projeto 4: etapa 1, kit e cartão fixo`, e o repositório público `livro-de-receitas` no GitHub, com o push feito. É a etapa 1 do Projeto 4.

**Pré-requisitos:** todo o JavaScript da grade, do E04 ao E22, e a Prova 1 no E23. Hoje entram como lembrete, em uma frase cada: scripts do npm (E04), `.gitignore`, commit e push (E05), template string (E06), `npx serve` e o endereço `localhost` (E12), `export default` e `import` (E16), a palavra `class` (E18). Novo hoje: React, componente, JSX e as regras dele, chaves no JSX e o Vite. Props, `map` com JSX e estado ficam para o E25 e o E26: não antecipe.

:::warning A turma sabe JavaScript, não sabe tela
Não explique de novo `const`, função ou `import`: cite o encontro e siga. O tempo de hoje vai para o novo: o kit rodando, o JSX e as regras dele. É o primeiro contato da turma com uma tela que ela mesma escreve.
:::

**Materiais:** projetor com o VS Code e o navegador lado a lado, fonte grande nos dois; Wi-Fi (o `npm install` baixa 19 pacotes, cerca de 47 MB por máquina, e as fotos das receitas vêm da internet); o [kit-receitas.zip](materiais/projeto-4/kit-receitas.zip) num pendrive, também numa versão com o `node_modules` já instalado, para quem ficar sem rede; a página do Projeto 4 aberta (página do curso, seção **Projetos**); o quiz publicado; os prints de referência da pasta do instrutor do Projeto 4 (`instrutor/prints/kit-desktop.png` e `etapa1-desktop.png`).

## Bloco 1 · O kit no navegador (80 min)

**"Palavras novas de hoje" (2 min).** Leia as cinco palavras com um exemplo rápido de cada. Não explique ainda: cada uma ganha a sua seção.

**"Projeto 4: o Livro de receitas" (5 min).** Abra a página do Projeto 4 no projetor. Mostre o desenho da tela, a linha do tempo das 4 etapas, a rubrica (seus componentes 25, lista e busca 20, favoritas 15, receitas da API 25, repositório e README 15; aprovação com 70) e o prazo, início do E29. **Seção "Componentes" (10 min).** Leia o gancho: com as mesmas peças de Lego, dá para montar um carro e uma casa? Esperado: sim, encaixando de outro jeito. "Componente é a peça de Lego: pequena, reaproveitável, encaixa em outras. O React monta a tela juntando peças." Em "React: a tela feita de peças", aponte no diagrama o `App` por fora, o `Cabecalho` no topo, os três cartões e o `Rodape`, e pergunte: "qual peça aparece três vezes?". Esperado: o `CartaoReceita`. "E quem escreve essa peça?" Vocês: é o contorno tracejado. Em "Componentes na prática", pergunte: "se o cartão tiver um erro, em quantos lugares vocês corrigem?". Um. Diga que o React é um pacote do npm, como o picocolors do E04, e que no E29 o React Native leva as mesmas ideias ao celular.

**Seção "O Vite" (8 min).** Leia o gancho: todo site precisa de um servidor; e se o servidor fosse o seu computador? Esperado: "precisa de internet?", "não dá". Retome a analogia do E01: "o servidor era a cozinha do restaurante, longe de vocês. O Vite liga uma cozinha dentro do computador de vocês, só para testar." Em "Vite: um servidor no seu computador", leia os três trabalhos e aponte o script `"dev": "vite"`: é o `npm run racha` do E04 com outro nome. Em "localhost: o endereço do seu computador", leia a saída linha por linha. Para a porta, uma frase: "o computador tem várias entradas numeradas; o Vite atende na 5173". Lembre o `npx serve` do E12: "lá era a porta 3000; aqui, a 5173". A recarga ao salvar fica para depois do passo 1, com o kit de cada um rodando.

**Projeto · Passo 1 (15 min).** É o passo mais lento do dia. Todos ao mesmo tempo, você no projetor. Circule nesta ordem:

:::steps
1. O zip baixado e extraído com **Extrair tudo**. Com dois cliques, o Windows só mostra o que tem dentro do zip, sem criar a pasta: o terminal não a encontra.
2. A pasta dupla `kit-receitas/kit-receitas`: entre na de dentro, a que tem o `package.json`, e renomeie essa.
3. O terminal termina em `livro-de-receitas` antes do `npm install`. Fora dela: `npm error enoent Could not read package.json`.
4. O `npm install` termina com `found 0 vulnerabilities`. As linhas `8 packages are looking for funding` e `run npm fund for details` são só um convite a doar para os autores dos pacotes; não é erro.
5. O `npm run dev` mostra `Local: http://localhost:5173/`; <kbd>Ctrl</kbd> + clique abre no navegador.
:::

Quem estiver sem internet recebe o kit do pendrive na versão com `node_modules` e pula o `npm install`. O "Pronto quando" é a página do print `kit-desktop.png`: cabeçalho, caixa tracejada e rodapé.

**"O Vite na prática" (5 min).** Agora, com o kit de todos rodando. Peça que cada um troque o texto do aviso no `App.jsx` (por exemplo, "Aqui vai a pizza") e salve, olhando o navegador: a página muda sem <kbd>F5</kbd>, e o terminal escreve `[vite] (client) hmr update /src/App.jsx`. Desfaçam. Depois, na sua máquina: <kbd>Ctrl</kbd> + <kbd>C</kbd> no terminal, <kbd>F5</kbd> no navegador e leia "Não é possível acessar esse site" e "A conexão com localhost foi recusada". `npm run dev` de novo e <kbd>F5</kbd>: volta. "O servidor é o terminal ligado. Fechou o terminal, fechou a cozinha."

**"O que tem no kit" (5 min).** Abra no VS Code cada arquivo da tabela enquanto lê. No `index.html`, a `<div id="root">` vazia; no navegador, <kbd>F12</kbd>, aba **Elements**: a mesma `<div id="root">`, cheia. "Quem preencheu foi o React, a partir do `main.jsx`: ele desenha o `App` dentro dessa caixa. O `main.jsx` vocês não mexem." Diga que `.jsx` é um arquivo JavaScript com JSX dentro e que o `receitas.js` entra no E25.

**Projeto · Passo 2 (10 min).** O segundo terminal primeiro: o botão **+** do painel do terminal; o do `npm run dev` continua ligado. Depois, o `.gitignore`, criado pelo painel do VS Code na raiz (não dentro de `src`), e os comandos do E05. No `git status`, confira mesa por mesa que `node_modules/` não aparece. No Windows, o `git add` mostra avisos `LF will be replaced by CRLF`: são sobre o fim de linha dos arquivos e não atrapalham. Quem tiver o Git sem nome e e-mail recebe `Author identity unknown` no commit: configure como no E01 e repita o commit.

Saída esperada do `git status` antes do commit (resumida): `On branch main`, `No commits yet` e a lista `new file:` com `.gitignore`, `README.md`, `index.html`, `package-lock.json`, `package.json`, `public/favicon.svg`, os arquivos de `src/` e o `vite.config.js`. São 20 arquivos; nenhum de `node_modules`.

**Seção "O primeiro componente" (8 min).** Leia o gancho: se vocês desenhassem um cartão de receita, o que poriam nele? Esperado: foto, nome, tempo, porções, ingredientes. Anote no quadro: é o cartão do projeto. "No código, a peça é uma função que devolve um pedaço de tela." Na pasta de demonstração, escreva a função do slide **dentro** do `App.jsx`, acima do `function App()`, e use `<Aviso />` duas vezes dentro do `<main>`: aparecem dois avisos. Pergunte: "por que `Aviso` começa com maiúscula?". A resposta está no slide: é assim que o React separa a peça da tag do HTML. Troque para `<aviso />`, salve e mostre: o aviso some, e o Console diz `<aviso /> is using incorrect casing`. Volte para a maiúscula. "Por enquanto a peça mora no mesmo arquivo; daqui a pouco, cada peça vai para o seu."

**"JSX: as tags da tela" (5 min).** "As tags depois do `return` são o HTML do E01, escrito dentro do JavaScript: é o JSX." Leia a tabela das tags. Para os parênteses do `return`: "quando a tela tem várias linhas, os parênteses dizem onde ela começa e onde termina".

**Folga (7 min).** Para quem ficou para trás nos passos 1 e 2: ninguém vai para a pausa sem o kit no navegador e o primeiro commit.

## Bloco 2 · O primeiro componente (75 min)

**"As três regras do JSX" e "As regras na prática" (12 min).** Na pasta de demonstração, no `Aviso`, quebre uma regra de cada vez, salve e leia o resultado com a turma antes de consertar:

:::steps
1. `<p class="aviso">`: a página funciona, e o Console diz ``Invalid DOM property `class`. Did you mean `className`?``. "A palavra `class` é a das classes do E18: o JSX precisa de outra." Abra **Elements**: com `className`, o HTML final mostra `class="aviso"`. O JSX só troca o nome na escrita.
2. Uma `<img src="pizza.webp">` sem a barra: a tela de erro do Vite, com `Expected corresponding JSX closing tag for 'img'.`, o arquivo e a linha. "No E01, a `<img>` ficava aberta; no JSX, fecha."
3. Duas tags soltas no `return`: `Adjacent JSX elements must be wrapped in an enclosing tag.` e a sugestão `Help: Did you want a JSX fragment <>...</>?`. Envolva com `<>` e `</>` e salve: a tela de erro some sozinha.
:::

Para o "um elemento pai", use a analogia do `return`: "a receita entrega um prato só; várias coisas vão juntas numa travessa". Em **Elements**, mostre que o fragmento do `App` não vira tag: dentro da `<div id="root">`, só o `<header>`, o `<main>` e o `<footer>`. Apague o `Aviso` da pasta de demonstração no fim.

**Seção "Importar componentes" (8 min).** Leia o gancho: na padaria, como o pão sai da vitrine e chega à sua mesa? Esperado: alguém pega e entrega. "É a vitrine do E16: o `export` põe na vitrine, o `import` pega de lá. Cada peça mora no seu arquivo." Em "export default e import", pergunte: "por que o `import` vem sem chaves?". Esperado: porque o arquivo usa `export default`, como no E16. Explique o `./` como "a partir da pasta deste arquivo". Em "Importar na prática", abra o `App.jsx` do kit e aponte os dois `import`; abra o `Carregando.jsx` e leia o manual da peça. Para o atributo: "o `src` diz à `<img>` qual foto mostrar; o `dificuldade` diz à `Etiqueta` qual etiqueta mostrar. No E25, esse atributo ganha nome: prop." Não entre em props hoje.

**Projeto · Passo 3 (15 min).** A turma cria `src/components/CartaoReceita.jsx` pelo painel do VS Code, **dentro** de `components`, e digita o cartão (não copia: digitando, aprende as tags). Depois, a linha do `export default` e as duas mudanças no `App.jsx`. Antes de salvar o `App.jsx`, pergunte: "o que vai sumir da tela, e o que vai aparecer?". Esperado: some o aviso, aparece o cartão. Circule procurando:

- o arquivo criado em `src` em vez de `src/components`: `Failed to resolve import "./components/CartaoReceita.jsx"`;
- o nome do arquivo diferente do `import` (`cartaoReceita.jsx`, `CartaoReceitas.jsx`): o mesmo `Failed to resolve import`;
- `class` no lugar de `className`: o cartão até aparece, mas o Console avisa;
- a `<img>` sem a barra do `/>`: a tela de erro do Vite;
- o `export default` esquecido: tela em branco, e o Console diz `does not provide an export named 'default'`. Às vezes a página só fica em branco depois de um <kbd>F5</kbd>.

O "Pronto quando" é o cartão do print do passo 3: a foto da pizza e "Pizza margherita" em negrito, à esquerda, numa coluna da grade.

**"O cartão em português" (5 min).** Leia linha por linha. Aponte o `alt`: "desligue o Wi-Fi e aperte <kbd>F5</kbd>: no lugar da foto aparece o texto do `alt`". Mostre o nome `cartao__foto`: "antes dos dois sublinhados, a peça; depois, a parte dela". O comentário no topo do `src/styles/cartao.css` lista todas as classes do cartão.

**Seção "Chaves no JSX" (10 min).** Leia o gancho: num cartaz, se vocês escreverem 20 + 15, aparece a conta ou o 35? Esperado: a conta, "20 + 15". "No JSX também: o texto aparece como está. As chaves abrem uma janela para o JavaScript, e o que está dentro dela é calculado." Lembre o `${ }` da template string do E06. Na pasta de demonstração, escreva a `Festa` do slide e salve: "Duas receitas rendem 16 porções". Tire as chaves e salve: aparece `porcoes * 2`, sem erro nenhum. Em "Chaves na prática", peça a turma para dizer o que aparece em cada linha antes de mostrar; a do `toFixed(2)` retoma o E04 ("20.00, com ponto").

**Projeto · Passo 4 (10 min).** Duas constantes antes do `return` e a linha `cartao__info`. Antes de salvar, pergunte: "o que aparece: 35 ou preparo + cozimento?". Circule procurando as constantes escritas fora da função (antes do `function`) ou depois do `return` e a conta sem chaves. O "Pronto quando" é "Italiana, 35 minutos", em cinza, embaixo do nome.

**"Quando aparece um erro" (5 min).** Lembre a luz do painel do carro e leia a tabela. Diga uma vez: "no Vite 8, o erro do Console também aparece no terminal do `npm run dev`, com `[vite] (client)` na frente". Pergunte quais deles a turma já viu hoje.

**Apresentação da Sua vez e da etapa pronta (5 min).** Projete "Projeto 4 · Sua vez" e leia as dicas em voz alta. Mostre que o manual da `Etiqueta` está no topo de `src/components/Etiqueta.jsx`, sem abrir o arquivo no projetor. Projete também "Etapa 1 pronta": o commit e o GitHub ocupam os 10 minutos finais da Sua vez.

## Projeto: sua vez (30 min)

**Enunciado:** o slide "Projeto 4 · Sua vez: complete o cartão". No `CartaoReceita`, uma segunda linha `cartao__info` com "4 porções, nota 4.6", feita com duas constantes novas, `porcoes` e `nota`, entre chaves; e a `Etiqueta` do kit com `dificuldade="Easy"`, dentro de uma `<div className="cartao__rodape">`, no fim do `cartao__corpo`.

**Organização:** individual, cada um no próprio computador, sem olhar a tela do vizinho nos primeiros 15 minutos. Depois, quem travou pode pedir ajuda a um colega, que explica sem digitar por ele.

**Marcos:** 3:15, a linha "4 porções, nota 4.6" na tela; 3:25, a etiqueta "Fácil" no cartão e o Console limpo; 3:35, a etapa pronta no GitHub.

**Etapa 1 pronta (os 10 minutos finais do bloco).** A partir de 3:25, todos param onde estão e fazem, no segundo terminal, o `git add .` e o commit `Projeto 4: etapa 1, kit e cartão fixo`. Depois, no GitHub, **New repository**: `livro-de-receitas`, **Public**, sem README e sem `.gitignore`; os três comandos que o GitHub mostra; e o push. Confira que o GitHub mostra os dois commits e que não há pasta `node_modules` na lista de arquivos. Quem terminar a Sua vez depois disso faz um commit novo e outro `git push`.

**O que observar:**

| O aluno fez | O que aparece | Pergunta para destravar |
|---|---|---|
| `const nota = 4,6` | tela de erro do Vite: `[PARSE_ERROR] Unexpected token`, na linha da constante | "no JavaScript, o número decimal usa ponto ou vírgula?" |
| esqueceu uma constante | tela em branco; Console: `ReferenceError: porcoes is not defined` | "onde o cartão guarda os 20 minutos de preparo?" |
| `from './components/Etiqueta.jsx'` | `Failed to resolve import "./components/Etiqueta.jsx" from "src/components/CartaoReceita.jsx"` | "em que pasta está o cartão? E a etiqueta?" |
| `import { Etiqueta } from ...` | tela em branco; Console: `does not provide an export named 'Etiqueta'` | "a `Etiqueta` sai com `export default`. Como fica o `import`?" |
| esqueceu o `import` da `Etiqueta` | tela em branco; Console: `ReferenceError: Etiqueta is not defined` | "como o `App` traz o cartão?" |
| `dificuldade=Easy`, sem aspas | tela de erro do Vite: `[PARSE_ERROR] Unexpected token` | "como o `src` da `<img>` recebe o endereço?" |
| a `Etiqueta` depois do `</article>` | `Adjacent JSX elements must be wrapped in an enclosing tag.` | "qual é o pai de tudo no cartão?" |
| `dificuldade="easy"`, minúsculo | aparece "easy", sem cor | "o que o manual da peça diz que ela aceita?" |

:::example Solução de referência
`src/components/CartaoReceita.jsx` no fim da etapa 1:

```jsx
import Etiqueta from './Etiqueta.jsx'

function CartaoReceita() {
  const preparo = 20
  const cozimento = 15
  const porcoes = 4
  const nota = 4.6

  return (
    <article className="cartao">
      <img
        className="cartao__foto"
        src="https://cdn.dummyjson.com/recipe-images/1.webp"
        alt="Pizza margherita"
      />
      <div className="cartao__corpo">
        <h2 className="cartao__nome">Pizza margherita</h2>
        <p className="cartao__info">Italiana, {preparo + cozimento} minutos</p>
        <p className="cartao__info">{porcoes} porções, nota {nota}</p>
        <div className="cartao__rodape">
          <Etiqueta dificuldade="Easy" />
        </div>
      </div>
    </article>
  )
}

export default CartaoReceita
```

`src/App.jsx` (o comentário das etapas, no topo, vem do kit e fica):

```jsx
// App.jsx: a tela do Livro de Receitas. É aqui que você trabalha.
//
// Etapa 1 (E24): troque o aviso pelo seu CartaoReceita, dentro de <div className="grade">.
// Etapa 2 (E25): o seu nome no Rodape e a lista das receitas, com map.
```

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| `'vite' não é reconhecido como um comando interno ou externo` | faltou o `npm install`, ou ele rodou em outra pasta | `npm install` dentro da `livro-de-receitas` |
| `npm error enoent Could not read package.json` | o terminal está fora da pasta do projeto, ou na pasta de fora do `kit-receitas/kit-receitas` | `cd` até a pasta que tem o `package.json` |
| `Vite requires Node.js version 20.19+ or 22.12+` | Node antigo, de outra instalação | instalar o Node LTS atual, como no E01, e reabrir o terminal |
| `Port 5173 is in use, trying another one...` e a página em `localhost:5174` | outro `npm run dev` ligado (às vezes num terminal escondido) | usar o endereço que o terminal mostrar, ou <kbd>Ctrl</kbd> + <kbd>C</kbd> no terminal antigo |
| a página não muda ao salvar | o arquivo não foi salvo (bolinha branca na aba do VS Code), ou o `npm run dev` foi desligado | <kbd>Ctrl</kbd> + <kbd>S</kbd>; conferir o terminal do Vite |
| "Não é possível acessar esse site" | o `npm run dev` está desligado | `npm run dev` de novo e <kbd>F5</kbd> |
| `git status` mostra `node_modules/` | `.gitignore` com outro nome (`gitignore.txt`, `.gitignore.txt`) ou dentro de `src` | renomear no painel do VS Code; o arquivo fica na raiz, ao lado do `package.json` |
| o cartão some; Console: `<cartaoReceita /> is using incorrect casing` | a tag da peça com inicial minúscula | `<CartaoReceita />`; o nome da função também com maiúscula |
| `[PARSE_ERROR] Unexpected token` na linha do `)` do `return` | o `return` sozinho na linha, sem o `(` logo depois | `return (` na mesma linha |
| aparece "preparo + cozimento minutos" | a conta ficou fora das chaves | `{preparo + cozimento}` |
| no lugar da foto, o texto "Pizza margherita" | sem internet, ou o endereço da foto digitado errado | conferir a rede e o `src` letra por letra |
