## Visão do encontro

**Objetivo:** fechar a Introdução ao ambiente React (E21 a E25). A turma revisa os oito temas da unidade consertando bugs ao vivo, treina com uma prova simulada, fecha a versão 1 do `minhas-tarefas` e faz a Prova 2.

**Pré-requisitos (E24):** `minhas-tarefas` com o commit "E24: efeitos e hooks próprios": `src/api/tarefas.js` com `URL_API` e `carregarTarefas(busca, sinal)`; `src/hooks/useTarefas.js`, que recebe a busca e devolve `tarefas`, `carregando`, `erro`, `recarregar` e as ações do E23; `src/hooks/useDebounce.js` ligado ao campo de busca (`busca` e `buscaAtrasada`); `src/hooks/useTituloDaAba.js`. **Encontro sem matéria nova:** a aula 49 só revisa. ## Abertura (15 min)

**Retomada do E24 (6 min)**, com a resposta esperada:

1. "Por que o efeito do `useTarefas` termina com `[busca, tentativa]` e o do título da aba com `[pendentes]`?" Esperado: todo valor que o efeito usa entra no array, e o efeito roda de novo quando um deles muda; `[]` só serve quando o efeito não usa nada do componente.
2. "No `useDebounce`, o que a limpeza `return () => clearTimeout(temporizador)` faz quando chega uma letra nova?" Esperado: cancela o agendamento da letra anterior; só o último sobrevive à pausa, e o `useTarefas` busca uma vez.
3. "Posso chamar o `useDebounce` dentro de um `if (busca !== '')`?" Esperado: não; hooks só no topo, porque React os conta pela ordem. Gancho: "Hoje vocês vão ver que cada tema da unidade cabe em um slide, e que os erros da prova são quase sempre os mesmos sete."

**Tarefa de casa (5 min):** abra dois repositórios do E24 e confira o commit "E24: efeitos e hooks próprios", `src/api/tarefas.js` e os três hooks em `src/hooks/`; digite "qui" depressa na busca de um deles, com a aba Rede aberta: uma requisição só. Comente as duas questões mais erradas do quiz E24; as candidatas são as dependências do efeito e as regras dos hooks, e as duas voltam na prova.

**Objetivos (4 min):** projete "Mapa da revisão" e anuncie: "Revisão de 50 minutos, prova simulada de 45, laboratório de 40 para fechar a versão 1 e, às 3:00, a Prova 2. Hoje não tem matéria nova." Peça que todos testem o login no sistema agora.

## Bloco 1 · Revisão por tema (50 min)

**"Mapa da revisão": o semáforo (5 min).** Cada aluno escreve os oito temas na folha e marca cada um: verde (sei explicar), amarelo (sei fazer, não sei explicar) ou vermelho (travo). Peça mãos para os vermelhos, tema por tema, e anote no quadro. Os dois temas mais vermelhos ganham o dobro de tempo; os verdes, só a pergunta.

**Slides "Por que React" a "Hooks próprios" (40 min, cerca de 5 por tema).** Não reensine. Em cada slide, uma pergunta para a turma e um **bug ao vivo** no projeto de demonstração: você quebra o código, a turma prevê o sintoma antes de você salvar e diz o conserto; depois, `Ctrl + Z`.

| Slide | Pergunta (resposta esperada) | Bug ao vivo |
|---|---|---|
| Por que React | "No modelo declarativo, quem atualiza o DOM?" (React, a partir do estado) | Sem bug: aba Elements aberta, adicione uma tarefa e mostre o `<li>` novo surgindo, sem nenhum `querySelector` no código |
| Projeto Vite e JSX | "Qual arquivo liga o `App` à página?" (`src/main.jsx`) | No `Cabecalho`, apague o `<header>` e deixe o título e o contador soltos: a tela de erro do Vite; a turma lê arquivo, linha e mensagem |
| Componentes e props | "O filho pode alterar uma prop? O que é `children`?" (não; o conteúdo entre as tags) | No `ListaTarefas`, troque `titulo={t.titulo}` por `title={t.titulo}`: cartões sem título e nenhum erro no console |
| Listas, keys e estilos | "Por que o índice é uma `key` ruim?" (ele marca a posição, não a tarefa) | Apague o `key={t.id}`: o aviso no console |
| Eventos e estado | "`onClick={remover(id)}` roda quando?" (ao desenhar, não no clique) | No `adicionarTarefa`, dentro do `useTarefas`, troque o spread por `tarefas.push(nova)` e `setTarefas(tarefas)`: a tarefa não aparece. Conclua outra tarefa: a nova surge junto, porque o `map` criou um array novo com ela dentro |
| Formulários controlados | "Por que `value` sem `onChange` trava o campo?" (o estado nunca muda) | Apague o `onChange` do campo de título: nada do que você digita aparece, e o console avisa |
| Efeitos e fetch | "Por que o `npm run dev` mostra duas requisições?" (o StrictMode monta duas vezes; a limpeza cancela a primeira) | Apague o array de dependências do efeito no `useTarefas` por 5 segundos, com a aba Rede aberta: enxurrada de requisições |
| Hooks próprios | "Dois componentes que chamam `useTarefas()` dividem a lista?" (não: cada chamada tem estados próprios) | Apague a limpeza do `useDebounce` e digite "qui" depressa, com a aba Rede aberta: três requisições em vez de uma. Se sobrar tempo, ponha o `useDebounce` dentro de um `if (busca !== '')`: o lint acusa, e a primeira letra derruba o app com `Rendered more hooks than during the previous render` |

**Semáforo de novo (5 min).** "Quem ainda tem vermelho?" Anote os nomes: eles são os primeiros que você atende na pausa.

:::tip Ritmo
Tema todo verde fica só com a pergunta, sem bug. Nunca corte os bugs de "Eventos e estado", "Efeitos e fetch" e "Hooks próprios": são os que mais caem na prova.

**Circule observando:** o `useState('todas')` no topo, junto dos outros hooks; o contador e o título da aba contam **todas** as tarefas, não só as visíveis; filtro e busca se combinam ("Pendentes" com "qui"); o botão do filtro ativo se destaca por mais que a cor; `npm run lint` e console sem avisos.

:::example Solução de referência
`src/components/FiltroTarefas.jsx`: os três botões saem de um `map`, e o ativo ganha uma classe própria.

```jsx
import estilos from './FiltroTarefas.module.css'

const OPCOES = [
  { valor: 'todas', rotulo: 'Todas' },
  { valor: 'pendentes', rotulo: 'Pendentes' },
  { valor: 'concluidas', rotulo: 'Concluídas' },
]

function FiltroTarefas({ filtro, onMudar }) {
  return (
    <div className={estilos.filtro}>
      {OPCOES.map((opcao) => (
        <button
          key={opcao.valor}
          type="button"
          className={filtro === opcao.valor ? estilos.ativo : ''}
          onClick={() => onMudar(opcao.valor)}
        >
          {opcao.rotulo}
        </button>
      ))}
    </div>
  )
}

export default FiltroTarefas
```

`src/components/FiltroTarefas.module.css`: o ativo fica em negrito e sublinhado, não só colorido.

```css
.filtro {
  display: flex;
  gap: 8px;
  margin: 12px 0;
}

.ativo {
  font-weight: 700;
  border-bottom: 3px solid currentColor;
}
```

`src/App.jsx`, o topo. O filtro é um estado da tela, então mora no `App`, ao lado da busca; a busca continua no servidor, pelo `useTarefas`, e o filtro age sobre a lista que ele devolve.

```jsx
function App() {
  const [busca, setBusca] = useState('')
  const buscaAtrasada = useDebounce(busca, 300)
  const { tarefas, carregando, erro, recarregar,
    adicionarTarefa, alternarConcluida, removerTarefa } = useTarefas(buscaAtrasada)
  const [filtro, setFiltro] = useState('todas')

  function passaNoFiltro(t) {
    if (filtro === 'pendentes') return !t.concluida
    if (filtro === 'concluidas') return t.concluida
    return true
  }

  const visiveis = tarefas.filter(passaNoFiltro)
  const pendentes = tarefas.filter((t) => !t.concluida).length
  useTituloDaAba(`(${pendentes}) Minhas Tarefas`)
```

No JSX do `App`, o filtro entra acima da lista, e a lista recebe `visiveis` no lugar de `tarefas`. As ações continuam vindo do `useTarefas`, que trabalha sobre a lista completa; a mensagem de lista vazia do `ListaTarefas` (E22) cobre o filtro sem resultado.

```jsx
<FiltroTarefas filtro={filtro} onMudar={setFiltro} />
{carregando ? (
  <p>Carregando...</p>
) : (
  <ListaTarefas tarefas={visiveis} onAlternar={alternarConcluida} onRemover={removerTarefa} />
)}
```

README, no mínimo: o título "Minhas Tarefas"; uma frase sobre o app (lista de tarefas em React com Vite, feita no curso Programador Mobile); o que ele faz (carrega tarefas da JSONPlaceholder, adiciona, conclui e remove, busca por título e filtra por situação); como rodar (`npm install` e depois `npm run dev`); e o limite da v1: a API de testes não guarda o que você adiciona.
:::

**Critérios:** base do E24 funcionando; três botões de filtro, com o ativo destacado; filtro e busca combinados; contador e título da aba sobre a lista completa; mensagem de lista vazia; `npm run lint` e console sem erros; README com o que o app faz e como rodar; commit `v1 web` antes das 3:00.

**Coleta:** o aluno envia o link do repositório, como nos encontros anteriores. Durante a prova, abra cada repositório no GitHub, em "Commits", e confira: `v1 web` anterior às 3:00, `src/hooks/` com os hooks do E24, `FiltroTarefas.jsx` e `node_modules` fora do repositório. ## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| "Concluídas" mostra a lista vazia | O `valor` do botão e o `if` não batem (`'concluídas'` com acento de um lado) | Os dois textos precisam ser iguais; valores sem acento, o acento só no `rotulo` |
| `Rendered more hooks than during the previous render` | `useState('todas')` escrito depois de um `return` antecipado, como `if (carregando) return ...` | Todos os hooks no topo; os `return` depois deles (aula 48) |
| O contador de pendentes ou a aba mudam ao filtrar | `pendentes` calculado sobre `visiveis` | Conte sobre `tarefas`, a lista completa |
| Tarefa adicionada some depois de uma busca | A JSONPlaceholder não guarda o que você adiciona (aula 48) | Comportamento esperado da v1; vai para o README como limite |
| Clicar no filtro recarrega a página | Botões do filtro dentro do `<form>`, sem `type="button"` | Tire o filtro do formulário ou use `type="button"` |
| Aviso de `key` no console | `map` dos botões sem `key` | `key={opcao.valor}` |
| `Failed to fetch` com Wi-Fi funcionando | API fora do ar ou bloqueada pela rede da escola | Troque o `URL_API` de `src/api/tarefas.js` por `'/tarefas.json'` |
| `git push` recusado ou pedindo senha | Token expirado ou remoto errado | `git remote -v`; refaça o login; se não resolver, push de casa |
