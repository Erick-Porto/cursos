## Visão do encontro

**Objetivo:** abrir a unidade Classes e estruturas de controle aprofundando as decisões. A turma já escreve `if`, `else` e faixas com `else if` (E07a) e conhece o ternário e o curto-circuito (E05b); hoje ela escreve decisões corretas e fáceis de ler e as aplica às regras da Lojinha que escolhem um caminho: parcelas, status do pedido, frete por região e cupom. No fim, abrir o Projeto 3 (Lista de tarefas), o mais difícil do Módulo Básico: até o E20, ele aplica as decisões, os laços, as classes, os erros e o assincronismo da unidade numa lista de tarefas com a tela feita pelo aluno no DOM.

**Slides de seção:** cada conceito abre com um slide que traz o nome dele e uma frase de gancho, no centro ("Guard clauses: num show, o segurança barra quem não tem ingresso na porta ou lá dentro?"). É a hora da conversa: leia o gancho, ouça duas ou três respostas e explique com a analogia; o que dizer em cada seção está abaixo. O slide seguinte, a âncora, ensina o mesmo conceito por escrito, com a analogia e a forma de usar; depois vem um slide "na prática", com dois ou três casos de uso e a saída de cada um. Em aula, passe pela âncora apontando o que acabou de dizer, sem ler tudo, e rode os casos de uso. As analogias são as do curso: a bifurcação na estrada para o `if`, o menu da central de atendimento para o `switch`, a caixa vazia que ainda é caixa para o truthy, o campo em branco do formulário para o `??` e o segurança na porta para a guard clause.

**Resultado ao fim das 4h:** no `lojinha-regras`, `src/regras/pedido.js` (status e cupom), `maximoDeParcelas` em `precos.js` e o `calcularFrete` completo em `frete.js`, com 15 testes novos passando e os do E10 atualizados; `node src/scripts/pedidos.js` imprime o relatório de status. O `resumoDoCarrinho` com cupom e o `resumo-do-carrinho.js 01310-100 bemvindo10` ficam para casa. Commit "E13: frete, status e cupom". No Projeto 3, cada aluno com o repositório `lista-de-tarefas` criado a partir do ponto de partida e a etapa 1 (prazo e prioridade) começada.

**Pré-requisitos:** `lojinha-regras` do E12 com `npm test` e `npm run lint` verdes. Em uso hoje: `formatarPreco` (E05), `paraCentavos`, `paraReais` e `calcularDesconto` em `src/regras/precos.js` (E05), `ehCepValido` em `src/utils/validar.js` (E06), `subtotal` (E07) e `contarItens` (E09) em `src/regras/carrinho.js`, o dicionário `rotulosDeOrdem` (E08) e, do E10, `src/regras/frete.js` (`FRETE_GRATIS_A_PARTIR_DE`, o `calcularFrete` simples e o `calcularFreteComCache`), `somarReais` e `resumoDoCarrinho` com o script `src/scripts/resumo-do-carrinho.js`. ## Bloco 1 · Decisões com if, else e switch (50 min)

**"O que você vai aprender", "Palavras novas de hoje" e "Um pedido, muitas decisões" (4 min).** Leia as seis palavras novas, uma frase cada. Na pergunta do slide, liste as respostas no quadro. Esperado: frete, parcelas, cupom, status, estoque, logado ou visitante. Circule parcelas, status, frete e cupom: "esses viram código hoje".

**Seção "Faixas e bordas" (8 min).** Leia o gancho: "no dia exato em que faz 18 anos, a pessoa já pode tirar a carteira?". Esperado: sim; no dia do aniversário, já pode. "Esse dia exato é a borda: o valor em que uma faixa termina e a próxima começa. E o `else if` é a estrada com várias saídas: vale a primeira que combina." Em "Faixas: o else if", revisão rápida, sem reexplicar: pergunte quantas parcelas o Fone de R$ 199,90 recebe e por que a ordem das faixas importava no E07a. Esperado: 3; o `else if` para no primeiro `true`. Na `e13-rascunho`, cole `maximoDeParcelas` com `export` no fim de `precos.js`, os testes no fim de `precos.test.js` e rode `npm test -- precos`: verde. Inverta as faixas e rode de novo: os dois testes ficam vermelhos. "No E07a, o script rodava sem reclamar. O teste reclama na hora." Desfaça. Em "Faixas na prática", pergunte o que sai com `49.99` e com `50` antes de mostrar: `1` e `3`.

**"Pense" (6 min).** 2 minutos em duplas, sem rodar. Esperado: "Boa" para 4.6, e ninguém ganha "Excelente". Cole a função no REPL e chame com `4.6`, `4.2` e `3.5`. Peça a uma dupla que reordene em voz alta. Esperado: `>= 4.5`, `>= 4`, `>= 3`. Escreva a regra no quadro: com `<`, da menor faixa para a maior; com `>=`, da maior para a menor.

**Seção "switch" (8 min).** Leia o gancho: "na central de atendimento, o que acontece quando você digita 2?". Esperado: vai direto para o setor 2; o que não está no menu cai em "outros assuntos". "O `switch` é esse menu: um valor comparado com cada opção, e o `default` é o 'outros assuntos'." No REPL, escreva `textoDoStatus` (o `switch` do slide dentro de `function textoDoStatus(status) { }`) e chame com `'enviado'`, `'Pago'` e `undefined`, os casos de "switch na prática". Esperado: "A caminho" e duas vezes "Status desconhecido". Pergunte por que `'Pago'` caiu no `default`. Esperado: o `case` compara com `===`, como no E05, e maiúscula é outro texto. Em "Os cinco status de um pedido", aponte a tabela do quadro e explique o tom: "hoje ele vai entre colchetes no relatório; no E30, escolhe a cor do selo no app".

**Seção "Cascata" (12 min).** Leia o gancho: "a água que cai numa cascata para no primeiro degrau?". Esperado: não; desce até o fim. "Sem `break`, a execução desce assim, `case` por `case`, até achar uma saída." No REPL, `let status = 'pendente'; let tom;` e o `switch` sem `break`: o `tom` sai `'perigo'`. Acrescente o `break` e repita. Projete a animação da cascata e pergunte, antes de ela chegar ao `break`, se o `case 'cancelado'` compara o `status`. Esperado: não; sem `break`, a execução só desce. Escreva `tomDoStatus` e pergunte, antes de rodar, o que `tomDoStatus('pago')` devolve. Esperado: `'sucesso'`. Quem disser `undefined` acha que `case` vazio não faz nada: o quiz volta a isso.

Em "O relatório de pedidos", o caso de uso das duas funções: na `e13-rascunho`, crie `src/regras/pedido.js` com as duas funções (com `export`) e `src/scripts/pedidos.js` com o código do slide. Rode `node src/scripts/pedidos.js`. Pergunte o que aconteceria sem o `default` de `textoDoStatus`. Comente o `default` e rode de novo: `#1044  undefined  [neutro]`. Desfaça. "O status novo da API não pode estragar o relatório."

**Seção "if, switch ou dicionário" (3 min).** Leia o gancho: "martelo, chave de fenda ou alicate: o que decide qual ferramenta pegar?". Esperado: o trabalho que você vai fazer. "Com as decisões é igual: a forma da pergunta escolhe a ferramenta." Lembre o `rotulosDeOrdem` do E08 e pergunte quando cada forma ganha. Esperado: faixas pedem `if`; um valor contra opções com grupos, `switch`; tradução pura, dicionário. "Cada decisão na prática" fica para leitura.

**Seção "Truthy e falsy" (6 min).** Leia o gancho: "uma caixa vazia ainda é uma caixa?". Esperado: é. "Para o `if`, o `[]` é uma caixa vazia: ainda conta como 'sim'. Já o `0`, o `''` e o `null` contam como 'não'." Os seis falsy são do E05b: não reexplique, vá direto às pegadinhas de "Truthy e falsy na prática". No REPL: `Boolean('0')`, `Boolean([])` e `Boolean(' ')`, todos `true`. Depois `const desconto = 0;` e `desconto && 'Desconto: R$ 0,00'`: o REPL mostra `0`. Pergunte o que um `console.log` disso imprime num resumo. Esperado: um `0` solto. Por fim, `'enviado' === 'pago' || 'entregue'` devolve `'entregue'`, um texto truthy: "a condição vale para qualquer status" (está nos erros comuns).

**"Pratique" (2 min).** Individual, no caderno. Esperado: a resposta do slide. Para quem escrever `if (!frete)`: "e quando o frete for grátis?".

**"Erros comuns" a "Próximos passos" (1 min).** Leitura rápida.

:::tip Ritmo
Se atrasar, mostre o fall-through só no slide e fale o "if, switch ou dicionário?" sem REPL. O "Pense" do `>=` e o `0` do `&&` não se cortam: são os erros que mais aparecem no laboratório.
:::

## Bloco 2 · Condições legíveis (50 min)

**"O que você vai aprender", "Palavras novas de hoje" e "Uma regra difícil de ler" (4 min).** Leia as seis palavras novas, uma frase cada. Projete a pirâmide e faça a pergunta do slide valendo tempo. Esperado: `null` quando o CEP é vazio, `null` ou `undefined`, ou está fora do formato do `ehCepValido` do E06. Anote o tempo no quadro.

**Seção "Ternário" (5 min).** Leia o gancho: "na frase '1 item' ou '3 itens', quem escolhe a palavra certa?". Esperado: a quantidade; se for 1, item, senão, itens. "O ternário é essa escolha numa linha: leia o `?` como 'então' e o `:` como 'senão'." O ternário é do E05b: pergunte só onde ele cabe. Esperado: num `const`, num `return`, dentro do `${ }`. Em "Ternário na prática", leia os três casos. Mostre o par "ruim" e "melhor" de "Ternário ou if?": "o ternário escolhe um valor; passos diferentes pedem `if`". Peça a alguém que leia o ternário aninhado em voz alta. "Três resultados: função com `if`, a `textoDoFrete` da aula 25."

**Seção "O operador ??" (3 min).** Leia o gancho: "num formulário, quem responde '0 filhos' deixou o campo em branco?". Esperado: não; zero é uma resposta. "O `??` só troca o campo em branco, `null` e `undefined`; o `||` troca até o zero." No REPL: `0 || 'Informe o CEP'`, `0 ?? 'Informe o CEP'` e `'' ?? 'x'`. "O `||` do E05b troca qualquer falsy; o `??`, só o que falta." A nota zero de "?? na prática" fecha a ideia.

**Seção "O operador ?." (3 min).** Leia o gancho: "se o pedido é para retirar na loja, qual é o CEP da entrega?". Esperado: nenhum; não há entrega. "O `?.` olha antes de entrar: sem entrega, devolve `undefined` em vez de quebrar." No REPL, `const pedido = { id: 1042, status: 'pago' };` e `pedido.entrega.cep`: `TypeError`. Leia a mensagem com a turma: `Cannot read properties of undefined (reading 'cep')` diz o que faltou e o campo que você tentou ler. Repita com `?.` e com `?? 'Retirada na loja'`. Em "?. na prática", o caso 2 é o que o `validarCupom` vai usar: `codigo?.trim()` com o cupom que não foi digitado.

**"Pratique" (4 min).** Em duplas, sem rodar; corrija item a item no REPL. O item 3 é o que mais erra: com `??`, o `''` continua `''`.

**Seção "Condições com nome" (3 min).** Leia o gancho: "o que se entende mais rápido: 'frete grátis' ou 'subtotal >= 150'?". Esperado: "frete grátis". "Dar nome à condição é pôr etiqueta na caixa do sim ou não." Leia o "antes" e pergunte o que a linha decide; leia o "depois". "O frete grátis passou para R$ 199: quantos lugares você altera?" Esperado: um, a `FRETE_GRATIS_A_PARTIR_DE` do E10. "E se a regra do CEP mudar?" Esperado: só o `ehCepValido`, do E06. "Condições com nome na prática" fica para leitura.

**Seção "Frete por região" (5 min).** Leia o gancho: "por que o frete para Rio Branco custa mais que para São Paulo?". Esperado: é mais longe. "O primeiro dígito do CEP diz a região, e o dicionário traduz a região em frete." Compare a tabela do quadro com o `FRETE_POR_DIGITO` linha a linha, com a turma lendo os valores. Em "Dicionário na prática", rode no REPL `FRETE_POR_DIGITO['6']` e `FRETE_POR_DIGITO[6]`: o mesmo valor.

**Seção "Guard clauses" (12 min).** Leia o gancho: "num show, o segurança barra quem não tem ingresso na porta ou lá dentro?". Esperado: na porta. "A guard clause é o segurança: barra o caso inválido na entrada, com `return`, e o resto da função só cuida de quem passou." Leia "As guardas em português". Depois, refatoração ao vivo na `e13-rascunho`, protegida pelos testes:

:::steps
1. Abra a pirâmide e o `frete.test.js` do ponto de partida e rode `npm test -- --watchAll frete`: os 4 testes passam.
2. Escreva no topo da função `const cepValido = ehCepValido(cep ?? '');` e `if (!cepValido) return null;`. Salve: verde.
3. Apague o `if (cep)` e o `if (ehCepValido(cep))` com seus `else`. Verde.
4. Escreva a guarda do frete grátis com a constante e deixe o `digitos` e o `return` da região no fim. Verde.
5. Quebre de propósito: troque a ordem das duas guardas. "CEP inválido devolve null, mesmo acima de R$ 150" fica vermelho. Pergunte por quê antes de explicar.
6. Desfaça e repita a pergunta do início do bloco: agora a resposta sai em segundos.
:::

Feche com o fluxograma de "O caminho das guardas": peça a um aluno que siga com o dedo `calcularFrete(200, '1234')`. Esperado: sai na primeira guarda, com `null`, antes de chegar ao frete grátis; é o teste que ficou vermelho no passo 5. Lembre que o `calcularFreteComCache` do fim do arquivo continua igual: ele memoriza a função que estiver ali. Em "Guard clauses na prática", peça a saída das quatro chamadas antes de mostrar.

Em "Testes nas bordas": "Sem esse teste, a Lojinha prometeria entrega grátis num CEP que não existe." Pergunte que bordas faltam. Esperado: `149.99`, CEP com 7 e 9 dígitos, CEP com espaços, um valor de cada faixa. Abra o `frete.test.js` do E10 na `main`: "outros CEPs pagam R$ 19,90" usa um CEP do Rio, que agora paga R$ 14,90. "Quando a regra muda de propósito, o teste muda junto, no mesmo commit. Apagar o teste é perder a especificação."

**Seção "O cupom" (6 min).** Leia o gancho: "quantos motivos uma loja tem para recusar um cupom?". Esperado: código errado, cupom vencido, compra pequena, nada digitado. "Cada motivo vira uma guarda, com a sua mensagem." Leia "O cupom em português" e os três casos de "Cupom na prática". As duas guardas em comentário ficam para o laboratório. Na `e13-solucao`, rode o `resumo-do-carrinho.js` sem argumentos, com `01310-100`, com `01310-100 bemvindo10` e com `1234 NATAL25`. Pergunte por que `codigo === undefined ? null : ...` e não `validarCupom(codigo, valorItens)` direto. Esperado: sem cupom digitado, o resumo não deve imprimir "Digite o código do cupom". Depois: "com a Garrafa e o Livro (R$ 139,80), o `LOJINHA20` vale. E com só o Livro de Receitas?" Esperado: R$ 59,90, abaixo do mínimo: "Válido em compras a partir de R$ 100". Mostre o `TypeError` do `formatarPreco(null)`: troque `textoDoFrete(resumo.frete)` por `formatarPreco(resumo.frete)` e rode sem CEP. Desfaça.

**"Quando aparece um erro" a "No laboratório" (1 min).** Leitura rápida: a tabela de mensagens é a que a turma vai consultar no laboratório.

**Desafio que prepara o laboratório (4 min).** Em duplas: "Antes de escrever `validarCupom`, escrevam a tabela de testes: código, subtotal e resultado." Recolha no quadro. Esperado: `'BEMVINDO10'` com R$ 199,90 dá 19,99; `'  bemvindo10 '` também vale; `'LOJINHA20'` com R$ 129,80 dá 20, com R$ 100 vale e com R$ 99,90 é recusado; `''`, `'   '`, `null` e `undefined` pedem o código; `'DESCONTO50'` não existe; `'NATAL25'` expirou. Essa tabela vira o `pedido.test.js`.

:::tip Ritmo
Se atrasar, pule o `FRETE_POR_DIGITO['6']` no REPL e faça o "Pratique" em voz alta. A refatoração com testes e o desafio não se cortam: são o modelo do laboratório.

## Laboratório (55 min)

**Enunciado:** os passos do slide "No laboratório" da aula 26, com a tabela de testes do desafio, menos o passo 6: o `resumoDoCarrinho` com cupom e o script que lê CEP e cupom do terminal ficam para casa. As regras que ele junta já estão testadas nos passos 3 a 5, e nenhum encontro até o E20 usa o script. O `frete.js` refatorado ao vivo é o modelo.

```javascript
export const FRETE_GRATIS_A_PARTIR_DE = 150;

// primeiro dígito do CEP: valor do frete em reais
const FRETE_POR_DIGITO = {
  0: 9.9, // SP
  1: 9.9, // SP
  2: 14.9, // RJ e ES
  3: 14.9, // MG
  4: 19.9, // BA e SE
  5: 19.9, // PE, AL, PB e RN
  6: 24.9, // CE, PI, MA, PA, AP, AM, RR e AC
  7: 19.9, // DF, GO, TO, MT, MS e RO
  8: 14.9, // PR e SC
  9: 14.9, // RS
};

export function calcularFrete(subtotal, cep) {
  const cepValido = ehCepValido(cep ?? ''); // do E06
  if (!cepValido) return null;
  if (subtotal >= FRETE_GRATIS_A_PARTIR_DE) return 0;

  const digitos = cep.replace(/\D/g, '');
  return FRETE_POR_DIGITO[digitos[0]];
}

export function textoDoFrete(frete) {
  if (frete === null) return 'Informe o CEP';
  if (frete === 0) return 'Grátis';
  return formatarPreco(frete);
}
```

```javascript
const CUPONS = {
  BEMVINDO10: { tipo: 'percentual', valor: 10, minimo: 0, ativo: true },
  LOJINHA20: { tipo: 'fixo', valor: 20, minimo: 100, ativo: true },
  NATAL25: { tipo: 'percentual', valor: 25, minimo: 0, ativo: false },
};

function recusar(mensagem) {
  return { valido: false, desconto: 0, mensagem };
}

export function validarCupom(codigo, subtotal) {
  const chave = codigo?.trim().toUpperCase() ?? '';
  if (chave === '') return recusar('Digite o código do cupom');

  const cupom = CUPONS[chave];
  if (!cupom) return recusar('Cupom não encontrado');
  if (!cupom.ativo) return recusar('Este cupom expirou');
  if (subtotal < cupom.minimo) return recusar(`Válido em compras a partir de R$ ${cupom.minimo}`);

  // o percentual usa o calcularDesconto do E05, em centavos: 10% de 199,90 = 19,99
  const desconto =
    cupom.tipo === 'percentual' ? calcularDesconto(subtotal, cupom.valor) : cupom.valor;
  return { valido: true, desconto, mensagem: `Cupom ${chave} aplicado` };
}
```
