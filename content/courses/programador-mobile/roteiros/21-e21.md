## Visão do encontro

**Objetivo:** abrir a unidade Introdução ao ambiente React. A turma sai do terminal e vai para a tela: entende por que atualizar o DOM na mão gera bugs (o que ela acabou de fazer no Projeto 3), o que é código declarativo e o que é um componente, e cria o `minhas-tarefas` com Vite, com os primeiros componentes em JSX. O Projeto 4 (Livro de receitas) começa hoje, com a etapa 1.

**Slides de seção:** cada conceito vem em três slides. O primeiro, a seção, tem só o nome do conceito e uma frase de gancho, no centro ("Componentes" e "Com as mesmas peças de Lego, dá para montar um carro e uma casa?"). É a hora da conversa: leia o gancho, ouça duas ou três respostas e explique com a analogia indicada abaixo. O segundo explica o que é e como usar, por escrito, para quem estuda para as provas; em aula, passe por ele apontando o que acabou de dizer. O terceiro, "... na prática", mostra casos de uso com o resultado: rode um deles ao vivo ou leia o resultado do slide. As analogias de hoje ficam até o fim do curso: o DOM é a casa montada a partir da planta (o HTML), o componente é a peça de Lego, o Vite é a cozinha já montada.

**Resultado ao fim das 4h:** repositório público `minhas-tarefas` com dois commits ou mais, sem `node_modules`; `npm run dev` e `npm run lint` sem erros; `App` montado com `Cabecalho` e `Rodape` em `src/components`. Do Projeto 4, cada aluno sai com o `livro-de-receitas` criado e o `Cabecalho` começado; a etapa 1 completa (cartão fixo, README e push) fica para casa, até o E22.

**Pré-requisitos (E01 a E20):** Node.js LTS, VS Code e Git instalados e em uso desde o E01; `package.json` e scripts (E02); `npx` (E03); `add`, `commit`, `push`, repositório no GitHub e lint (E03); funções e arrow functions (E07), `map`, `filter` e desestruturação (E09), callbacks (E10), módulos com `import` e `export` (E11); Prova 1 no E20. Novos hoje: DOM, React, Vite e JSX.

**Materiais:** projetor com editor, terminal e navegador lado a lado; Wi-Fi para `npm install` em massa (o `node_modules` do projeto tem cerca de 90 MB); um computador por aluno; [demos-e21.zip](materiais/e21/demos-e21.zip) com o `contador.html` dos slides; a [versão do aluno do contador](materiais/e21/aluno/contador.html), ligada pelo slide; quiz `quiz-e21` publicado; pendrive com um `minhas-tarefas` recém-criado, com `node_modules`; a página do Projeto 4 no sistema (página do curso, **Projetos**), com o enunciado e o guia de correção.

:::warning A turma sabe JavaScript, não sabe tela
Do E05 ao E20, tudo saiu no terminal. Não explique de novo `const`, arrow function, `map` nem módulos: cite o encontro e a analogia ("a desestruturação do E09", "o `filter`, a peneira") e siga. O que precisa de tempo hoje é o novo: o DOM, a ideia de declarar a tela e as regras do JSX.
:::

## Bloco 1 · Por que React (50 min)

**"O que você vai aprender", "Palavras novas de hoje" e "Por que isso importa" (3 min).** Leia as seis palavras em voz alta, com um exemplo rápido de cada. Deixe a pergunta do terceiro slide no ar por 30 segundos, sem responder: a resposta é a aula.

**Seção "O DOM" (15 min).** Leia o gancho: se vocês mudam um móvel de lugar, a planta da casa muda junto? Esperado: não. "O HTML é a planta; o DOM é a casa montada na memória do navegador. O JavaScript muda os móveis; a planta fica igual." Em "O DOM na prática", digite as três linhas no Console, com a versão do aluno aberta, e aperte `F5` no fim: o número volta a 0. Depois, demonstre com o `contador.html` da pasta `demos-e21/`:

:::steps
1. Abra o arquivo no navegador e clique três vezes.
2. `F12`, aba **Elements**: mostre o `<span id="total">` e o número mudando a cada clique. "O DOM é esta árvore. Vocês a editaram no E01; hoje é o JavaScript da página que mexe nela."
3. Aba **Console**: `document.querySelector('#total')` e Enter. O elemento aparece e, ao passar o mouse, fica destacado na página. "O `#` é o mesmo do seletor de CSS: procure pelo id."
4. Ainda no Console: `document.querySelector('#total').textContent = 99`. A tela mostra 99. Digite `total`: continua 3. Clique: vira 4. "Tela e dado são duas coisas separadas."
5. No VS Code, comente a linha `span.textContent = total`, salve, recarregue e clique três vezes: a tela mostra 0; no Console, `total` vale 3. "A variável mudou; a tela não. Manter os dois em dia é trabalho seu." É o bug de uma questão do quiz.
:::

O resto do código é lembrete, não aula: leia "O contador em português" linha por linha. A `let` é a caixa com etiqueta que deixa trocar o conteúdo, do E05; a arrow function passada ao `addEventListener` é um callback, como os do E10 e o `setTimeout` do E18: "o navegador guarda a função e a chama a cada clique".

A turma acompanha pela [versão do aluno](materiais/e21/aluno/contador.html), aberta pelo link do slide: o mesmo contador com um quadro "Na memória" (quem está sem DevTools vê o valor de `total`), uma chave que desliga a linha sem editar código e a explicação linha por linha. Peça que repitam os quatro passos da página junto com você.

Em "O problema cresce com a tela", pergunte: "Para remover uma tarefa, quantas coisas vocês atualizam na mão?" Três. Em "Você já fez isso na mão: o Projeto 3", dê 1 minuto para cada um abrir o `src/tela/` da própria `lista-de-tarefas` e contar as linhas que só existem para a tela acompanhar os dados (trocar classe, refazer o resumo, mostrar ou esconder o aviso). Duas pessoas dizem o número; projete o `src/tela/` que você separou. "Quem esqueceu uma dessas chamadas viu a tela mentir. No React, essas linhas somem." Quem não entregou o Projeto 3 acompanha pela tela do vizinho.

**Seção "React" (4 min).** Leia o gancho: no estádio, quem troca o número do placar eletrônico quando sai um gol? Esperado: ninguém; o painel muda sozinho. "O React é o placar eletrônico: vocês mudam o dado, e a tela se redesenha." Em "React na prática: o mesmo contador", só leitura. Aponte `const [total, setTotal] = useState(0)` e pergunte: "Que sintaxe é essa?" Esperado: a desestruturação de array do E09; `useState` devolve um par. Leia "O contador em React, em português". "O que ele faz por dentro fica para o E23."

**Seção "Declarativo e imperativo" (8 min).** Leia o gancho: no restaurante, vocês entram na cozinha e ditam a receita, ou só pedem o prato? Esperado: pedem o prato. "Imperativo é ditar a receita, passo a passo; declarativo é pedir o prato e deixar os passos com o cozinheiro." Peça um exemplo da turma de "pedir sem ditar a receita". Em "Declarativo na prática", peça que duas pessoas leiam as duas versões em voz alta. "Qual vira frase?" A do `filter`: "os produtos em destaque". "O React faz com a tela o que o `filter`, a peneira, faz com a lista: vocês dizem o resultado, ele cuida dos passos."

**Seção "Componentes" (10 min).** Leia o gancho: com as mesmas peças de Lego, dá para montar um carro e uma casa? Esperado: sim, encaixando de outro jeito. "Componente é a peça: pequena, reaproveitável, encaixa em outras." Na árvore, `CartaoTarefa` aparece três vezes: "Se o cartão tiver um bug, em quantos lugares vocês corrigem?" Um. Em "Componentes na prática": "É como chamar a mesma função com argumentos diferentes; no E22, esses atributos viram as props."

No "Pense", esperado: `Cabecalho` com `CampoBusca`, `ListaCategorias` com vários `ChipCategoria`, `ListaRestaurantes` com vários `CartaoRestaurante`, `BarraInferior` com três `BotaoAba`; repetem-se chip, cartão e botão; `App`, as listas e o cabeçalho contêm outros. Sem resposta, desenhe retângulos no quadro e pergunte só "o que se repete?". Depois, mostre a resposta do slide.

**Seção "SPA" (3 min).** Leia o gancho: quando vocês trocam de aba no WhatsApp, a tela pisca em branco? Esperado: não. "Uma SPA é assim: carrega uma vez e troca só o que mudou." Faça os três passos de "SPA na prática" no painel do curso: clique num link (a tela não pisca), abra a aba **Network** e mostre que os pedidos trazem JSON, como os da DummyJSON no E19, e aperte `F5` para comparar.

**Seção "As ferramentas" (3 min).** Leia o gancho: numa caixa de ferramentas, por que não existe só um martelo? Esperado: cada trabalho pede uma ferramenta. "O ecossistema é a caixa de ferramentas do React." Nada a instalar hoje: em "As ferramentas na prática", rode `node -v` e `npm -v` no seu terminal; React e Vite chegam com o `npm install` da próxima aula. Em "Mercado", o GitHub com o `lojinha-regras` é o começo do portfólio. Na tabela "O JavaScript que vem junto", peça que cada um escolha a linha de que menos se lembra e anote o encontro para revisar em casa.

**Slides "Erros comuns" e "Resumo" (4 min).** Leia sem comentar; voltam no quiz.

:::tip Ritmo
Atrasado? Reduza "Mercado e tendência" a uma frase e a seção "SPA" a dois minutos. Nunca corte a demonstração do contador (passos 4 e 5) nem o "Pense" dos componentes.
:::

## Bloco 2 · Primeiro projeto React com Vite e JSX (50 min)

**"O que você vai aprender", "Palavras novas de hoje" e "Por que um gerador de projeto?" (3 min).** Leia as seis palavras, com um exemplo de cada. Resposta da pergunta do terceiro slide: "três arquivos, `App.jsx`, `Cabecalho.jsx` e `Rodape.jsx`; o resto o Vite gera".

**Seção "O Vite" (9 min).** Leia o gancho: para cozinhar, é mais rápido montar a cozinha do zero ou chegar numa cozinha pronta? Esperado: chegar numa pronta. "O Vite entrega a cozinha montada: vocês só cozinham." Crie o projeto ao vivo na pasta onde você guarda os projetos, **ao lado** do `lojinha-regras`, nunca dentro dele, e aponte em cada passo a linha do terminal que aparece em "Os 4 comandos na prática":

:::steps
1. `npm create vite@latest minhas-tarefas -- --template react --eslint`. "O `--eslint` escolhe o mesmo linter do E03; sem ele, o gerador pergunta qual usar." Se perguntar "Install with npm and start now?", escolha `No` com as setas: mantém a sequência do slide.
2. `cd minhas-tarefas` e `npm install`. Na espera, abra o `package.json` e compare com o do `lojinha-regras`: `"type": "module"`, os scripts `dev`, `build` e `lint`, `react` e `react-dom` em `dependencies`, as ferramentas em `devDependencies`. "É o `package.json` do E02, com outras peças."
3. `npm run dev` e leia o endereço no terminal. Se a 5173 estiver ocupada, o Vite sobe na 5174 e avisa; para liberá-la, `Ctrl + C` no terminal esquecido.
4. Abra o endereço no navegador.
:::

Em "npm run dev e a recarga automática", troque o texto do `<h1>` para "Minhas Tarefas", salve e deixe a turma olhar o navegador antes de falar.

**Seção "Os arquivos do projeto" (5 min).** Leia o gancho: se a página começa com uma caixa vazia, quem coloca o conteúdo nela? Esperado: o JavaScript, o React. Abra cada arquivo da tabela de "O que cada arquivo faz" enquanto o lê. No `index.html`, a `div#root` vazia; no navegador, `F12`, **Elements**: a `div#root` cheia. "Quem preencheu foi o React, pelo DOM, como o `textContent` da aula 41; vocês não escreveram nenhuma linha disso." Projete a animação de "O caminho até a tela" e narre os três passos.

**Seção "JSX" (10 min).** Leia o gancho: uma tag de HTML dentro de uma função JavaScript, pode isso? Esperado: no arquivo `.js` do `lojinha-regras`, não; aqui, sim. "Isso é JSX: a tela escrita com tags dentro do JavaScript, que o Vite traduz." Quebre cada regra ao vivo no `App.jsx` (dois irmãos sem raiz, `class`, `<img>` sem `/>`) e mostre a tela de erro do Vite e o conserto. Frise: `class` só avisa no Console ("Invalid DOM property `class`. Did you mean `className`?") e a página continua; os outros dois param a compilação (questão do quiz). O `export default App` é o dos módulos do E11: não explique, pergunte "de onde vocês conhecem isso?".

**Seção "Chaves no JSX" (7 min).** Leia o gancho: numa página HTML, o que aparece se vocês escreverem 2 + 2? Esperado: o texto "2 + 2". "No JSX, entre chaves, aparece 4: as chaves são uma janela para o JavaScript." Digite as quatro linhas de "Chaves na prática" com um nome da turma e compare com a tabela. "Pense": "JSX é HTML?" Esperado: não; é JavaScript, que o Vite traduz em chamadas de função, por isso `class` conflita com a palavra reservada e as chaves executam JavaScript. Se ninguém responder, mostre a tradução: aba **Network**, recarregue, clique em `App.jsx` e abra **Response**: aparece `_jsxDEV("h1", ...)`, uma chamada de função. Depois, a resposta do slide.

**Seção "Componentes" (5 min).** Leia o gancho: lembram das peças de Lego da aula 41? Como uma peça entra em outra? Esperado: encaixando. "O componente é a peça; o `import` traz a peça, e a tag encaixa." Crie `src/components/Saudacao.jsx`, importe no `App` e confira na tela. Em "Componentes na prática", escreva `<Saudacao />` duas vezes e salve: a frase aparece duas vezes. Volte para uma.

**Seção "Mensagens de erro" (3 min).** Leia o gancho: acendeu uma luz no painel do carro, vocês ignoram ou leem o que ela quer dizer? Esperado: leem. "A mensagem de erro é a luz do painel: diz o que aconteceu e onde." Apague o `export default` do `Saudacao` de propósito e salve; se a tela não mudar, recarregue com `F5`: ela fica em branco e o Console mostra "The requested module '/src/components/Saudacao.jsx' does not provide an export named 'default'". Leia com a turma na ordem de "Lendo uma mensagem de erro": arquivo, mensagem, conserto. Devolva o `export default`. Para a tela de erro do slide, junte dois irmãos sem fragmento. Aponte a tabela "Quando aparece um erro" e o "Resumo": voltam no quiz.

**Slide "No laboratório" e desafio (8 min).** Leia os seis passos. Desafio: cada aluno roda agora `npm create vite@latest minhas-tarefas -- --template react --eslint`, `cd minhas-tarefas` e `npm install`, para baixar durante a pausa. Enquanto baixa, projete o trecho e peça os três erros (sem raiz, `class`, `<img>` aberta):

```jsx
function Cabecalho() {
  return (
    <img src="/logo.png" alt="Logo">
    <h1 class="titulo">Minhas Tarefas</h1>
  )
}
```

:::tip Ritmo
Apertou? Condense as três regras em 5 minutos de erros ao vivo. O `npm install` antes da pausa não se corta: economiza 10 minutos de laboratório.
:::

## Laboratório (55 min)

**Enunciado** (slide "No laboratório"): criar `minhas-tarefas` com Vite, fora da pasta do `lojinha-regras`; `git init` e primeiro commit; limpar o modelo (`App` com fragmento vazio, `App.css` vazio); `Cabecalho.jsx` com `<header>` e título; `Rodape.jsx` com `<footer>`, nome e `{new Date().getFullYear()}`; os dois no `App`; `npm run lint` sem erros; segundo commit e push para um repositório público.

**Sala:** individual (cada um precisa do próprio repositório), em duplas para se ajudarem. Quem saiu da Prova 1 e chegou no meio do Bloco 1 senta ao lado de alguém que acompanhou a demonstração.

**Marcos:** 10 min, `npm run dev` rodando (o `npm install` correu na pausa); 20 min, primeiro commit; 35 min, `Cabecalho` e `Rodape` na tela; 45 min, `npm run lint` sem erros; 50 min, push feito; 55 min, link no sistema. Quem chegar aos 35 minutos sem o `Rodape` faz o lint, o commit e o push só com o `Cabecalho` e termina o `Rodape` em casa (Plano B, "Turma atrasada").

**Circule observando:** prompt dentro de `minhas-tarefas` (e não do `lojinha-regras`); `git status` sem `node_modules`; `export default` em cada componente; nomes com maiúscula; ano vindo da expressão; dois commits com mensagens claras. Repositório no GitHub: New repository, `minhas-tarefas`, Public, sem README, como o `lojinha-regras` no E03.

:::example Solução de referência
```jsx
// src/App.jsx
import Cabecalho from './components/Cabecalho.jsx'
import Rodape from './components/Rodape.jsx'
import './App.css'

function App() {
  return (
    <>
      <Cabecalho />
      <Rodape />
    </>
  )
}

export default App
```

```jsx
// src/components/Cabecalho.jsx
function Cabecalho() {
```

## Dificuldades frequentes

| Sintoma | Causa provável | Como ajudar |
|---|---|---|
| `npm error Missing script: "dev"` | Terminal na pasta do `lojinha-regras` (ou em outro projeto) | `cd` até `minhas-tarefas`; `ls` mostra o `package.json` com o script `dev` |
| `Could not read package.json` | Terminal numa pasta sem projeto: faltou o `cd minhas-tarefas` | `cd minhas-tarefas` e repetir |
| `Vite requires Node.js version 20.19+ or 22.12+` | Node.js antigo, de outra instalação | Instalar a LTS atual, como no E01; reabrir o terminal |
| No `lojinha-regras`, `git status` mostra `minhas-tarefas/` | Projeto criado dentro do `lojinha-regras` | Parar o `npm run dev`, mover a pasta `minhas-tarefas` para fora e conferir o `git status` dos dois |
| Tela em branco; Console: "does not provide an export named 'default'" | Faltou `export default` no componente | Acrescentar no fim do arquivo e recarregar com `F5` |
| Tela de erro do Vite: "Adjacent JSX elements" ou "Expected corresponding JSX closing tag" | Dois irmãos sem raiz; tag sem `/>` | Fragmento `<>...</>`; fechar com `/>` |
| Componente não aparece, sem erro | Nome com minúscula (`<cabecalho />`) | Nome do componente e da tag com maiúscula |
| Push recusado ou pedido de senha | Credencial de outra conta ou senha em vez de navegador | Como no E03: remover a credencial antiga e autorizar pelo navegador |
| No `minhas-tarefas`, `git status` mostra `livro-de-receitas/` | Projeto 4 criado dentro do laboratório | O mesmo conserto do `lojinha-regras`: parar o servidor, mover a pasta para fora e conferir o `git status` dos dois |
| O `livro-de-receitas` abre na 5174, ou o navegador mostra o app errado | O `npm run dev` do `minhas-tarefas` continua ligado na 5173 | `Ctrl + C` no terminal do laboratório, ou use a 5174 que o Vite indicou |
