Pedido ao suporte do laboratório

Modelo de mensagem para o suporte de TI do laboratório. Copie, troque os campos destacados e envie com pelo menos uma semana de antecedência. O que o suporte não conseguir fazer define o seu plano B.

Como usar

  • Quando: uma semana antes do E01, ou assim que souber o laboratório. Reenvie a partir do item 1 se parte da turma ficar sem ambiente no E01.
  • Peça para testar em uma máquina antes do encontro: node -v, npm -v, git --version, instalar uma extensão no VS Code e, em uma pasta de teste, rodar npm init -y e npm install -D jest (confirma o acesso ao npm e a gravação da pasta node_modules).
  • Guarde a resposta: o que não for liberado (administrador, rede, antivírus) vira plano B no roteiro: pendrives, máquina preparada ou editor online do GitHub.
  • Depois do E01, anexe a lista de pendências da folha de acompanhamento e peça prazo para o E02.

Sou instrutor do curso Programador Mobile (180 horas, 45 encontros de 4 horas), que usará o laboratório [sala] às [dias da semana], das [hora] às [hora], de [data inicial] a [data final]. Os alunos trabalham com JavaScript (Node.js) e, mais adiante, com React e React Native; todo o software é gratuito e de código aberto.

1. Software a instalar, para todos os usuários

  • Node.js LTS (a versão par mais recente, com npm), de https://nodejs.org. Instalador .msi com as opções padrão; não é necessário marcar "ferramentas nativas".
  • Git for Windows, de https://git-scm.com, com as opções padrão.
  • Visual Studio Code, de https://code.visualstudio.com (System Installer), com as extensões Prettier - Code formatter (esbenp.prettier-vscode), ESLint (dbaeumer.vscode-eslint) e Error Lens (usernamehw.errorlens). Se a loja de extensões for bloqueada, basta liberar os endereços do item 3 e os alunos instalam.
  • Google Chrome ou Microsoft Edge atualizados; as ferramentas do desenvolvedor (DevTools) são usadas em sala.

Se não for possível instalar para todos os usuários, peço que os alunos tenham permissão para rodar os instaladores nas próprias contas (Node.js, Git e o User Installer do VS Code).

2. Permissões nas contas dos alunos

  • Executar node, npm, npx e git e gravar nas próprias pastas de usuário. O npm cria a pasta .npm e as pastas node_modules dos projetos, com milhares de arquivos pequenos.
  • No PowerShell, permitir scripts assinados localmente (Set-ExecutionPolicy -Scope CurrentUser RemoteSigned). Sem isso, o comando npm falha com "a execução de scripts foi desabilitada neste sistema".
  • Exceção no antivírus para node.exe e para as pastas node_modules: a verificação em tempo real deixa o npm install muito lento.
  • Manter os arquivos dos alunos entre um encontro e outro. Se as máquinas forem restauradas, avisem; orientaremos a turma a guardar os projetos no GitHub.

3. Acesso à rede (HTTPS, porta 443)

  • nodejs.org, registry.npmjs.org e npmjs.com
  • github.com, api.github.com, raw.githubusercontent.com e objects.githubusercontent.com
  • code.visualstudio.com, marketplace.visualstudio.com, update.code.visualstudio.com e *.vscode-cdn.net
  • erick-porto.github.io (site do curso) e *.supabase.co (login, progresso e quizzes dos alunos)
  • A partir do encontro E19 ([data]): dummyjson.com (API de exemplo que os programas dos alunos consultam)
  • A partir do encontro E26 ([data]): expo.dev, exp.host, *.expo.dev e *.expo.io; e, a partir do E30, picsum.photos e fastly.picsum.photos (imagens do app de exemplo)

Se o laboratório usa proxy, peço o endereço e a porta para configurarmos o npm e o git (npm config set proxy, git config http.proxy) ou, se possível, acesso direto a esses endereços.

4. Rede local a partir do E26 ([data])

Os alunos testam os aplicativos no próprio celular com o aplicativo Expo Go, que se conecta ao computador pela rede local. Precisamos que celulares e computadores fiquem na mesma rede Wi-Fi, com tráfego TCP entre eles liberado nas portas 8081 e 19000 a 19006. Se isso não for possível, a alternativa é o modo túnel do Expo, que exige acesso a *.exp.direct e aos servidores do ngrok.

5. O que não precisamos

  • Emulador Android, Android Studio ou Xcode: não serão usados.
  • Contas institucionais de software: os alunos criam as próprias contas no GitHub durante a aula; para isso precisam de acesso a github.com e ao e-mail pessoal.
