Antes de começar

  1. Crie a pasta de treino

    No terminal, na sua pasta de projetos, ao lado do lojinha-regras, não dentro dele: mkdir treino-e02, cd treino-e02 e code .. Assim o treino não se mistura com o projeto da Lojinha.

  2. Um arquivo por exercício

    Crie ex01.js, ex02.js e assim por diante. Salve com Ctrl + S e rode com node ex01.js. Os exercícios de leitura também dão certo no REPL: node, cole as linhas e .exit para sair.

  3. Antes de rodar, confira

    O caminho no terminal termina em treino-e02, e a aba do arquivo no VS Code não tem a bolinha de "não salvo".

Como treinar. Nos exercícios Leia, escreva no caderno o que você acha que vai aparecer e só depois rode. Errar a previsão e descobrir o porquê também é treino. As respostas ficam fechadas: abra depois de tentar.

4

Três fichas com defeito

Ache o erro

Cada trecho tem um problema. Leia a mensagem, diga o que está errado e como corrigir.

a)

trecho a
const produto = { nome: 'Fone' preco: 199.9 };
//                             ^^^^^
// SyntaxError: Unexpected identifier 'preco'

b)

trecho b
const produto = { nome: Fone, preco: 199.9 };
//                      ^
// ReferenceError: Fone is not defined

c) Este roda sem mensagem de erro, mas mostra undefined em vez do preço.

trecho c
const produto = { nome: 'Fone', preco: 199.9 };
console.log(produto.Preco);   // undefined
Ver a resposta
  1. Falta a vírgula entre os campos. O ^^^^^ aponta para preco: o Node esperava uma vírgula antes dele. Correção: { nome: 'Fone', preco: 199.9 }.
  2. Texto sem aspas. Sem aspas, o Node acha que Fone é o nome de uma constante, procura e não encontra. Correção: nome: 'Fone'.
  3. Maiúscula conta. O campo se chama preco, com p minúsculo; Preco é outro nome, que não existe na ficha. Correção: produto.preco.

7

Soma e média dos preços

Escreva

Some os quatro preços, gaveta por gaveta, na ordem da lista. Depois, calcule a média: a soma dividida pela quantidade de preços, que o .length informa.

ex07.js (começo)
const precos = [199.9, 49.9, 89.9, 59.9];
Saída esperada
Soma: R$ 399.6
Média: R$ 99.9
Ver uma resposta
o resto de ex07.js
const soma = precos[0] + precos[1] + precos[2] + precos[3];
const media = soma / precos.length;

console.log('Soma: R$', soma);
console.log('Média: R$', media);

Saiu algo como 399.59999999999997? Você somou em outra ordem. O computador às vezes erra lá no fim das contas com casas decimais; no E05 você vê por quê e como a Lojinha evita isso.

Somar gaveta por gaveta funciona com 4 preços. Com 300, não dá: no E09 você aprende a somar uma lista inteira de uma vez.

8

A última gaveta, sem contar

Desafio

No exercício 6, o último item está na gaveta 2. Se o carrinho ganhar mais um item, carrinho[2] deixa de ser o último.

Mostre o último item de um jeito que funcione para qualquer tamanho de carrinho. Teste com 3 itens e depois acrescente um quarto, 'Tapete de Yoga', sem mudar o console.log.

Pista: com 3 itens, o .length é 3 e a última gaveta é a 2. Com 4 itens, 4 e 3. Que conta leva de um número ao outro?

Ver uma resposta
ex08.js
const carrinho = ['Fone Bluetooth', 'Cabo USB-C', 'Garrafa Térmica', 'Tapete de Yoga'];

console.log('Último:', carrinho[carrinho.length - 1]);   // Último: Tapete de Yoga

A última gaveta é sempre o tamanho menos 1, porque a contagem começa do 0. O Node faz a conta de dentro dos colchetes primeiro (4 - 1 = 3) e depois abre a gaveta 3.

Parte 4 · Listas e argumentos

O process.argv da aula 3 também é uma lista. Agora dá para entender por que o primeiro argumento está na gaveta 2.

O Node guarda o comando inteiro numa lista, o process.argv. A gaveta 0 tem o caminho do node, a 1 tem o caminho do arquivo, e os argumentos começam na 2. Por isso o primeiro argumento é o process.argv[2].

O espaço separa os argumentos: Maria Souza ocupa duas gavetas. Com aspas, o nome inteiro cabe numa gaveta só, e a lista fica com 3. Quer ver a lista toda? console.log(process.argv): as duas primeiras gavetas mostram caminhos do seu computador.

A gaveta escolhida no comando

Desafio

Copie o gaveta.js, rode os quatro comandos e explique o que acontece nos dois últimos.

gaveta.js
const produtos = [
  { nome: 'Fone Bluetooth', preco: 199.9 },
  { nome: 'Luminária de Mesa', preco: 89.9 },
  { nome: 'Tênis de Corrida', preco: 349.9 },
];

const posicao = process.argv[2];
const produto = produtos[posicao];

console.log('Gaveta', posicao + ':', produto.nome, 'por R$', produto.preco);
terminal
node gaveta.js 0
node gaveta.js 2
node gaveta.js 5
node gaveta.js
Ver a resposta
Saída
Gaveta 0: Fone Bluetooth por R$ 199.9
Gaveta 2: Tênis de Corrida por R$ 349.9
TypeError: Cannot read properties of undefined (reading 'nome')
TypeError: Cannot read properties of undefined (reading 'nome')

O argumento escolhe a gaveta. Com 5, a gaveta não existe e produtos[5] é undefined. Sem argumento, a posição é undefined, e a gaveta também. Nos dois casos, a linha seguinte tenta ler o campo nome de algo que não existe: é o que a mensagem diz, "não dá para ler propriedades de undefined (lendo 'nome')".

Essa é uma das mensagens mais comuns de quem programa. Quando ela aparecer, pergunte: qual gaveta ou campo veio vazio antes do .nome? Avisar o usuário em vez de quebrar pede um if, que vem no E07.
