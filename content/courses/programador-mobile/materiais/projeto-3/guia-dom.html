1. A página e o seu código

O navegador lê o index.html e monta o DOM: a árvore de elementos da página, a mesma que você vê na aba Elements do DevTools (F12, E01). O seu JavaScript lê e muda essa árvore, e a tela acompanha.

index.html (já vem assim no ponto de partida)
<script type="module" src="src/tela/app.js"></script>
  • type="module" deixa o arquivo usar import e export, como no Node (E11). O app.js importa as suas classes e regras de src/.
  • No navegador, o import relativo precisa do .js no fim: '../regras/tarefas.js'.
  • Um script de módulo só roda depois que o HTML inteiro foi lido: quando o seu código procura um elemento, ele já existe.
  • Abra sempre com npx serve . na pasta do projeto e use o endereço que ele mostra. Pelo file:// (dois cliques no arquivo), o navegador bloqueia módulos.
  • Erros aparecem na aba Console do DevTools, com o arquivo e a linha.

2. Encontrar um elemento

src/tela/app.js
const lista = document.querySelector('#lista');   // o elemento com id="lista"
const formulario = document.querySelector('#formulario');
const titulo = document.querySelector('#titulo');
  • querySelector recebe um seletor de CSS: # procura pelo id.
  • Devolve o primeiro elemento que combina, ou null se não achar nenhum.
  • Procure cada elemento uma vez, no topo do arquivo, e guarde numa const. Ele continua o mesmo enquanto a página estiver aberta.

Cannot read properties of null (reading 'addEventListener') quer dizer que o querySelector não achou nada: confira o id no HTML, letra por letra.

3. Trocar o texto

exemplo
const recado = document.querySelector('#recado');
recado.textContent = 'Bom dia!';

Experimente

Recado ainda não trocado.

Digite <b>oi</b> e troque: as tags aparecem como texto, sem virar negrito.

textContent põe o texto exatamente como ele é. Por isso ele é o certo para mostrar o que a pessoa digitou, como o título de uma tarefa.

Existe também o innerHTML, que interpreta o texto como HTML. Com o que a pessoa digitou, ele é perigoso: um título como <img src=x onerror=...> roda código na página. Neste projeto, use só textContent.

4. Criar, colocar e apagar elementos

exemplo
const item = document.createElement('li');  // nasce fora da página
item.className = 'fruta';                      // class="fruta"

const nome = document.createElement('strong');
nome.textContent = 'Banana';
const preco = document.createElement('span');
preco.textContent = 'R$ 6,90';

item.append(nome, preco);                      // os dois dentro do item

lista.append(item);                            // agora aparece, no fim da lista
QueroUse
criar um elementodocument.createElement('li')
colocar dentro de outro, no fimpai.append(filho); aceita vários: pai.append(a, b, c)
apagar tudo o que está dentropai.replaceChildren()

Criar, dar classe e dar texto se repete muito. Uma função pequena economiza linhas: criar(tag, classe, texto), que cria, preenche e devolve o elemento. Escreva a sua em src/tela/.

5. Classes: o CSS decide a cara

O estilo.css do projeto já sabe desenhar uma tarefa atrasada, concluída ou de prioridade alta. O seu JavaScript só escolhe as classes; cor, borda e risco são do CSS.

exemplo
cartao.classList.add('destaque', 'grande');  // acrescenta uma ou várias
cartao.classList.remove('grande');
cartao.classList.toggle('riscado', feito);    // põe se feito for true, tira se false
cartao.classList.contains('destaque');        // true

Experimente

Um cartão qualquer

className: "cartao-classe"

Um nome de classe montado com template string também vale: item.classList.add(`prioridade-${prioridade}`) dá prioridade-alta.

6. Desenhar a partir dos dados

A ideia que segura o projeto inteiro: os dados ficam numa variável, e uma função desenha a tela a partir deles. Toda vez que os dados mudam, você chama a função de novo.

  1. Os dados mudam (alguém adicionou, concluiu ou removeu).
  2. Você chama a função que desenha.
  3. Ela apaga o que estava na tela e cria tudo de novo, a partir dos dados.
exemplo
const frutas = ['Maçã', 'Banana', 'Uva'];
const lista = document.querySelector('#frutas');
const vazio = document.querySelector('#sem-frutas');

function desenhar() {
  lista.replaceChildren();               // 1. apaga o que estava lá
  for (const fruta of frutas) {          // 2. um item por fruta
    const item = document.createElement('li');
    item.textContent = fruta;
    lista.append(item);
  }
  vazio.hidden = frutas.length > 0;     // 3. a mensagem só aparece sem frutas
}

desenhar();

Experimente

    Nenhuma fruta por aqui.

    • Sem o replaceChildren() no começo, cada chamada acrescenta a lista inteira de novo: a tela mostra tudo duplicado.
    • elemento.hidden = true esconde o elemento; false mostra. É assim que a mensagem de lista vazia aparece e some.
    • A função de desenhar não decide regra nenhuma: o texto do prazo, a ordem e o resumo vêm das suas regras e classes, que já têm testes.

    Mudar o dado e esquecer de chamar a função de desenhar é o erro mais comum de quem mexe no DOM à mão: o dado muda e a tela fica parada. No E21, o React resolve justamente isso.

    7. Eventos

    addEventListener(tipo, funcao) guarda a função e o navegador a chama quando o evento acontece, como o setTimeout do E18 chama a função quando o tempo acaba. A função recebe o evento; evento.target é o elemento onde ele aconteceu.

    EventoQuando aconteceNo projeto
    clickclique ou toque; Enter num botãoConcluir, Remover, Importar
    inputa cada letra digitada ou apagadaa busca
    changequando o valor de um select mudao filtro
    submito formulário foi enviado (botão ou Enter)nova tarefa
    exemplo
    campo.addEventListener('input', () => {
  eco.textContent = `Você digitou: ${campo.value}`;
});

tamanho.addEventListener('change', desenhar);  // o nome da função, sem ()

    Experimente

    Você digitou: (nada ainda) · tamanho: m

    • campo.value é sempre texto; o campo vazio dá ''.
    • O value de um select é o value da opção escolhida, não o texto que aparece.
    • addEventListener('change', desenhar()), com parênteses, chama a função na hora e entrega o resultado (undefined) ao navegador. Passe a função, sem chamar.

    8. Formulário: submit e preventDefault

    Ouça o submit do formulário, não o clique do botão: assim o Enter no campo também envia. Por padrão, enviar um formulário recarrega a página, e tudo o que estava na memória some. evento.preventDefault() cancela esse padrão.

    exemplo
    formulario.addEventListener('submit', (evento) => {
  evento.preventDefault();          // sem isso, a página recarrega
  const nome = campoNome.value;     // texto; '' se vazio
  const especie = campoEspecie.value;
  bichinhos.push({ nome, especie });
  formulario.reset();               // limpa os campos
  campoNome.focus();                // o cursor volta para o primeiro campo
  desenhar();
});

    Experimente

      Envie com o botão ou com Enter no campo.

      • Campo de data (type="date"): o value vem como 'AAAA-MM-DD', mesmo que a tela mostre dd/mm/aaaa, ou '' se vazio. É o formato do prazo das tarefas.
      • O novalidate do <form> do projeto desliga as mensagens prontas do navegador: quem valida são as suas classes (etapa 5).

      9. dataset: um ouvinte para a lista inteira

      Os botões de cada item nascem e morrem a cada desenho. Em vez de um ouvinte por botão, ponha um ouvinte na lista: o clique num botão "sobe" até ela. Para saber qual botão foi, guarde os dados no próprio botão com atributos data-:

      o HTML que o seu código cria
      <button type="button" data-acao="apagar" data-id="2">Apagar</button>
      exemplo
      botao.dataset.acao = 'apagar';      // vira data-acao="apagar"
botao.dataset.id = recado.id;       // vira data-id="2"

lista.addEventListener('click', (evento) => {
  const { acao, id } = evento.target.dataset;
  if (!acao) return;                // clicou fora de um botão: guard clause (E13)
  const numero = Number(id);        // o dataset sempre devolve texto
  if (acao === 'apagar') recados = recados.filter((r) => r.id !== numero);
  if (acao === 'curtir') curtidos.add(numero);
  desenhar();
});

      Experimente

        Clique num botão ou no espaço vazio de um item.

        • data-id no HTML vira dataset.id no JavaScript; data-acao, dataset.acao.
        • O valor é sempre texto: '2' === 2 é false. Converta com Number antes de procurar pelo id.
        • Um ouvinte só, ligado uma vez no começo, serve para os itens que ainda nem existem: os que o próximo desenho criar.

        10. Mensagem embaixo do campo

        O HTML do projeto já tem um parágrafo vazio embaixo do título e do prazo (#erro-titulo e #erro-prazo), e o CSS esconde o parágrafo enquanto ele está vazio. Mostrar o erro é escrever nele; limpar é escrever ''.

        exemplo
        function mostrarErro(campo, mensagem, texto) {
  mensagem.textContent = texto;
  campo.setAttribute('aria-invalid', 'true');  // borda vermelha e aviso ao leitor de tela
  campo.focus();
}

function limparErro(campo, mensagem) {
  mensagem.textContent = '';
  campo.removeAttribute('aria-invalid');
}

        Experimente: o recado precisa de pelo menos 3 letras

        Envie vazio, com 2 letras e com 3.

        • No projeto, quem decide que o título está errado é a sua classe, que lança um erro próprio (etapa 5). A tela só captura o erro com try...catch e escolhe onde mostrar pelo codigo, com o switch do E13.
        • aria-describedby="erro-titulo", que já está no HTML, liga o campo à mensagem: o leitor de tela lê o erro junto com o campo.
        • Limpe as mensagens antigas no começo de cada envio, antes de validar de novo.

        11. localStorage: guardar no navegador

        O localStorage guarda textos no navegador, por chave, e eles continuam lá depois de recarregar ou fechar a página.

        exemplo
        localStorage.setItem('recado', 'Comprar pão');
localStorage.getItem('recado');      // 'Comprar pão'
localStorage.getItem('nao-existe');  // null
localStorage.removeItem('recado');

// só guarda texto: objetos e listas passam pelo JSON (E06)
localStorage.setItem('bichinhos', JSON.stringify([{ nome: 'Mingau' }]));
const lidos = JSON.parse(localStorage.getItem('bichinhos'));

        Experimente: guarde, recarregue a página e veja o recado voltar

        • Instâncias de classe perdem a classe no JSON.stringify (E15): guarde os dados do paraJSON() e recrie as instâncias ao ler.
        • Veja e apague o que está guardado no DevTools, aba Application, item Local storage.
        • Cada endereço tem o seu: localhost:3000 e localhost:5000 não enxergam os dados um do outro. Se o npx serve abriu em outra porta, as tarefas "somem".
        • O localStorage não existe no Node nem no Jest. Por isso, na etapa 6, os testes recebem um armazenamento falso com o mesmo getItem e setItem.

        12. Desligar o botão enquanto espera

        Enquanto um pedido à internet não volta, o botão que o disparou fica desligado: assim ninguém dispara o mesmo pedido cinco vezes. O finally (E17) religa nos dois caminhos.

        exemplo
        botao.addEventListener('click', async () => {
  botao.disabled = true;
  situacao.textContent = 'Carregando...';
  try {
    const piada = await buscarPiada();   // uma Promise (E18, E19)
    situacao.textContent = piada;
  } catch (erro) {
    situacao.textContent = erro.message;
  } finally {
    botao.disabled = false;              // com sucesso ou com falha
  }
});

        Experimente: a espera aqui é de mentira, 2 segundos

        Clique em Buscar.

        • Botão desligado não recebe clique; o CSS do projeto deixa ele mais claro.
        • Sem o finally, uma falha deixa o botão desligado para sempre, e o "Carregando..." fica na tela.
        • Para testar o caminho sem internet no navegador: DevTools, aba Network, troque No throttling por Offline.

        13. Erros comuns

        Access to script ... from origin 'null' has been blocked by CORS policy
        A página foi aberta pelo file://. Rode npx serve . e use o endereço dele.
        GET .../src/regras/tarefas 404 (Not Found)
        Import sem o .js. O Jest aceita sem; o navegador, não.
        Cannot read properties of null (reading 'addEventListener')
        O querySelector não achou o elemento: id escrito diferente do HTML.
        A página pisca e a tarefa nova some
        Faltou evento.preventDefault() no submit: o navegador recarregou a página.
        A lista aparece duplicada depois de cada ação
        A função de desenhar não apaga o que já estava lá: replaceChildren() no começo.
        Clicar em Remover não faz nada
        O id do dataset é texto: compare com Number(id).
        O dado mudou, mas a tela não
        Faltou chamar a função de desenhar depois da mudança.
        As tarefas salvas sumiram
        O npx serve abriu em outra porta, e cada endereço tem o seu localStorage.
        Uncaught (in promise) no Console
        Uma Promise rejeitou e ninguém tratou: falta catch (ou try...catch em volta do await).
